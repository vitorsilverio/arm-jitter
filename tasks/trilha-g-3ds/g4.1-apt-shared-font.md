# G4.1 — `APT:GetSharedFont` (fonte do sistema para o console)

**Trilha:** G · **Depende de:** G4 (commit `f36a6aa`) · **Repo:** n3dsemu
**Leia a RFC-N3DSEMU.md antes.** Caminho de fix já DECIDIDO pelo usuário (ver Objetivo — fonte de
código aberto via `JayFoxRox/3ds-font`, não dump real); esta task confirma a hipótese e implementa.

## Contexto

Validando a G4 (janela Vulkan) com `hello-world.3dsx` (o alvo de aceite da própria G4), a janela
abre e o laço de apresentação roda sem erro, mas a tela fica **sempre preta** — nenhum glyph
aparece. Investigação desta sessão (ver commit `f36a6aa`) isolou dois bugs reais e corrigiu os
dois (faltava `APT:S`/`APT:A` como alias de `APT:U`; o framebuffer precisa ser lido da memória
compartilhada do `gsp`, não mais só da IPC `SetBufferSwap` — libctru 2.7.0 mudou esse caminho).
Com os dois corrigidos, o boot avança de verdade e o framebuffer de CIMA (onde
`consoleInit(GFX_TOP, NULL)` desenha, confirmado lendo `C:\devkitPro\examples\3ds\graphics\
printing\hello-world\source\main.c`) troca de endereço a cada quadro com formato/stride
plausíveis — mas fica **100% zerado** em todo o buffer, sempre (confirmado varrendo os 230400
bytes do framebuffer ativo, não só uma amostra).

Rastreado até `APT:U GetSharedFont` (3dbrew: cabeçalho `0x00440000`, id `0x44`) — comando que o
console moderno do libctru usa para mapear a fonte do sistema (`fontEnsureMapped`/
`fontGetSystemFont`) antes de desenhar qualquer glyph. `AptService` não implementa esse comando
(cai em `respondUnknown`/`SERVICE_COMMAND_NOT_IMPLEMENTED`) — hipótese forte (não 100% confirmada
com trace de retorno de erro observado em ação, mas consistente com todos os sintomas: boot sem
crash, framebuffer trocando de verdade, conteúdo sempre zero) é que sem fonte mapeada o console
simplesmente não tem o que desenhar e segue em frente sem erro fatal.

## Objetivo

Confirmar a hipótese (trace/log mostrando `GetSharedFont` sendo chamado e falhando) e implementar
`GetSharedFont` devolvendo uma fonte BCFNT **de código aberto**, sem depender de dump de hardware
real.

**Decisão do usuário (2026-08-19, não reabrir)**: usar
[`JayFoxRox/3ds-font`](https://github.com/JayFoxRox/3ds-font) em vez de extrair
`shared_font.bin` de um 3DS real. É um TOOLSET (`extract`/`generate`, C/CMake), **não** um binário
BCFNT pronto — gera o arquivo combinando com uma fonte TTF de origem à parte (não incluída no
repositório). O toolset em si é **GPLv2+**; a fonte TTF que for escolhida como origem PRECISA ter
licença compatível com distribuição no `n3dsemu` (BSD 3-Clause, ver `[[onda4-plano-infra-3ds]]`)
— preferir uma fonte permissiva (ex.: SIL Open Font License, como Deja Vu ou Noto) em vez de uma
GPL, para não forçar o `n3dsemu` a carregar uma obrigação de copyleft só por causa de um asset de
fonte. Se o toolset GPLv2+ for usado só como FERRAMENTA DE BUILD (gera o `.bcfnt` em tempo de
desenvolvimento, o binário resultante — dados de fonte, não código GPL — é o que entra no
repositório/jar), isso não obriga o `n3dsemu` a virar GPL; confirmar esse raciocínio antes de
prosseguir (mesmo modelo de "ferramenta de build vs. artefato gerado" já usado para `3dstools`
nesta trilha) — se tiver dúvida, PARE e pergunte ao usuário antes de vincular a licença errada.

Este é o gatilho real que falta para `hello-world.3dsx` desenhar algo — sem ele, G4 nunca fecha o
aceite visual, não importa o que mais seja corrigido no caminho de apresentação.

## Inclui

1. Trace/log confirmando que `GetSharedFont` é chamado e que a resposta de erro é o que impede o
   console de desenhar (não presumir — confirmar).
2. Levantar o formato real do CFNT/BCFNT (3dbrew: `CFNT`, `CGLP`, `CWDH`, `CMAP`) o suficiente
   para saber o tamanho/exigências mínimas de uma resposta válida e como o `extract`/`generate`
   do `JayFoxRox/3ds-font` produzem esse layout.
3. Escolher uma fonte TTF de origem com licença permissiva (SIL OFL ou equivalente — não GPL,
   ver Objetivo) e usar o toolset para gerar o `.bcfnt`; confirmar antes de prosseguir se o
   raciocínio "GPL só como ferramenta de build, artefato gerado não" vale para este caso
   específico (formato binário de dados, sem código GPL embutido no resultado).
4. Implementar `GetSharedFont`: criar/mapear um bloco de memória compartilhada com o `.bcfnt`
   gerado (mesmo padrão de `MemoryBlockObject`/`handles.create` já usado por `gsp::Gpu` para a
   fila de interrupção) e devolver o handle + endereço conforme 3dbrew.
5. Teste de regressão confirmando que `GetSharedFont` responde sucesso e que o handle resolve
   para um bloco com o cabeçalho `CFNT` esperado.

## NÃO inclui (não fazer)

- Não extrair `shared_font.bin` de um 3DS real — decisão do usuário foi usar a fonte de código
  aberto (ver Objetivo), não fazer dump.
- Não mexer no `arm-jitter` — o bug de divergência STREX descoberto na mesma sessão é uma task
  separada (`strex-asm-interp-divergence.md`), sem relação com fonte/console.
- Sem PICA200/G5.

## Validação

`mvn -o test` verde no n3dsemu (a divergência STREX do `arm-jitter` é um bloqueador SEPARADO —
ver a task irmã; não é esperado que esta task sozinha deixe a suíte 100% verde se aquela não
tiver fechado primeiro). Se o fix visual for aplicado, confirmação do usuário rodando
`n3dsemu testdata/hello-world.3dsx` e vendo texto (mesmo que só "Hello World!" legível).

## Armadilhas

- **Licença**: `JayFoxRox/3ds-font` é GPLv2+; a fonte TTF de origem escolhida precisa ser
  permissiva (SIL OFL ou similar) para o `.bcfnt` GERADO não carregar obrigação de copyleft para o
  `n3dsemu` (BSD 3-Clause) — não presumir que "é open source" já resolve a compatibilidade de
  licença, checar explicitamente.
- `libctru` fonte não está disponível localmente (só `include/`+`lib/*.a`) — usar 3dbrew +
  desmontagem do `.3dsx` real como nas tasks anteriores desta trilha.
- O toolset é C/CMake — confirmar que compila neste ambiente (mesma cautela de toolchain já vista
  em outras tasks desta fila) antes de assumir que é só "rodar e usar".
