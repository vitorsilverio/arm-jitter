# B9.12 — v4T/v5TE: curadoria de denominador (ARMv6/v6T2/v5T/v5TE indevidamente contados como falta)

**Trilha:** B · **Repo:** arm-jitter · **Depende de:** — · **Status:** ✅

## Contexto

`docs/COBERTURA-ISA.md` mede v4T em 64% (205/316) e v5TE em 70% (222/316) — os dois piores
números do 32 bits depois de v6-M. A B9.10 já mostrou o padrão: parte de um número baixo não é
trabalho pendente, é `docs/isa-nao-aplicavel.tsv` incompleto (denominador errado), porque a curadoria
de exclusão foi feita primeiro para v6-M/v6K/MPCore e nunca revisitada para v4T/v5TE.

Auditoria desta sessão contra `target/isa-decode/a32.decode` (vendorizado, real) confirma: dezenas de
células `❌` em v4T/v5TE são instruções **ARMv5T/ARMv5TE/ARMv6/ARMv6K/ARMv6T2/ARMv7** — todas
POSTERIORES ao próprio ARMv4T/ARMv5TE por construção (ARMv4T = 1994/95, ARMv5TE = 1999/2000; ARMv6
é 2001+). A prova é indireta mas sólida: toda instrução deste lote já está `✅` em `v6K`/`MPCore`
(ou `v5TE`, para o lote v5T-only) — ou seja, JÁ está implementada a partir da versão certa; só falta
a linha do TSV dizendo que v4T/v5TE não a têm.

## Objetivo

Fechar as células de v4T/v5TE que são curadoria (não implementação), citando a versão real de
introdução para cada mnemônico — igual à B9.10.

## Inclui

1. **Novas linhas TSV (ARMv6/ARMv6K, exclui v4T,v5TE)**: `UMAAL`, `USADA8`, `SMC`, os 36 mnemônicos
   de aritmética paralela (`SADD16`...`UHSUB8`, ver `a32.decode` linhas ~431-475), `PKH`, `SSAT`,
   `USAT`, `SSAT16`, `USAT16`, `SXTAB16`, `SXTAB`, `SXTAH`, `UXTAB16`, `UXTAB`, `UXTAH`, `SEL`,
   `REV`, `REV16`, `REVSH`, `STREX`, `STREXD_a32`, `STREXB`, `STREXH`, `LDREX`, `LDREXD_a32`,
   `LDREXB`, `LDREXH`, `WFI`, `SETEND`, `CPS`, `CPS_v7m`.
2. **Novas linhas TSV (ARMv5T, exclui só v4T)**: `CLZ`, `BLX_r`.
3. **Novas linhas TSV (ARMv5TE, exclui só v4T)**: `LDRD_rr`, `STRD_rr`, `LDRD_ri_a32`,
   `STRD_ri_a32`, `MCRR`, `MRRC`.
4. **Estender linhas EXISTENTES** (hoje só `v6K,MPCore`) para incluir `v4T,v5TE`: `MOVW`, `MOVT`,
   `MLS`, `SBFX`, `UBFX`, `BFCI`, `RBIT` (ARMv6T2), `SDIV`, `UDIV` (extensão de divisão ARMv7-A/R) —
   mesma razão-versão já citada nessas linhas, só adicionar os dois presets que também são
   anteriores.
5. Regenerar `docs/COBERTURA-ISA.md` (`./gerar-cobertura-isa.sh`) e conferir que só as células
   citadas mudaram de `❌` para `·`.

## Não inclui (achados colaterais desta sessão, NÃO resolvidos aqui)

- **`MCR`/`MRC`** (forma base, `cond 1110 ... 0/1 ... 1 ....`) mostram `v4T ❌` mas são ARMv3+ —
  aplicáveis a v4T por construção. Isto é um GAP REAL (não curadoria): o preset `ARMV4T` parece não
  habilitar o dispatch de coprocessador que os presets seguintes já têm. Candidata a task própria.
- **T16 hints** (`YIELD`/`WFE`/`WFI`/`SEV`/`NOP`/`IT`/`CBZ`, forma Thumb de 16 bits) mostram `❌`
  também em `v6K`/`MPCore` (não só v4T/v5TE) — não é denominador errado, é gap real de decode em
  TODOS os presets A-profile pré-Thumb-2 (só v7-A/v6-M/v7-M têm). Fora do escopo desta task
  (misturaria curadoria com implementação); candidata a task própria.
- `MRS_bank`/`MSR_bank`/`ERET`/`HVC` — já documentados como pendência intencional em
  `b9.7-t32-thumb2.md` (regra do usuário, não excluir).

## Passos

1. `./gerar-cobertura-isa.sh` para confirmar o baseline (v4T 64%, v5TE 70%, global 81%).
2. Adicionar as linhas novas + estender as existentes em `docs/isa-nao-aplicavel.tsv`, cada uma
   citando a versão real (mesmo padrão das linhas já existentes de B9.2/B9.6, seção correspondente).
3. Regenerar e conferir a tabela.

   curadoria de medição, nenhum código de produção muda).
5. Commit + push.

## Aceite

- `docs/COBERTURA-ISA.md` mostra v4T e v5TE subindo (denominador correto), sem nenhuma mudança de
  código de produção.
- `docs/isa-nao-aplicavel.tsv` sem duplicar mnemônico+arquitetura já citados.

## Validação

`mvn -o test` no arm-jitter + suites dos 5 consumidores (G5).

## Armadilhas

- TSV casa por **nome** do mnemônico, não por grupo/linha — um mnemônico que aparece em A32 E T16
  com o mesmo nome (`REV`, `SXTAH`, etc.) é coberto por uma única linha, ok.
- Não confundir "não implementado ainda" com "não se aplica" — todo item desta lista já está `✅`
  em pelo menos um preset mais novo (prova de que a versão de introdução está certa), critério que
  a `README.md`/regra máxima exige (nunca excluir por suposição).

## Resultado

Executado 2026-08-28. Baseline confirmado (`./gerar-cobertura-isa.sh`): v4T 64% (205/316), v5TE 70%
(222/316), global 81%. Todas as 3 categorias do "Inclui" foram cross-checadas contra
`target/isa-decode/a32.decode` real (números de linha citados no TSV) e contra o padrão já
estabelecido pelas linhas de B9.2/B9.6/B9.10 (mesma instrução, mesma versão, já `✅` em `v6K`/`MPCore`
ou `v5TE`, confirmando que a versão de introdução citada está correta e a instrução não foi excluída
por suposição). Zero mudança de código de produção — só `docs/isa-nao-aplicavel.tsv` +
`docs/COBERTURA-ISA.md` regenerado. `MCR`/`MRC` sob `v4T` e os hints T16 (`YIELD`/`WFE`/`WFI`/`SEV`/
`NOP`/`IT`/`CBZ`) ficaram documentados como gaps reais (não curadoria) na seção "Não inclui", candidatos
a task própria.
