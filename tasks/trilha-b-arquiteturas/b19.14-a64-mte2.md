### O que a extensão faz

`FEAT_MTE2` associa a cada **granule** de 16 bytes de memória endereçável uma **tag de alocação**
de 4 bits, guardada numa RAM de tags PARALELA à memória de dados (não endereçável por instrução de
dados comum). Um ponteiro tagueado carrega uma **tag lógica** em bits altos do endereço (bits
`59:56`, layout "Top-Byte Ignore" estendido). Em hardware real, todo acesso de dados tagueado
compara a tag lógica do ponteiro contra a tag de alocação do granule e falha (síncrono/assíncrono/
assimétrico, conforme `TCR_EL1`) se não baterem — **esta spec NÃO exige modelar a falha** (ver
Decisão de escopo).

- **`STG`/`LDG`**: grava/lê a tag de alocação de UM granule (16 bytes) endereçado por `Xn+offset`.
- **`STZG`**: como `STG`, e **zera os dados** do granule (não só a tag).
- **`ST2G`/`STZ2G`**: mesma família, cobrindo **2 granules** (32 bytes) de uma vez.
- **`STGM`/`LDGM`/`STZGM`**: gravam/lêem/zeram um **bloco compacto de tags** (bitmap de 4 bits por
  granule, cobrindo um "tag block" inteiro, tipicamente 256 bytes = 16 granules) num único registro
  de 64 bits — forma "multiple", sem varrer granule a granule.
- **`STGP`**: como `STP` normal (grava par de registradores de 64 bits), **e também** grava a tag
  do granule endereçado — combina transferência de dados com gravação de tag.
- **`IRG`** ("Insert Random Tag"): gera uma tag lógica pseudoaleatória (respeitando a máscara de
  exclusão de `GCR_EL1`/`Rn`, se implementada — ver Decisão de escopo) e a insere no endereço de
  `Rm`, resultado em `Rd`.
- **`GMI`** ("Tag Mask Insert"): insere no registrador de máscara de exclusão (`Rd`) o bit
  correspondente à tag do endereço de `Rn` — usado para acumular tags "já usadas" antes de chamar
  `IRG`, evitando reusar a mesma tag em alocações adjacentes.
- **`SUBP`/`SUBPS`**: subtrai dois ponteiros **ignorando os bits de tag** (a subtração de endereço
  trata a tag como parte do endereço, mas o resultado é a diferença de endereço "puro", com
  extensão de sinal conforme `TCR_EL1.TBI`) — `SUBPS` também atualiza `NZCV`.
- **`SETGP`/`SETGM`/`SETGE`** ⚠️: variantes com tag da família acelerada de `memset` que a
  **B19.16** (`FEAT_MOPS`) já cobre para `SETP`/`SETM`/`SETE` sem tag — aqui, além de escrever
  dados, também escrevem a tag de alocação. Medem `⚠️` (misdecode), não `❌` — mesma classe de
  achado que `CPYP`/`CPYM`/`CPYE`/`LDRA`/`FAMAX`/`FAMIN` (E12): outra instrução hoje reivindica
  parte deste encoding incorretamente. **Ler a B19.16 antes de mexer aqui** — as duas famílias
  compartilham o formato `@set` e provavelmente a mesma causa raiz de misdecode no dispatcher de
  "Memory Set" (`decodeLoadLiteral`, comentário em `Aarch64Decoder.java:677-678`, que já lista
  `SETP`/`SETM`/`SETE`/`CPYFP`/`CPYFM`/`CPYFE`/`LDCLRP`/`LDSETP`/`SWPP` como não modelados — a
  família `SETG*` desta task não está nem citada nesse comentário, o que sugere que o gap dela é
  ainda menos mapeado que o das irmãs sem tag).

## Decisão de escopo a tomar no início (e registrar)

`FEAT_MTE2` completo exige: (1) RAM de tags real, indexada por endereço físico/granule; (2)
registradores de sistema `GCR_EL1` (máscara de exclusão global), `RGSR_EL1` (estado do gerador de
tag aleatória), `TFSR_EL1`/`TFSRE0_EL1` (relatório de falha de tag); (3) o modo de checagem
(`TCR_EL1.TCMA0/1`, síncrono/assíncrono/assimétrico) e a exceção de "Tag Check Fault" em todo
acesso de dados tagueado — não só nestas 26 células, mas em TODO `LDR`/`STR` do core. Isso é
trabalho enorme e cruza a fronteira do decode desta task.

**Rota recomendada, seguindo o precedente de `FPCR.RMode`/`FZ` (B8.5) e `FPMR.OSM` (B19.11b)**:
implementar as 26 células com **armazenamento funcional real de tag** (uma estrutura de tags nova
em `Aarch64Core`/no barramento de memória, indexada por endereço arredondado ao granule de 16
bytes) e os efeitos de dados/aritmética exatos (`STZG` zera, `STGP` grava par, `SUBP` ignora tag,
`IRG`/`GMI` operam sobre a máscara de exclusão) — **sem** implementar a checagem de tag em
`LDR`/`STR` comuns nem a exceção de "Tag Check Fault" (equivalente a nunca configurar `TCR_EL1`
para modo síncrono do ponto de vista observável: os dados sempre são acessíveis independente da tag
bater). Registrar esta decisão explicitamente no `## Resultado`, com a mesma disciplina de "decisão
consciente, não lacuna silenciosa" que `FPCR.RMode` já usa (G8).

`GCR_EL1`/`RGSR_EL1` para `IRG` podem ser modelados como armazenamento simples (padrão de `FPCR`),
já que só afetam a ALEATORIEDADE da tag gerada, não a corretude funcional de um programa que já
saiba lidar com qualquer tag.

## Inclui

1. **Estrutura de tags** — uma tabela/mapa de tags de 4 bits por granule de 16 bytes, associada ao
   `Aarch64Core`/barramento de memória do guest (dimensionar pelo espaço de endereço real usado
   pelos testes, não um mapa infinito ingênuo — considerar uma estrutura esparsa).
2. **`STG`/`LDG`/`STZG`/`ST2G`/`STZ2G`** — decode (formato `@ldst_tag`, offset assinado com pré/pós-
   índice conforme `p`/`w`, mesma disciplina de `LDR`/`STR` com offset imediato) + executor
   (grava/lê tag; `STZG`/`STZ2G` também zeram os dados do(s) granule(s)).
3. **`STGM`/`LDGM`/`STZGM`** — decode (formato `@ldst_tag_mult`) + executor de bloco compacto de
   tags (bitmap de 64 bits cobrindo o tag block do endereço).
4. **`STGP`** — decode (`@ldstpair sz=3 sign=0`, mesma família de `LDP`/`STP` de 64 bits) +
   executor (grava par de registradores E a tag).
5. **`SUBP`/`SUBPS`** — decode + executor (subtração de endereço ignorando tag; `SUBPS` atualiza
   `NZCV`).
6. **`IRG`/`GMI`** — decode + executor, com `GCR_EL1`/`RGSR_EL1` como armazenamento simples (ver
   Decisão de escopo).
7. **`SETGP`/`SETGM`/`SETGE`** — primeiro achar a causa raiz do `⚠️` (provavelmente compartilhada
   com `SETP`/`SETM`/`SETE` da B19.16 — coordenar as duas tasks, ou executar esta DEPOIS da B19.16
   se a ordem ajudar), depois decode + executor (memset acelerado + gravação de tag).
8. Testes (ver Aceite).

## Não inclui

- **Checagem de tag em `LDR`/`STR` comuns** e a exceção de "Tag Check Fault" — decisão explícita
  registrada acima, candidata a task futura própria se algum consumidor real precisar.
- **`TFSR_EL1`/`TFSRE0_EL1`** (relatório de falha) — decorrência do item anterior, fora do escopo.
- **`SETP`/`SETM`/`SETE`/`CPYE`/`CPYM`/`CPYP`/`CPYFP`/`CPYFM`/`CPYFE`** (sem tag) ⇒ **B19.16**.
- **`LDCLRP`/`LDSETP`/`SWPP`** ⇒ **B19.25**.
- **Emissão nativa.**

## Aceite

- As 26 células decodificam sob `ARMV8_5_A`+ e seguem `unsupported` abaixo.
- **`STG`/`LDG`** roundtrip: gravar uma tag e lê-la de volta.
- **`STZG`** zera os dados do granule, além de gravar a tag — teste que confere as duas coisas.
- **`STGM`/`LDGM`** cobrem múltiplos granules num único registrador — teste com padrão de bits não
  trivial (tags diferentes por granule).
- **`STGP`** grava o par de registradores E a tag num só teste.
- **`SUBP`** ignora a tag: dois ponteiros com a MESMA base de endereço mas tags DIFERENTES produzem
  a mesma diferença que a mesma base com tags iguais.
- **`GMI`** acumula corretamente múltiplas tags na máscara de exclusão; **`IRG`** nunca gera uma tag
  presente na máscara (teste determinístico, sem depender de aleatoriedade real — usar semente
  fixa ou mock).
- **`SETGP`/`SETGM`/`SETGE`**: teste de regressão do `⚠️` original, igual ao padrão da B19.16.
- `docs/COBERTURA-ISA.md`: as 26 células saem de `❌`/`⚠️` para `✅` de `ARMv8.5-A` em diante.
- `mvn -o test` verde + G5 verde nos 5 consumidores.

## Armadilhas

1. **Não modelar a checagem de tag é uma decisão, não uma lacuna** — registrar explicitamente (G8),
   nunca deixar implícito.
2. **`STZG` zera dados, `STG` não** — confundir os dois é o erro mais fácil.
3. **`STGM`/`LDGM` operam em bloco, não granule a granule** — a largura do "tag block" precisa ser
   confirmada no manual antes de decidir o layout do bitmap.
4. **`SUBP` ignora a tag, mas `TCR_EL1.TBI` ainda pode afetar a extensão de sinal** — conferir o
   pseudocódigo real antes de assumir que é uma subtração de 64 bits comum.
5. **`SETGP`/`SETGM`/`SETGE` são `⚠️`, não `❌`** — achar a causa raiz do misdecode antes de
   "adicionar decode que falta"; coordenar com a B19.16, que tem a família irmã sem tag.
6. **A RAM de tags não pode ser um mapa ingênuo sem limite** se os testes cobrirem endereços
   grandes — dimensionar com cuidado (estrutura esparsa).

## Não fazer

- Não implementar checagem de tag em `LDR`/`STR` comuns nem a exceção de "Tag Check Fault".
- Não implementar `TFSR_EL1`/`TFSRE0_EL1`.
- Não implementar `SETP`/`SETM`/`SETE`/`CPY*` sem tag (B19.16) nem `LDCLRP`/`LDSETP`/`SWPP` (B19.25).
- Não adicionar caso nativo em `Ir64NativePolicy`.
