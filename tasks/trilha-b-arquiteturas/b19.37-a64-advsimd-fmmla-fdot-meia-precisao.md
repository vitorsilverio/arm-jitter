# B19.37 — A64: `FMMLA`/`FDOT` AdvSIMD que faltam (`FEAT_F8F16MM`/`F8F32MM`, `FEAT_F16F32DOT`/`F16F32MM`/`F16MM`)

**Trilha:** B · **Repo:** arm-jitter (A64-only, G5 não se aplica) · **Depende de:** E15.15a ✅ (achado)
**Épico:** `b19-plano-a64-gap-remanescente.md` · **Status:** ⬜ — spec escrita em 2026-10-06 (achado da E15.15a,
registrado como task pela regra 9 do `tasks/README.md`).

## Contexto

A E15.15a passou pelo `objdump` 2.46 do devkitA64 todas as palavras do espaço AdvSIMD `bit21=0` que o decoder
RECUSA (oráculo `e15.15a-scripts/AdvSimdBit21ZeroOracle.java`, preset "todas as features menos SME"). Fora o bug
do `Ra` que a própria E15.15a corrigiu, sobraram cinco famílias que o `objdump` desmonta e o decoder recusa, todas
no "three same extra" (`0 Q U 01110 size 0 Rm opcode 1 Rn Rd`):

| Palavra | `objdump` | Padrão | Feature |
|---|---|---|---|
| `6e1feef4` | `fmmla v20.8h, v23.16b, v31.16b` | `0110 1110 000 Rm 11101 1` (QEMU `FMMLA_hb`) | `FEAT_F8F16MM` |
| `6e9fef62` | `fmmla v2.4s, v27.16b, v31.16b` | `0110 1110 100 Rm 11101 1` (QEMU `FMMLA_sb`) | `FEAT_F8F32MM` |
| `4e9ffecb` / `0e9ffefa` | `fdot v11.4s, v22.8h, v31.8h` / `fdot v26.2s, v23.4h, v31.4h` | `0 Q 0 01110 100 Rm 11111 1` (fora do QEMU) | `FEAT_F16F32DOT` (a confirmar) |
| `4e5feeb4` | `fmmla v20.4s, v21.8h, v31.8h` | `0100 1110 010 Rm 11101 1` (fora do QEMU) | `FEAT_F16F32MM` (a confirmar) |
| `4edfeeb4` | `fmmla v20.8h, v21.8h, v31.8h` | `0100 1110 110 Rm 11101 1` (fora do QEMU) | `FEAT_F16MM` (a confirmar) |

(64 palavras de cada linha na amostra — 32 `Rm` × 2 sorteios de `Rn`/`Rd`.)

- `FMMLA_hb`/`FMMLA_sb` AdvSIMD estão no `a64.decode`, e `docs/COBERTURA-ISA.md` os mede `·` em todas as colunas:
  `Aarch64Feature.FP8_MATRIX_MULTIPLY_FP16`/`FP8_MATRIX_MULTIPLY_FP32` existem (Armv9.6-A, nenhum preset as
  declara) e as formas SVE já foram implementadas pela B17.23 — só a forma AdvSIMD falta.
- `FDOT`/`FMMLA` de meia precisão (`.8h` → `.4s`, `.8h` → `.8h`) não estão no `a64.decode` deste inventário nem
  em `Aarch64Feature`: invisíveis para a tabela. Extensões recentes (2025); nome e versão de cada feature a
  confirmar no ARM ARM/`binutils` antes de criar constante (B17.1 Armadilha 2; E12 achou nomes inventados na TSV).

## Objetivo

As cinco formas decodificam e executam (interpretado) nos presets/arquiteturas com a feature; sem ela, recusadas.

## Inclui

- Confirmar nome, versão e campo de ID (`ID_AA64FPFR0_EL1`?) de `FEAT_F16F32DOT`/`FEAT_F16F32MM`/`FEAT_F16MM`;
  criar as constantes que faltarem em `Aarch64Feature`, sem declarar em preset além do que a versão permite
  (Armv9.6-A+ não tem coluna — mesma regra do bloco "Armv9.6-A" de `Aarch64Feature`).
- Linhas em `AdvSimdBit21ZeroRows` (a tabela da E15.15a; o teste de sobreposição prova que não colidem com
  `BFMMLA`/`FCADD`/`FDOT_hb`/`SMMLA`…). `FMMLA_hb`/`FMMLA_sb` leem `FPMR` (FP8), como as formas SVE da B17.23 —
  reaproveitar o executor delas.
- Records/executor (semântica verbatim do pseudocódigo, `feedback-curl-verbatim-qemu-source`), testes de
  executor com valores conferidos.
- Cobertura: `require(...)` no `IsaCoverageReport` para `FMMLA_hb`/`FMMLA_sb` AdvSIMD; as três formas sem padrão
  no QEMU entram pelo mesmo mecanismo das extensões fora do `.decode` (ver como a B19.35 tratar o `FEAT_CPA`).
- `AdvSimdFpResidueG8Test`: reconferir com `objdump` e atualizar contagem/SHA (o conjunto aceito cresce).

## Não inclui

- Coluna `ARMv9.6-A` em `docs/COBERTURA-ISA.md` (task própria, muda o denominador global).
- Formas indexadas (`FDOT`/`FMMLA` por elemento), se existirem — medir no `objdump`; se houver, task própria.

## Aceite

- As palavras da tabela acima decodificam com a feature (campos conferidos no `objdump`) e são recusadas sem.
- Oráculo da E15.15a antes × depois: diff = exatamente essas famílias.
- `mvn -o -pl core verify` verde; JaCoCo 0 perdido no código novo.

## Armadilhas

- `opcode=11101`/`bit10=1` é compartilhado com `BFMMLA` (`size=01`, `U=1`) e `FCADD`/`FCMLA` (`U=1`); `11111`
  com `BFDOT`/`BFMLAL` (`U=1`) e `FDOT_hb`/`FDOT_sb`/`FMLAL_hb` (`U=0`, `size=0x`/`11`). Só `size` e `U` separam.
- `FMMLA` é `Q=1` fixo (`@rrr_q1e0`); `FDOT` `.2s`/`.4s` tem `Q` livre.
