# B1.1 — ArmFeatures + preset ARMV6K (plumbing, sem instruções novas)

**Trilha:** B · **Depende de:** — · **Repo:** arm-jitter

## Contexto

O mecanismo de gating por arquitetura já existe e funcionou para o ARMv5TE:
`arch/ArmFeature.java` (enum de capacidades/quirks), `arch/ArmArchitecture.java`
(presets `ARMV4T`, `ARMV5TE` via `of(String, ArmFeature...)`) e `arch/DecoderExtension`.
Esta task SÓ prepara o terreno do ARMv6/v6K — nenhuma instrução nova é decodificada.

## Objetivo

Preset `ArmArchitecture.ARMV6K` compilando e testado, com as features novas declaradas
mas ainda não usadas por nenhum decoder.

## Especificação

1. Ler `arch/ArmFeature.java` e `arch/ArmArchitecture.java` inteiros antes de editar.
   Seguir exatamente o estilo existente (javadoc `///` por constante explicando o que
   habilita e em quais arquiteturas existe).
2. Adicionar ao `ArmFeature` (nomes finais podem ajustar ao estilo do enum, mas um
   feature POR grupo funcional, não um "ARMV6" monolítico — os decoders das tasks
   B1.2–B1.5 gateiam cada grupo separadamente):
   - `EXTEND_ROTATE` — SXTB/SXTH/SXTB16/UXTB/UXTH/UXTB16 e variantes com acumulador
     SXTAB/SXTAH/SXTAB16/UXTAB/UXTAH/UXTAB16 (ARMv6+).
   - `BYTE_REVERSE` — REV/REV16/REVSH (ARMv6+).
   - `UMAAL` — multiplicação longa com acumulador duplo (ARMv6+).
   - `PARALLEL_SIMD` — aritmética paralela de 8/16 bits + SEL + flags GE (ARMv6+).
   - `PACK_SATURATE` — PKHBT/PKHTB, SSAT/USAT/SSAT16/USAT16, USAD8/USADA8 (ARMv6+).
   - `EXCLUSIVE_WORD` — LDREX/STREX word (ARMv6).
   - `EXCLUSIVE_SIZED` — LDREXB/H/D, STREXB/H/D, CLREX (ARMv6K).
   - `MODE_CHANGE_INSTRUCTIONS` — CPS, SRS, RFE (ARMv6+).
   - `SETEND_BIG_ENDIAN_DATA` — SETEND + bit E do CPSR (ARMv6+).
   - `WAIT_HINTS` — WFI/WFE/SEV/YIELD como instruções dedicadas (ARMv6K).
3. Adicionar `ArmArchitecture.ARMV6K = of("ARMv6K", <todas as features do ARMV5TE> +
   <todas as novas>)`. Atenção: copiar a lista do `ARMV5TE` explicitamente (o `of`
   recebe varargs; verifique se há forma existente de compor a partir de outro preset —
   se não houver, criar método `extending(ArmArchitecture base, ArmFeature... extra)`).
4. Testes em `arch/`: preset contém as features esperadas; `ARMV4T`/`ARMV5TE` NÃO
   contêm nenhuma das novas (G2).

## Não fazer

- NÃO tocar em decoder, IR, executores ou codegen.
- NÃO criar preset "ARMV6" simples por enquanto (Pi 1 usa quase tudo do v6K; se
  precisarmos, deriva-se depois).

## Aceite

- `mvn test` verde; nenhum comportamento de runtime muda (diff de comportamento zero).
- Javadoc de cada feature nova cita a(s) instrução(ões) e a arquitetura de origem.
