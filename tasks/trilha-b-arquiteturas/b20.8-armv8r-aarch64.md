# B20.8 — ARMv8-R AArch64 (`Cortex-R82`): PMSA no lado A64 (`PRBAR_EL1`/`PRLAR_EL1`) + EL2 obrigatório

**Trilha:** B · **Repo:** arm-jitter (+ revalidação G5) · **Depende de:** B20.7, B19.9 (✅ 2026-09-10)
**Épico:** `b20-plano-perfil-r.md` · **Status:** ⬜ (spec escrita 2026-09-14, ainda não executada)

## Contexto

Este é, nas palavras do plano mestre, *"o degrau que junta as duas metades do projeto"*: o perfil R
chega ao AArch64 (`Cortex-R82`, ARMv8-R AArch64), reusando toda a infraestrutura de 64 bits que
B6/B10/B11/B19 construíram — `Aarch64Core`, `Aarch64ExceptionLevel`, `Aarch64SystemRegisterId`/
`Aarch64SystemRegisterBus`, `AddressSpace64` — e trocando apenas o **modelo de memória**: PMSA
(proteção por regiões) no lugar de VMSA (tabelas de página).

A dependência de **B19.9** (fechamento do épico A64, ✅ 2026-09-10) é o que garante que o conjunto
A64 está completo o suficiente para um preset novo não nascer cheio de buracos: `ARMv8.0-A` mede
99% em `docs/COBERTURA-ISA.md`.

### O que muda em relação à B20.7 (AArch32)

PMSAv8-64 é a **mesma arquitetura de MPU** da PMSAv8-32 (base+limite, granule de 64 bytes, sem
sub-regiões, sobreposição proibida), mas os registradores são de sistema A64 (`PRBAR_EL1`,
`PRLAR_EL1`, `PRSELR_EL1`, `MPUIR_EL1`, `PRENR_EL1`, mais os `_EL2` do hipervisor) e os campos de
falha vão para `ESR_EL1`/`FAR_EL1`, não para `DFSR`/`DFAR`. A fonte normativa é o **ARM ARM
Supplement ARMv8-R AArch64, ARM DDI 0600A** (o link recuperado nesta rodada:
`kib.kiev.ua/x86docs/ARM/ARMARMv8/DDI0600A_d_armv8_r64_supplement.pdf`; a cópia oficial está em
developer.arm.com) — **nenhum campo de bit do lado A64 foi confirmado nesta rodada de spec**, ver
Armadilha 1.

### A pergunta de escopo que esta task tem que responder primeiro

O `Cortex-R82` **pode** ter VMSA em EL1 (o ARMv8-R AArch64 permite uma implementação com MMU em
EL1, o que é uma das novidades do R82 frente ao R52) — enquanto EL2 é sempre PMSA. Isso colide com
o invariante do épico ("PMSA e VMSA são MUTUAMENTE EXCLUSIVOS numa mesma implementação"), que foi
escrito pensando em ARMv7-R. **Decidir e documentar** logo no início: o preset desta task modela o
R82 **só-PMSA** (recomendado — escopo menor, coerente com o épico) e o modo com VMSA em EL1 vira
task futura NOMEADA. Se a leitura do manual contradisser isso, PARE e confirme com o usuário —
mexer no invariante do épico não é decisão de uma sessão de execução.

## Objetivo

Existe `Aarch64Architecture.ARMV8_R_64` (ou nome equivalente) com `Pmsav8AddressSpace64` +
`Pmsav8SystemRegisters64`, `Aarch64Processor.CORTEX_R82` catalogado, e um binário A64 bare-metal
com MPU ativa executa corretamente (proteção aplicada, abort quando negado) nos dois motores.

## Inclui

1. **Features novas em `Aarch64Feature`** (`R_PROFILE`/`PMSA`, nomes a alinhar com os do lado
   32 bits da B20.1 — são enums diferentes, o projeto já tem esse espelhamento em vários casos,
   ver o Javadoc de `ArmFeature.ADVANCED_SIMD_RDM` sobre "mirror de `Aarch64Feature#RDM`").
2. **Entradas novas em `ir64/Aarch64SystemRegisterId`**: `MPUIR_EL1`, `PRSELR_EL1`, `PRBAR_EL1`,
   `PRLAR_EL1`, `PRENR_EL1` (+ `_EL2` se a sessão incluir o hipervisor), cada uma com o Javadoc no
   padrão da classe (`op0=…,op1=…,CRn=…,CRm=…,op2=…` no comentário — é o padrão vigente).
3. **`Pmsav8SystemRegisters64 implements Aarch64SystemRegisterBus`** — espelho estrutural de
   `Aarch64VmsaSystemRegisters` (`handles`/`read`/`write`), programando o banco de regiões.
4. **`Pmsav8AddressSpace64 implements AddressSpace64`** — checagem base≤addr≤limit, `AP`/`XN`,
   background region (`SCTLR_EL1.M`/`.BR`), sobreposição conforme a regra da arquitetura, falha →
   exceção que o motor A64 converte em abort com `ESR_EL1`/`FAR_EL1`.
5. **Preset `ARMV8_R_64`** (lista positiva) + **`Aarch64Processor.CORTEX_R82`** + coluna própria em
   `docs/COBERTURA-ISA.md` — decidir se a coluna entra aqui ou na B20.9 e documentar (a tabela A64
   já tem 16 colunas; uma 17ª é uma mudança grande — considerar).
6. Testes (ver Aceite).

## Não inclui

- **VMSA em EL1** no R82 (ver "pergunta de escopo") — task futura nomeada.
- **Estágio 2 de proteção** (MPU de EL2 sobre EL1) — a infraestrutura existe
  (`Stage2TranslatingAddressSpace64`, B10.8) e o padrão de composição é conhecido, mas é escopo
  próprio. Nomear a task.
- **EL3/estado seguro** — ARMv8-R AArch64 não tem EL3. Confirmar e **testar a ausência** (nenhum
  caminho leva a `Aarch64ExceptionLevel.EL3` sob este preset).
- **Emissão nativa/Truffle** para qualquer coisa nova — padrão da trilha B.
- **PMSAv7/PMSAv8-32** — B20.2/B20.3/B20.7, intocadas.

## Armadilhas

1. **Nenhum campo de bit do lado AArch64 foi confirmado nesta rodada de spec.** A B20.7 confirmou
   `PRBAR`/`PRLAR` **de 32 bits** (XN\[0\], AP\[2:1\], SH\[4:3\], BASE\[31:6\] / EN\[0\], AI\[3:1\],
   LIMIT\[31:6\], via o patch do Xen citando o DDI 0568A.c). O layout de 64 bits é *análogo*, mas
   **não é a mesma largura**: `PRBAR_EL1` tem um campo de base de 52 bits, e supor "é igual com
   mais bits em cima" é exatamente o tipo de suposição que este projeto proíbe. Ler o DDI 0600A.
2. **O status de falha muda de registrador e de formato**: em A64 vai para `ESR_EL1` (EC/ISS), não
   para um `DFSR` de 32 bits. O ISS de uma falha de MPU tem codificação própria — confirmar antes
   de reusar `FaultStatus64` (que é de tradução VMSA).
3. **`Aarch64SystemRegisterId` é um enum consumido por decoder** — acrescentar entradas exige
   conferir que nenhum `switch` exaustivo quebra e que os encodings novos não colidem com
   registradores já mapeados (a classe já registra um achado real da F11 sobre `CRn`/`CRm` iguais
   com `op2` diferente).
4. **Duas features chamadas `PMSA` em enums diferentes** (`ArmFeature` e `Aarch64Feature`) é o
   padrão do projeto (mirror), mas o Javadoc de cada uma tem que apontar para a outra
   explicitamente — senão a próxima sessão acha que é duplicação por engano.
5. **`Cortex-R82` é AArch64-only** (não executa A32 em nenhum EL, ao contrário do R52). Não
   catalogá-lo em `ArmProcessor` (32 bits) — só em `Aarch64Processor`.
6. **Coluna nova na tabela A64**: 16 colunas já tornam o arquivo largo; medir o impacto do diff
   antes, e considerar deixar a coluna para a B20.9 junto do fechamento (documentar a escolha).

## Não fazer

- Não deduzir layout de bits de 64 bits a partir do layout de 32 bits.
- Não implementar VMSA em EL1 do R82, estágio 2, nem EL3.
- Não tocar em `TranslatingAddressSpace64`/`Stage2TranslatingAddressSpace64`/
  `Aarch64VmsaSystemRegisters`.
- Não catalogar `Cortex-R82` no catálogo de 32 bits.
- Não começar antes de ter o DDI 0600A em mãos (a task inteira depende de uma fonte que esta spec
  localizou mas não leu).
