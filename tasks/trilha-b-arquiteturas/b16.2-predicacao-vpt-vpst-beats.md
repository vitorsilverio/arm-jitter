## Contexto

O épico chama isto de "o coração da extensão" e de "espelho conceitual do bloco `IT` (B2.4)". É
verdade nas duas pontas: é estado de decode/execução que sobrevive ENTRE instruções, e o projeto já
tem o precedente exato em `core/ItState.java` + `CpsrRegister#itState()` + `ArmInterpreter` (que
aplica a condição do `IT` e enfileira o avanço) + `IrOp.SetItState`.

### O que o `mve.decode` realmente contém para esta task (medido nesta rodada de spec)

**Só 3 linhas de padrão** — e isso é um achado, porque o épico estimou "~8":

```
{
  VPSEL           1111 1110 0 . 11 ... 1 ... 0 1111 . 0 . 0 ... 1 @2op_nosz     # linha 732
  VCMPCS          1111 1110 0 . .. ... 1 ... 0 1111 0 0 . 0 ... 1 @vcmp          # B16.8
  VCMPHI          1111 1110 0 . .. ... 1 ... 0 1111 1 0 . 0 ... 1 @vcmp          # B16.8
}

{
  VPNOT            1111 1110 0 0 11 000 1 000 0 1111 0100 1101                   # linha 738
  VPST             1111 1110 0 . 11 000 1 ... 0 1111 0100 1101 mask=%mask_22_13  # linha 739
  VCMPEQ_fp_scalar 1111 1110 0 . 11 ... 1 ... 0 1111 0100 ....  @vcmp_fp_scalar  # B16.8/B16.9
  VCMPEQ_scalar    1111 1110 0 . .. ... 1 ... 0 1111 0100 ....  @vcmp_scalar     # B16.8
}
```

com `%mask_22_13 22:1 13:3` — o campo `mask` de 4 bits (bit 22 concatenado com bits[15:13]).

**`VPT` não existe como linha própria.** O comentário do arquivo real diz isso explicitamente
(linhas 698-700):

```
# Comparisons. We expand out the conditions which are split across
# encodings T1, T2, T3 and the fc bits. These include VPT, which is
# effectively "VCMP then VPST". A plain "VCMP" has a mask field of zero.
```

Ou seja: `VPT` é uma `VCMP` (uma das 45 linhas de comparação, B16.8/B16.9) com `mask != 0`. O QEMU
confirma no `do_vcmp` (`target/arm/tcg/translate-mve.c`, via `WebFetch` nesta rodada):

```c
static bool do_vcmp(DisasContext *s, arg_vcmp *a, MVEGenCmpFn *fn) {
    /* ... validation ... */
    fn(tcg_env, qn, qm);
    if (a->mask) {
        gen_vpst(s, a->mask);  /* VPT established */
    }
    s->base.is_jmp = DISAS_UPDATE_NOCHAIN;
    mve_update_eci(s);
    return true;
}
```

Consequência de sequenciamento: **esta task entrega `gen_vpst` (a função) e as 3 linhas próprias;
a B16.8 apenas CHAMA `gen_vpst` quando `mask != 0`.** A dependência declarada no épico (B16.8
depende de B16.2) está correta.

### A semântica, verbatim do QEMU (`target/arm/tcg/mve_helper.c`, obtida por `WebFetch` nesta rodada — NÃO parafrasear na implementação, transcrever)

```c
static uint16_t mve_eci_mask(CPUARMState *env)
{
    /*
     * Return the mask of which elements in the MVE vector correspond
     * to beats being executed. The mask has 1 bits for executed lanes
     * and 0 bits where ECI says this beat was already executed.
     */
    int eci;

    if ((env->condexec_bits & 0xf) != 0) {
        return 0xffff;
    }

    eci = env->condexec_bits >> 4;
    switch (eci) {
    case ECI_NONE:        return 0xffff;
    case ECI_A0:          return 0xfff0;
    case ECI_A0A1:        return 0xff00;
    case ECI_A0A1A2:
    case ECI_A0A1A2B0:    return 0xf000;
    default:              g_assert_not_reached();
    }
}

static uint16_t mve_element_mask(CPUARMState *env)
{
    /*
     * Return the mask of which elements in the MVE vector should be
     * updated. This is a combination of multiple things:
     *  (1) by default, we update every lane in the vector
     *  (2) VPT predication stores its state in the VPR register;
     *  (3) low-overhead-branch tail predication will mask out part
     *      the vector on the final iteration of the loop
     *  (4) if EPSR.ECI is set then we must execute only some beats
     *      of the insn
     * We combine all these into a 16-bit result with the same semantics
     * as VPR.P0: 0 to mask the lane, 1 if it is active.
     * 8-bit vector ops will look at all bits of the result;
     * 16-bit ops will look at bits 0, 2, 4, ...;
     * 32-bit ops will look at bits 0, 4, 8 and 12.
     * Compare pseudocode GetCurInstrBeat(), though that only returns
     * the 4-bit slice of the mask corresponding to a single beat.
     */
    uint16_t mask = FIELD_EX32(env->v7m.vpr, V7M_VPR, P0);

    if (!(env->v7m.vpr & R_V7M_VPR_MASK01_MASK)) {
        mask |= 0xff;
    }
    if (!(env->v7m.vpr & R_V7M_VPR_MASK23_MASK)) {
        mask |= 0xff00;
    }

    if (env->v7m.ltpsize < 4 &&
        env->regs[14] <= (1 << (4 - env->v7m.ltpsize))) {
        /*
         * Tail predication active, and this is the last loop iteration.
         * The element size is (1 << ltpsize), and we only want to process
         * loopcount elements, so we want to retain the least significant
         * (loopcount * esize) predicate bits and zero out bits above that.
         */
        int masklen = env->regs[14] << env->v7m.ltpsize;
        assert(masklen <= 16);
        uint16_t ltpmask = masklen ? MAKE_64BIT_MASK(0, masklen) : 0;
        mask &= ltpmask;
    }

    /*
     * ECI bits indicate which beats are already executed;
     * we handle this by effectively predicating them out.
     */
    mask &= mve_eci_mask(env);
    return mask;
}

static void mve_advance_vpt(CPUARMState *env)
{
    /* Advance the VPT and ECI state if necessary */
    uint32_t vpr = env->v7m.vpr;
    unsigned mask01, mask23;
    uint16_t inv_mask;
    uint16_t eci_mask = mve_eci_mask(env);

    if ((env->condexec_bits & 0xf) == 0) {
        env->condexec_bits = (env->condexec_bits == (ECI_A0A1A2B0 << 4)) ?
            (ECI_A0 << 4) : (ECI_NONE << 4);
    }

    if (!(vpr & (R_V7M_VPR_MASK01_MASK | R_V7M_VPR_MASK23_MASK))) {
        /* VPT not enabled, nothing to do */
        return;
    }

    /* Invert P0 bits if needed, but only for beats we actually executed */
    mask01 = FIELD_EX32(vpr, V7M_VPR, MASK01);
    mask23 = FIELD_EX32(vpr, V7M_VPR, MASK23);
    /* Start by assuming we invert all bits corresponding to executed beats */
    inv_mask = eci_mask;
    if (mask01 <= 8) {
        /* MASK01 says don't invert low half of P0 */
        inv_mask &= ~0xff;
    }
    if (mask23 <= 8) {
        /* MASK23 says don't invert high half of P0 */
        inv_mask &= ~0xff00;
    }
    vpr ^= inv_mask;
    /* Only update MASK01 if beat 1 executed */
    if (eci_mask & 0xf0) {
        vpr = FIELD_DP32(vpr, V7M_VPR, MASK01, mask01 << 1);
    }
    /* Beat 3 always executes, so update MASK23 */
    vpr = FIELD_DP32(vpr, V7M_VPR, MASK23, mask23 << 1);
    env->v7m.vpr = vpr;
}
```

`VPST` (`target/arm/tcg/translate-mve.c`):

```c
static void gen_vpst(DisasContext *s, uint32_t mask) {
    TCGv_i32 vpr = load_cpu_field(v7m.vpr);
    switch (s->eci) {
    case ECI_NONE:
    case ECI_A0:
        /* Update both 01 and 23 fields */
        tcg_gen_deposit_i32(vpr, vpr, tcg_constant_i32(mask | (mask << 4)),
                            R_V7M_VPR_MASK01_SHIFT,
                            R_V7M_VPR_MASK01_LENGTH + R_V7M_VPR_MASK23_LENGTH);
        break;
    case ECI_A0A1:
    case ECI_A0A1A2:
    case ECI_A0A1A2B0:
        /* Update only the 23 mask field */
        tcg_gen_deposit_i32(vpr, vpr, tcg_constant_i32(mask),
                            R_V7M_VPR_MASK23_SHIFT, R_V7M_VPR_MASK23_LENGTH);
        break;
    }
    store_cpu_field(vpr, v7m.vpr);
}
```

`ECI` (`target/arm/internals.h`, verbatim — os valores **não são contíguos**, `3` é reservado):

```c
/* Values for M-profile PSR.ECI for MVE insns */
enum MVEECIState {

    ECI_A0 = 1, /* Completed: A0 */
    ECI_A0A1 = 2, /* Completed: A0, A1 */

    ECI_A0A1A2 = 4, /* Completed: A0, A1, A2 */
```

```c
bool mve_eci_check(DisasContext *s) {
    s->eci_handled = true;

    case ECI_NONE: case ECI_A0: case ECI_A0A1: case ECI_A0A1A2: case ECI_A0A1A2B0:
        return true;
```

### Achado central desta spec: `ECI` e `ITSTATE` compartilham o MESMO campo

O QEMU guarda os dois em `env->condexec_bits`: `& 0xf` é o resto do `ITSTATE`, `>> 4` é o `ECI`. É
por isso que `mve_eci_mask` começa com "se estou num bloco `IT`, `ECI` não vale nada, devolve
`0xffff`" — a arquitetura real sobrepõe `EPSR.ICI/ECI` a `EPSR.IT` porque um bloco `IT` e uma
instrução vetorial interrompida não podem coexistir.

Neste projeto o `ITSTATE` vive em `CpsrRegister` (`itState()`/`setItState(int)`, 8 bits
reconstruídos de dois pedaços não-contíguos, bits 26:25 e 15:10 — ver
`core/CpsrRegister.java:189-206`). **O `ECI` tem que morar no MESMO campo de 8 bits**, não num
campo novo paralelo: caso contrário a entrada/saída de exceção (que preserva o CPSR inteiro via
SPSR, e portanto leva o `ITSTATE` "de carona", conforme o Javadoc de `itState()`) preservaria
`ITSTATE` e perderia `ECI`, que é exatamente o estado que a retomada por beat precisa. Confirmar o
mapeamento exato de bits de `EPSR.ICI/ECI` contra o ARMv8.1-M ARM antes de implementar
(Armadilha 2).

## Objetivo

O projeto ganha a máquina de predicação MVE completa: um `MveVptState` (análogo de `ItState`) com
`elementMask(...)`/`advance(...)`/`eciMask(...)` transcritos do QEMU, `ECI` armazenado no mesmo
campo de `ITSTATE`, e as 3 instruções próprias (`VPST`, `VPNOT`, `VPSEL`) decodificando e
executando sob `ArmFeature.MVE_INTEGER`. **`docs/COBERTURA-ISA.md`: 3 células `·`→`✅` na coluna
`ARMV8_1M_MVE`** — ou nenhuma, se a B16.14 ainda não tiver trocado a `Applicability` (ver
Armadilha 7: medir e documentar qual dos dois é o caso no momento da execução).

## Inclui

1. **`core/MveVptState.java`** (nome sugerido; espelhar `core/ItState.java`: classe final, só
   métodos estáticos, Javadoc `///` em português derivando o algoritmo):
   - `eciMask(int itStateByte)` — transcrição de `mve_eci_mask`.
   - `elementMask(int vpr, int itStateByte, int ltpsize, int lr)` — transcrição de
     `mve_element_mask`, **incluindo a etapa de tail predication** (que consulta `LTPSIZE` e `LR`;
     ver "Não inclui" sobre `LTPSIZE` só existir a partir da B15.6 — se não existir, o parâmetro
     entra com o valor neutro `4`, que desliga a etapa, e isso fica documentado no Javadoc).
   - `advance(int vpr, int itStateByte)` — transcrição de `mve_advance_vpt`, devolvendo o par
     (`vpr` novo, `itState` novo). Como Java não tem tupla, decidir na execução: record pequeno
     (`MveVptAdvance(int vpr, int itState)`) ou dois métodos puros. Preferência: record — é mais
     legível e o custo de alocação não está em caminho quente medido.
   - `vpstMask(int vpr, int eci, int mask)` — transcrição de `gen_vpst`.
   - `isReservedEci(int eci)` — para o `INVSTATE` (valor `3` e `6`/`7` são reservados).
   - Constantes nomeadas (G6): `ECI_NONE=0`, `ECI_A0=1`, `ECI_A0A1=2`, `ECI_A0A1A2=4`,
     `ECI_A0A1A2B0=5`, os shifts/masks de `P0`/`MASK01`/`MASK23` (reusando os da B16.1) e as
     máscaras `0xffff`/`0xfff0`/`0xff00`/`0xf000`.
2. **`ECI` no `CpsrRegister`**: acessores `eci()`/`setEci(int)` sobre o MESMO byte de `itState()`
   (bits[7:4] do byte), com Javadoc explicando a sobreposição arquitetural e por que ela é
   deliberada. **`itState()`/`setItState(int)` não mudam de assinatura nem de semântica** (G3).
3. **Decode de `VPST`** (`mask=%mask_22_13`), **`VPNOT`** e **`VPSEL`** — extensão de decoder nova
   (`Thumb2MveDecoder` ou `Thumb2MvePredicationDecoder`), gateada por `ArmFeature.MVE_INTEGER`,
   registrada **ANTES de `Thumb2NocpDecoder`** em `ARMV8_1M_MVE` (ver Armadilha 1 — é obrigatório).
   `InstructionKind` novos (ou um `Kind` MVE genérico com `liftedOp`, ver Armadilha 5).
4. **A decisão (a)/(b) que a B16.1 deixou aberta**: como a máscara entra no núcleo vetorial
   compartilhado (`advsimd/AdvSimdLanes`, RFC B13.2 D1). Esta task é a primeira que precisa e
   **deve fechar a decisão e registrá-la no `## Resultado`**, porque as 11 tasks seguintes a
   consomem:
   - **(a)** parâmetro `int elementMask` nas entradas que MVE usa (mexe na assinatura de um núcleo
     já consumido por A64 e NEON A32);
   - **(b)** wrapper `advsimd/MveLanes` que calcula em destino temporário e mescla só as lanes
     ativas (`dst = (dst & ~laneMask) | (tmp & laneMask)`), deixando `AdvSimdLanes` intacto.
   Critério objetivo sugerido: (b) preserva G3 interno e custa uma cópia de 128 bits por
   instrução; (a) é mais rápido mas toca ~30 assinaturas. **Medir com um protótipo de uma família
   (ex. `VADD` inteiro) antes de escolher** — mesma disciplina da RFC B13.2.
5. **Execução**:
   - `VPST`: aplica `vpstMask` ao `VPR` conforme o `ECI` corrente.
   - `VPNOT`: inverte `VPR.P0` — **é ela mesma beatwise e predicada** (QEMU usa um helper
     `gen_helper_mve_vpnot`, não um XOR simples); transcrever o helper real, não inventar.
   - `VPSEL`: seleciona lane a lane entre `Qn` e `Qm` segundo o predicado corrente e **também
     atualiza os bits de predicação** (o `trans_VPSEL` seta `DISAS_UPDATE_NOCHAIN` e passa por
     `do_2op`, que chama `mve_advance_vpt`).
   - **O avanço (`mve_advance_vpt`) roda depois de TODA instrução MVE**, não só destas 3. Esta task
     instala o gancho (análogo ao `IrOp.SetItState` de avanço que `ArmInterpreter` já enfileira em
     `core/ArmInterpreter.java:81-93`), e as tasks seguintes só precisam produzir `IrOp`s MVE que
     passem por ele.
   - `mve_eci_check`: valor reservado de `ECI` → `MProfileException.USAGE_FAULT` com o bit
     `INVSTATE` do `UFSR` (o `CFSR`/`UFSR` já ganhou armazenamento real na B15.2; conferir se o bit
     `INVSTATE` já existe lá ou se precisa ser acrescentado — `UFSR` bit 1, ARMv7-M ARM B3.2.15,
     **confirmar contra o manual**).
6. **`VMSR`/`VMRS` com `reg=12` (`VPR`)** — a B15.3 documentou explicitamente que `reg=12` "fica
   fora (B16)". Zero encoding novo (a linha `VMSR_VMRS` de `m-nocp.decode` já é decodificada pela
   B15.3); só o valor `12` passa a ser aceito **quando `MVE_INTEGER` está presente**, movendo o
   valor bruto do `VPR`. Se a B15.3 ainda não estiver fechada na hora da execução, PULE este item e
   registre como pendência — não implementar `VMSR_VMRS` do zero aqui.
7. Testes (ver Aceite).

## Não inclui

- **Nenhuma outra instrução MVE** — as 349 restantes são B16.3-B16.13.
- **`VCMP`/`VPT` propriamente** (as 45 linhas de comparação) — B16.8/B16.9. Esta task entrega
  `vpstMask`, que a B16.8 chama quando `mask != 0`.
- **`VCTP`/`DLSTP`/`LETP`/`LTPSIZE`** — são `LOW_OVERHEAD_BRANCH`, **B15.6**, e vivem em
  `t32.decode`, não em `mve.decode`. Esta task apenas CONSOME `LTPSIZE` na `elementMask`; se ele
  não existir ainda, o parâmetro entra neutro (`4`) e o teste de tail predication fica pendente,
  documentado.
- **Emissão nativa/Truffle** — decode + interpretado apenas.
- **Retomada real de exceção no meio de uma instrução vetorial** (isto é, a entrada de exceção
  gravando `ECI` parcial de verdade porque o emulador interrompeu no beat 2). Esta task implementa a
  LEITURA do `ECI` (uma instrução que começa com `ECI != 0` pula os beats já feitos) e o AVANÇO;
  o lado que ESCREVE `ECI` parcial depende do modelo de interrupção do emulador (hoje as instruções
  são atômicas do ponto de vista do interpretador) — candidata a task própria, a enfileirar, NUNCA
  a excluir (Regra máxima do projeto). Documentar isso explicitamente no `## Resultado`.

- `MveVptState.advance` reproduz `mve_advance_vpt`, incluindo os dois casos "não inverta metade de
  `P0`" (`mask01 <= 8` / `mask23 <= 8`) e "só atualiza `MASK01` se o beat 1 executou".
- `ECI` reservado (`3`, `6`, `7`) produz `USAGE_FAULT` com `UFSR.INVSTATE`, **não** UNDEF.
- `VPST`/`VPNOT`/`VPSEL` decodificam sob `MVE_INTEGER` e **não** decodificam sem ela (G8: sem a
  feature, o que acontece hoje continua acontecendo).
- **Nenhum encoding MVE é decodificado como `NOCP`** sob `ARMV8_1M_MVE` (teste explícito com pelo
  menos um encoding de cada um dos 3 padrões desta task).
- `VPSEL` seleciona lane a lane segundo o predicado, verificado nas 3 larguras de elemento
  (a máscara de 16 bits é lida "todos os bits" para 8 bits, "bits 0,2,4,..." para 16 e
  "bits 0,4,8,12" para 32 — literalmente o comentário de `mve_element_mask`).
- `mvn -o test` verde + G5 verde nos 5 consumidores; `docs/COBERTURA-ISA.md` com delta EXATAMENTE
  de 3 células (ou zero, ver Armadilha 7) e nenhuma célula vizinha alterada.

## Armadilhas

1. **`Thumb2NocpDecoder` engole TODO o espaço MVE** (achado registrado na B16.1, Armadilha 6, e
   confirmado lendo o arquivo): sob `M_PROFILE`, ele reivindica `bits[27:24]=1110`,
   `bits[27:25]=110` e `bits[27:24]=1111` com `bits[31:29]=111` — e os 352 encodings de MVE estão
   todos aí. O decoder desta task **tem** que ser registrado antes dele. Além disso, decidir aqui
   (e documentar) se `Thumb2NocpDecoder` precisa de um gate próprio "não reivindicar o espaço MVE
   quando `MVE_INTEGER` está presente": em hardware real, MVE habilitada faz esses encodings serem
   MVE, não `NOCP`; com MVE presente mas **desabilitada** via `CPACR`, eles voltam a ser `NOCP`.
   Isso é comportamento arquitetural real (o par funcional `NOCP`↔"tenho Helium?"), não detalhe —
   mas pode legitimamente ficar para uma task própria se o `CPACR` ainda não tiver armazenamento
   (a B15.2 decidiu NÃO adicionar armazenamento explícito de `CPACR`; ver o `## Resultado` dela).
2. **`ECI` no lugar errado é um bug silencioso de save/restore de exceção.** Ver "Achado central".
   Se o `ECI` for um campo novo fora do CPSR, o `SPSR` não o preserva e a retomada por beat
   depois de uma interrupção perde o estado — sintoma que só aparece em firmware real com IRQ
   dentro de laço vetorial, exatamente a armadilha que o épico prevê.
3. **`VPNOT` não é `vpr ^= 0xffff`.** Ela é beatwise e predicada (o QEMU chama um helper), então
   inverte só os bits de `P0` correspondentes a beats executados e ainda passa pelo avanço normal
   do `VPT`. Transcrever `HELPER(mve_vpnot)` do `mve_helper.c`, não improvisar.
4. **Predicação e saturação (`QC`) interagem.** O `mve_helper.c` só propaga o flag `QC` do `FPSCR`
   para lanes ATIVAS ("qc |= sat & mask & 1"). Uma implementação que sature e sete `QC` antes de
   aplicar a máscara produz `FPSCR` errado — divergência que o oráculo G1 pegaria só se houver
   teste. Registrar a regra aqui, mesmo que a primeira instrução saturante só apareça na B16.6.
5. **`DecodedInstruction` provavelmente não cabe.** A RFC B13.2 (D2) acrescentou o escape hatch
   `IrOp liftedOp` + `InstructionKind.LIFTED_IR_OP` exatamente porque a forma de operando vetorial
   não cabe nos campos fixos do record. Medir antes de escolher: `VPST` tem só um `mask` de 4 bits
   (cabe em `immediate`), mas `VPSEL` tem `qd`/`qn`/`qm` (3 registradores vetoriais) e quase
   certamente precisa do `liftedOp`. Documentar a escolha.
6. **G4 continua valendo**: uma instrução MVE totalmente predicada (máscara 0) ainda consome ciclo
   e fetch, e ainda avança o `VPT`. O avanço é INCONDICIONAL, como o `ITAdvance()` (ver o Javadoc de
   `ItState#advance`: "executada ou pulada, o avanço é INCONDICIONAL").
7. **Ordem B16.2 × B16.14**: enquanto `IsaCoverageReport` medir `mve.decode` como
   `NOT_IN_ANY_PRESET` (B16.14 é quem troca isso), as 352 células ficam `·` e o delta desta task na
   tabela é **zero**. Isso não é falha — é o desenho da escada (mesmo que a B13.1/B13.2 usaram).
   Medir, confirmar qual é o caso, e documentar; **não** antecipar a B16.14 só para ver as células
   virarem `✅`.
8. **`VPSEL` divide o bloco `{}` com `VCMPCS`/`VCMPHI`** (B16.8) e `VPST`/`VPNOT` dividem com
   `VCMPEQ_fp_scalar`/`VCMPEQ_scalar` (B16.8/B16.9). O decodetree prioriza o padrão mais
   específico: `VPNOT` (todos os bits fixos) antes de `VPST` (`mask` livre) antes das `VCMP*`. Se o
   decoder desta task usar uma máscara larga demais, ele rouba encodings de comparação — e o probe
   de cobertura da B16.8 mediria `✅` falso. Mesma classe de erro que a B15.2 pegou com
   `VLLDM_VLSTM_MASK`/`VSCCLRM_MASK`: **excluir explicitamente** o que ainda não existe.
9. **G3/G5**: `CpsrRegister` é tocado por MUITA coisa (`MRS`/`MSR`, entrada/saída de exceção,
   save-state de `gbaemu`/`ndsemu`). Qualquer mudança lá exige a suíte completa + G5, não só os
   testes novos.

## Não fazer

- Não implementar nenhuma `VCMP` (B16.8/B16.9) — só a função `vpstMask` que elas vão chamar.
- Não implementar `VCTP`/`DLSTP`/`LETP`/`LTPSIZE` (B15.6).
- Não parafrasear `mve_element_mask`/`mve_advance_vpt` "com o mesmo efeito": transcrever. O épico
  já avisa que beat-wise execution "não é detalhe de implementação", e a B2.4 provou o valor de
  transcrever o algoritmo do QEMU e validá-lo contra um oráculo secundário
  (`ItStateExpansionTest`).
- Não mudar a assinatura de `itState()`/`setItState(int)`.
- Não antecipar a troca de `Applicability` do grupo `mve.decode` (B16.14).
- Não decidir (a)/(b) sem protótipo medido — é a decisão que define o custo das 11 tasks seguintes,
  mesmo peso que a RFC B13.2 teve para B13.

## Resultado

**Fechada em 2026-09-16.** As 3 instruções (`VPST`/`VPNOT`/`VPSEL`) decodificam e executam sob
`ArmFeature.MVE_INTEGER`, mais o item 6 ("Inclui"): `VMSR`/`VMRS` com `reg=12` (`VPR`), já que a
B15.3 estava fechada na hora da execução.

**`core/MveVptState.java`** — transcrição das 4 funções do QEMU real (`eciMask`↔`mve_eci_mask`,
`elementMask`↔`mve_element_mask`, `advance`↔`mve_advance_vpt`, `vpstMask`↔`gen_vpst`), obtidas por
`WebFetch` nesta rodada e reconfirmadas linha a linha contra o texto já citado na spec. `advance`
devolve o record `MveVptAdvance(int vpr, int itState)` (decisão tomada: record, não dois métodos
separados). `isReservedEci` cobre `3`/`6`/`7`+ (o enum real só define `0,1,2,4,5`).

**`ECI` no `CpsrRegister`**: `eci()`/`setEci(int)` leem/escrevem o nibble alto do MESMO byte de
`itState()`/`setItState()` — **zero armazenamento novo**, reusando os dois campos não-contíguos já
existentes (bits 26:25/15:10 do CPSR). Confirmado contra o QEMU real (`xpsr_read`/`xpsr_write`,
via `WebSearch`): `condexec_bits` do QEMU já é literalmente este mesmo byte (`ITSTATE[7:0]`), então
`mve_eci_mask`'s `env->condexec_bits & 0xf`/`>> 4` operam sobre o formato que `itState()` já
produzia desde a B2.4 — nenhuma tradução de formato foi necessária.

**Achado real, bug pré-existente corrigido**: `ItState.inProgress(itState)` checava o byte
INTEIRO (`itState != 0`). Com `ECI` passando a ocupar o nibble alto do MESMO byte, um `ECI` válido
não-zero (ex. `ECI_A0A1A2B0`) fazia `inProgress` devolver `true` mesmo fora de qualquer IT block —
`ArmInterpreter`/`StandardIrBlockLifter` então tratavam a instrução MVE como "governada por IT" e
emitiam um `IrOp.SetItState(0, AL)` espúrio DEPOIS do `IrOp.AdvanceVpt` que a B16.2 instala,
zerando o `ECI` que `MveVptState.advance` tinha acabado de calcular (capturado por
`vpstWrapsEciFromA0A1A2B0ToA0Afterwards`/`vprTransferDoesNotAdvanceEci`, que falhavam antes da
correção). Corrigido checando só `ITSTATE<3:0>` (`ItState.inProgress`) — uma entrada real de `IT`
nunca tem `mask=0b0000` (o decoder de `IT` já rejeita essa forma), então o nibble baixo continua
sendo o discriminador correto e suficiente nos dois papéis que o byte agora desempenha.
Comportamento de todo IT block genuíno preservado byte a byte (G3): a mudança só afeta o caso NOVO
(nibble baixo `0`, nibble alto não-zero) que não existia antes da B16.2.

**Decoder** (`Thumb2MvePredicationDecoder`): as 3 máscaras/valores foram computadas bit a bit a
partir do `mve.decode` real (linhas 732-739, citadas na spec) e verificadas por script antes de
codar (nenhum assembler externo confirmou a toolchain MVE nesta sessão — os vetores de teste usam
os mesmos raws calculados, não um binário `.o` real). `VPNOT` é checado ANTES de `VPST` (é
literalmente `VPST` com `mask=0`, achado já documentado na spec) — resolve a ambiguidade sem
exclusão explícita. `VPSEL` rejeita (`null`) qualquer `Qd`/`Qn`/`Qm` fora de `Q0`-`Q7`
(`VfpRegisters.isValidMveQuadRegister`); esse encoding cai em `Thumb2NocpDecoder`, que o recusa
nomeadamente como `NOCP` (G8) — decisão registrada, não investigada mais a fundo (a faixa `Q8`-
`Q15` é UNPREDICTABLE na arquitetura real, sem comportamento definido para reproduzir).

**Decisão (a)/(b)**: nenhum protótipo de família aritmética foi construído nesta sessão — não há
NENHUMA instrução MVE aritmética implementada ainda para medir contra (`VADD` etc. são B16.6+).
`VPSEL` (a única das 3 que toca registradores `Q`) não passa pelo núcleo vetorial compartilhado
(`AdvSimdLanes`): é uma seleção byte a byte direta via `VfpRegisters.element`/`setElement`, sem
operação aritmética nenhuma para reusar. A decisão (a)/(b) para o núcleo aritmético (RFC B13.2)
fica **registrada como ainda em aberto na prática, com recomendação (b)** (wrapper `MveLanes`,
critério já documentado na spec: preserva G3 interno) — a task que primeiro precisar dela (B16.6,
`VAND`/`VADD`/etc.) deve medir com um protótipo real antes de criar a classe, em vez de herdar uma
abstração especulativa sem consumidor.

**`VPNOT`/`VPSEL`, semântica derivada, não verbatim**: `HELPER(mve_vpnot)`/`HELPER(mve_vpsel)` não
foram encontrados no orçamento desta sessão (tentativas via `WebFetch` do `mve_helper.c` real
truncaram antes da seção relevante; `grep.app`/patchwork/lore.kernel.org bloquearam ou não
indexaram o trecho). Implementados por derivação lógica a partir do idioma JÁ usado no MESMO
arquivo (`mve_advance_vpt`'s `inv_mask = eci_mask`) e do pseudocódigo arquitetural (`VPR.P0` como
seletor byte a byte para `VPSEL`, write-enable = `elementMask` corrente): `VPNOT` = `vpr ^=
eciMask(itState)` (afeta só os 16 bits baixos, `P0`); `VPSEL` seleciona `Qn`/`Qm` por byte segundo
`P0`, mascarado por `elementMask`. Testado contra a arquitetura documentada (`MvePredicationTest`),
não contra um oráculo QEMU byte a byte — registrado explicitamente como diferença do padrão
"transcrever, não parafrasear" que o resto da task seguiu, candidata a confirmação numa sessão
futura com acesso ao arquivo QEMU completo.

**`VMSR_VMRS reg=12`**: armazenamento puro (mesmo padrão de `TPIDR_EL0`/`FPCR`/`FPSR` do A64) —
`IrOp.VprTransfer` novo, NÃO beatwise (o QEMU real nunca chama `mve_advance_vpt` para
`VMSR`/`VMRS`, confirmado pelo Javadoc de `trans_VMSR_VMRS` já citado pela B15.3).

**`UFSR.INVSTATE`**: bit `17` do `CFSR` (`UFSR` bit 1) — `CFSR_UFSR_INVSTATE_BIT`, confirmado
contra a mesma numeração de `NOCP`(bit19=UFSR bit3)/`UNDEFINSTR`(bit16=UFSR bit0) que a B15.2/B15.5
já estabeleceram (ARMv7-M ARM B3.2.15).

**`isTerminal`** (`StandardIrBlockLifter`): `VPST`/`VPNOT`/`VPSEL` marcadas terminais (podem
faultar com `ECI` reservado, mesma categoria de `LOOP_START`/`LOOP_END`) — na prática este
emulador nunca PRODUZ um `ECI` reservado (só `MveVptState.advance` escreve `ECI`, sempre um dos 5
valores válidos), então o fault é código defensivo inalcançável pelo decode real, mas terminal por
precaução. `VPR_TRANSFER` não é terminal (armazenamento puro).

`docs/COBERTURA-ISA.md`: **zero-diff** (Armadilha 7 confirmada — `mve.decode` continua
`NOT_IN_ANY_PRESET`, só a B16.14 troca isso). `docs/COBERTURA-JIT.md`: `IrOp.Kind` 114→119 (todos
interpretados, `AsmNativePolicy` devolve `false` para os 5 — "Não inclui" explícito).
`TruffleCodeEmitterSupportsCoherenceTest` atualizado (114→119 constantes, 48→53 kinds
descobertos). `mvn -o test` verde (3982; as mesmas 3 falhas pré-existentes de mojibake,
`Aarch64Fp16VersionCurationTest`×2 + `IsaCoverageReportA64CurationGuardTest`×1) + `truffle` (73) +
`install`. **G5 completo** nos 5 consumidores (gbaemu 240, ndsemu 183, armbox, virtual-arm-box,
n3dsemu — todos verdes, zero-diff).

**Pendência registrada, não excluída** (regra máxima do projeto): a escrita de `ECI` PARCIAL na
entrada de exceção (uma instrução MVE interrompida no meio de um beat) não foi implementada — este
emulador trata toda instrução como atômica do ponto de vista do interpretador. Candidata a task
própria quando o modelo de interrupção ganhar granularidade sub-instrução.
