# B7.3 — `MProfileSystemControl`: SCS mínimo (NVIC, VTOR, SysTick, SHCSR/ICSR)

**Trilha:** B (épico B7) · **Depende de:** B7.2 · **Repo:** arm-jitter
**Referência:** ARMv7-M ARM (DDI 0403E) B3.2 (SCS), B3.3 (SysTick), B3.4 (NVIC).
**Oráculo:** QEMU `hw/intc/armv7m_nvic.c` (prioridades/preempção) — usar para
conferir semântica, não estrutura.

## Contexto

Decisão da RFC-M-PROFILE: NVIC/SysTick entram NA LIB como componente memory-mapped
que o hospedeiro mapeia em `0xE000E000` (o System Control Space), porque o
acoplamento com a entrada de exceção é forte demais para ficar do lado do
hospedeiro. Este componente transforma o `MProfileExceptionModel` de "exceção sob
demanda de teste" (B7.2) em um sistema com pending/active/prioridade de verdade.

## Inclui

### 1. `core/MProfileSystemControl.java` (ou pacote novo `mprofile/` — criar
`mprofile/` e mover `MProfileExceptionModel`/`MProfileException` para lá junto;
registrar o pacote novo no PR)

Componente com `int read32(int offset)` / `void write32(int offset, int value)`
relativos a `0xE000E000`, para o hospedeiro pendurar como handler de página (par
natural: `PagedAddressSpace.mapHandler` de C3 — mas NÃO acoplar: a interface é só
read/write por offset). Registradores (offsets da B3.2; nomear constantes, G6):

| Offset | Reg | Semântica mínima |
|--------|-----|------------------|
| 0xD08 | VTOR | lê/escreve `vectorTableOffset` do modelo (bits 31:7) |
| 0xD04 | ICSR | PENDSVSET/PENDSVCLR(28/27), PENDSTSET/CLR(26/25), VECTACTIVE(8:0) |
| 0xD0C | AIRCR | só VECTKEY(0x05FA) + SYSRESETREQ(2) → callback de reset p/ hospedeiro |
| 0xD18-0xD20 | SHPR1-3 | prioridade das exceções de sistema (8 bits cada, campo por byte) |
| 0xD24 | SHCSR | enable de UsageFault/BusFault/MemManage (v7-M) |
| 0x100+ | NVIC_ISER/ICER (0x100/0x180), ISPR/ICPR (0x200/0x280), IABR (0x300), IPR (0x400+) | até 32 IRQs externas nesta fase (1 word de cada; construtor recebe `externalIrqCount ≤ 32`) |
| 0x010-0x018 | SYST_CSR/RVR/CVR | SysTick: ENABLE, TICKINT, CLKSOURCE, COUNTFLAG |

### 2. Lógica de pendência/prioridade no `MProfileExceptionModel`

- `pendException(n)` / clear / query; prioridade efetiva: NMI=−2, HardFault=−1,
  demais = registrador (IPR/SHPR). PRIMASK mascara tudo ≥ 0.
- **Ponto de injeção**: o mesmo mecanismo que o perfil A usa para IRQ/FIQ entre
  blocos (`ArmCore.setInterruptLine` + checagem em `runBlock`/`step`) — o modelo M
  expõe `boolean hasPendingExceptionAbove(currentPriority)` e o core consulta no
  MESMO ponto onde hoje consulta `interruptLine()` (achar em `runBlock`/
  `stepReturningInternalCycles`); com modelo A nada muda.
- Preempção aninhada: exceção pendente com prioridade menor (mais urgente) que a
  ativa → nova entrada empilhada (B7.2 já suporta handler→handler). Tail-chaining
  como OTIMIZAÇÃO fica FORA (semanticamente idêntico a retornar+entrar; anotar).
- SysTick: `tick(int cycles)` chamado pelo hospedeiro/runner com os ciclos
  consumidos (mesmo padrão dos timers do gbaemu/ndsemu, que são do hospedeiro);
  decrementa CVR, recarrega de RVR, seta COUNTFLAG e pende SYSTICK se TICKINT.

## Não inclui

MPU, DWT/ITM/FPB (debug), CPUID/campos read-only detalhados (devolver valores
fixos plausíveis e documentados), mais de 32 IRQs externas, tail-chaining,
lazy-stacking, DEBUGEN.

## Testes mínimos (`MProfileSystemControlTest`)

1. VTOR: escrever, disparar exceção, vetor buscado da base nova.
2. NVIC: ISER habilita, ISPR pende, IRQ16+n entra com o número certo no IPSR;
   ICPR despende antes de entrar → não entra.
3. Prioridade: IRQ A (prio 0x40) ativa; IRQ B (prio 0x80) pende → NÃO preempta;
   IRQ C (prio 0x00) pende → preempta (entrada aninhada); NMI preempta qualquer um.
4. PRIMASK=1 segura IRQ mas não NMI.
5. PendSV via ICSR.PENDSVSET entra ao final do handler ativo (retorno → entra).
6. SysTick: RVR=100, ENABLE+TICKINT; `tick(250)` → 2 pendências geradas, COUNTFLAG
   lido-e-limpo conforme B3.3.
7. Integração: mini "kernel" de teste (bytes Thumb escritos à mão no teste) com
   main loop + handler SysTick incrementando contador em RAM — roda N ciclos,
   contador bate com o esperado, nos DOIS backends (G1).

## Armadilhas

- Prioridade M-profile: número MENOR = mais urgente; e a comparação de preempção
  usa só os bits implementados do IPR (impl-defined; fixar 8 bits nesta fase e
  documentar).
- ICSR.VECTACTIVE é read-only espelho do IPSR — não criar segundo estado.
- SysTick CVR: escrita de QUALQUER valor zera E limpa COUNTFLAG (pegadinha da B3.3).
- O check de pendência no caminho de bloco é caminho quente do JIT: com modelo A o
  custo tem que continuar sendo o `interruptLine()` de hoje (sem chamada virtual
  extra em A — mesma técnica de B7.1: método default `false`).

## Resultado

✅ (2026-07-23) — `MProfileSystemControl` novo em `core/`: VTOR/ICSR/AIRCR/SHPR1-3/SHCSR/NVIC(ISER/ICER/ISPR/ICPR/IABR/IPR, até 32 IRQs)/SysTick(CSR/RVR/CVR) por offset relativo a `0xE000E000`, decodificador fino em cima do `MProfileExceptionModel` (que ganhou o estado de verdade: `pending[]`/`priority[]`/`externalIrqEnabled[]`/pilha de exceções ativas). `ExceptionModel` ganhou `hasPendingException()`/`enterPendingException(core)` (default `false`/lança, mesma técnica de `interceptsBranch` da B7.1) e `ArmCore.servicePendingIrq` passa a consultar os dois: linha de IRQ do perfil A (inalterado) OU o novo hook do perfil M. Prioridade efetiva fixa p/ NMI(-2)/HardFault(-1), 8 bits configuráveis p/ o resto; preempção só entra com prioridade estritamente mais urgente que a ativa (Thread mode = a mais baixa possível); PRIMASK mascara tudo >= 0. `enterException` virou aceitar número bruto (não só o enum) p/ IRQs externas entrarem pelo mesmo caminho de empilhamento da B7.2, com push/pop na pilha de ativas em entrada/retorno. SysTick: `tick(cycles)` decrementa CVR, recarrega de RVR, seta COUNTFLAG (limpa em QUALQUER leitura de CSR) e pende SYSTICK se TICKINT — **achado da task**: a primeira versão só detectava o cruzamento por zero quando um único `tick()` consumia o período inteiro de uma vez, então alimentar 1 ciclo por chamada (padrão realista de host) nunca disparava a recarga; corrigido para detectar o cruzamento em qualquer granularidade de chamada. 7 testes novos (`MProfileSystemControlTest`): VTOR, NVIC habilita/pende/limpa, prioridade com preempção aninhada + NMI, PRIMASK, PendSV via ICSR entra só depois que a Thread libera, SysTick recarrega 2x em `tick(250)` + granularidade de 1 ciclo/chamada, e uma integração "mini kernel" (loop + handler Thumb reais rodando via `core.step()`, contador em RAM bate o número de recargas). Ficou tudo em `core/` (não moveu p/ pacote `mprofile/` — a alternativa "ou" do enunciado; SP/LR do `ArmCore` são package-private e a mudança de pacote não trazia benefício nesta fase). Suítes arm-jitter (core+truffle) + gbaemu + ndsemu verdes (G5)
