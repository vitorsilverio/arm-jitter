# B10.2 — EL2: registradores de sistema via `MRS`/`MSR`

**Trilha:** B · **Depende de:** B10.1 ✅ · **Repo:** arm-jitter

## Contexto

Segunda task da escada B10 (`b10-plano-el2-el3.md`). B10.1 generalizou `Aarch64ExceptionState`
para bancar `SP`/`ELR`/`SPSR`/`ESR`/`FAR`/`VBAR` nos 4 níveis (`EL1`-`EL3`), mas nenhum registrador
de sistema EL2 é decodificado ainda — `MRS`/`MSR` só resolve o grupo `op1=0` (EL1 "geral") e
`op1=3` (timer EL0), ver `Aarch64Decoder#decodeSystemRegisterId`. Esta task acrescenta o grupo
`op1=4` (EL2), puramente como armazenamento — SEM side effect funcional (nenhum código roda em
EL2 ainda; isso é `HVC` real, B10.4).

## Inclui

Decodificar e armazenar (leitura devolve exatamente o que foi escrito) os 13 registradores EL2
listados no plano mestre, todos `op0=3,op1=4`:

| Registrador | CRn | CRm | op2 |
|---|---|---|---|
| `SCTLR_EL2`   | 1  | 0 | 0 |
| `HCR_EL2`     | 1  | 1 | 0 |
| `MDCR_EL2`    | 1  | 1 | 1 |
| `CPTR_EL2`    | 1  | 1 | 2 |
| `TCR_EL2`     | 2  | 0 | 2 |
| `VTTBR_EL2`   | 2  | 1 | 0 |
| `VTCR_EL2`    | 2  | 1 | 2 |
| `SPSR_EL2`    | 4  | 0 | 0 |
| `ELR_EL2`     | 4  | 0 | 1 |
| `FAR_EL2`     | 6  | 0 | 0 |
| `ESR_EL2`     | 5  | 2 | 0 |
| `CNTHCTL_EL2` | 14 | 1 | 0 |
| `VBAR_EL2`    | 12 | 0 | 0 |

(Encodings conferidos contra a tabela de registradores de sistema do binutils/`aarch64-none-elf-as`
— `S3_4_Cn_Cm_op2` é a forma genérica de `MRS`/`MSR` para qualquer `op0:op1:CRn:CRm:op2`; confirmar
via corpus real na validação, não decorar.)

- `Aarch64SystemRegisterId`: 13 constantes novas.
- `Aarch64Decoder#decodeSystemRegisterId`: novo branch `op1 == SYSREG_OP1_EL2` (constante nova)
  antes do branch `op1 != SYSREG_OP1_EL1 -> null` atual, delegando a um método
  `decodeEl2RegisterId(crn, crm, op2)` espelhando o estilo de `decodeGenericTimerRegisterId`.
- `Aarch64VmsaSystemRegisters` (bus já instalado pelo host para o grupo EL1): estende `handles`/
  `read`/`write` para os 13 registradores novos.
  - `ESR_EL2`/`FAR_EL2`/`VBAR_EL2`/`ELR_EL2`/`SPSR_EL2`: delegam a
    `exceptionState.esr(EL2)`/`.far(EL2)`/`.vbar(EL2)`/`.elr(EL2)`/`.spsr(EL2)` (já existem desde
    B10.1 — mesma disciplina de fonte única já aplicada às versões EL1, ver javadoc da classe).
  - `SCTLR_EL2`/`HCR_EL2`/`MDCR_EL2`/`CPTR_EL2`/`TCR_EL2`/`VTTBR_EL2`/`VTCR_EL2`/`CNTHCTL_EL2`:
    campos novos de armazenamento puro (sem side effect — nenhum bit liga MMU/stage-2/trap ainda,
    isso é B10.4/B10.6/B10.8/B10.9). `SCTLR_EL2.M` NÃO deve ligar `TranslatingAddressSpace64`
    (essa MMU é a de stage-1 EL1; stage-2/EL2 real é B10.8) — não reusar `sctlrValue()`/
    `setMmuEnabled` do grupo EL1 por engano.

## Não inclui

- Roteamento real de `HVC`/`SMC`/IRQ/abort baseado em `HCR_EL2`/`SCR_EL3` — B10.4/B10.5.
- Registradores EL3 (`SCR_EL3`, ...) — B10.3 (pode andar em paralelo, arquivo próprio).
- Qualquer efeito funcional de `HCR_EL2.VM`, `TCR_EL2`/`VTCR_EL2`/`VTTBR_EL2` sobre tradução de
  endereço — stage-2 é B10.8.
- `AT`, registradores de debug, `TLBI` EL2 — demais tasks da escada.

## Validação

- Teste novo cobrindo os 13 registradores: `MSR`/`MRS` round-trip via `Ir64BlockExecutor` real
  (`step()`), valor arbitrário não-trivial (não só `0`/`-1`, para pegar truncamento). Corpus real
  via `aarch64-none-elf-as`/`objdump` para pelo menos 2-3 encodings (ex. `msr hcr_el2, x0`,
  `mrs x0, vttbr_el2`) confirmando os campos `CRn`/`CRm`/`op2` antes de codificar os demais de
  tabela.
- `ESR_EL2`/`FAR_EL2`/`VBAR_EL2`/`ELR_EL2`/`SPSR_EL2` independentes dos seus pares EL1 (escrever
  `ESR_EL1` não deve mudar `ESR_EL2` e vice-versa — já é verdade por construção via o array
  banked de B10.1, mas precisa de um teste que prove).
- `mvn -o test` verde no `core`. `mvn -o install` local.
- **G5**: gbaemu, ndsemu, virtual-arm-box (único consumidor A64), n3dsemu, armbox (40/41
  pré-existente, ver B10.1).
- Sem mudança de comportamento observável em nenhum consumidor hoje (nenhum guest real escreve
  estes registradores ainda — `virtual-arm-box`/F11 pula GIC/PSCI de propósito) — mudança é
  puramente aditiva (G3), sem marco na `docs/COBERTURA-ISA.md` (estes registradores já eram
  contados? conferir antes de assumir "sem mudança").

## Armadilhas

- `op0` continua `3` para EL2/EL3 (só `op1` distingue o nível-alvo do registrador — `op0=2` é o
  grupo de debug, fora de escopo aqui).
- Não confundir `TCR_EL2`/`SCTLR_EL2` com os campos RES1 diferentes de `TCR_EL1`/`SCTLR_EL1` — como
  esta task é armazenamento puro (sem side effect), os bits RES1 não importam ainda, mas não copiar
  valor default de reset de EL1 se algum teste checar valor inicial (reset real é 0 aqui, mesma
  disciplina "sem hospedeiro plugável" já usada por `TPIDR_EL1`).
- **Toolchain devkitA64 (`aarch64-none-elf-as`/`objdump`) indisponível nesta sessão** (não está no
  `PATH`) — os encodings dos 13 registradores foram derivados por FÓRMULA
  (`0xD5000000 | L<<21 | op0<<19 | op1<<16 | CRn<<12 | CRm<<8 | op2<<5 | Rt`), conferida campo a
  campo contra 3 opcodes REAIS já existentes no repo (`SCTLR_EL1`/`TTBR0_EL1`/`TCR_EL1`, de
  `Aarch64VmsaSystemRegistersTest`) antes de gerar os valores novos — não é "corpus real" no
  sentido de `Aarch64DecoderCorpusTest` (`corpus.bin` via assembler real). Teste novo
  (`Aarch64El2SystemRegisterDecoderTest`) documenta isso explicitamente no javadoc da classe.
  Pendência: regenerar via toolchain real quando disponível e, se possível, migrar para
  `corpus.bin`/`corpus.s` (mesmo padrão dos demais grupos de registrador).
