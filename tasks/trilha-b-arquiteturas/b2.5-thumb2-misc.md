# B2.5 — Misc Thumb-2: hints, barriers, MSR/MRS

**Trilha:** B · **Depende de:** B2.1 (e, para reuso de semântica, B1.5) · **Repo:** arm-jitter

## Contexto

Grupo residual de menor volume e menor risco da trilha B2 — instruções de sistema
Thumb-2 cuja semântica em ARM (32-bit) já existe majoritariamente desde a task B1.5
(CPS/hints WFI/WFE/SEV/YIELD/NOP). Esta task é principalmente **decode novo sobre
semântica já implementada**, mais os barriers de memória `DMB`/`DSB`/`ISB` (novos,
ARMv7) e `MRS`/`MSR` em encoding Thumb-2 de 32 bits.

## Objetivo

- Hints Thumb-2 de 16 bits: `NOP`, `YIELD`, `WFE`, `WFI`, `SEV` (formas curtas, dentro
  do espaço de 16 bits do Thumb-1 — conferir se já são cobertas por B1.5 aplicado ao
  Thumb ou se precisam de decode Thumb próprio).
- Barriers ARMv7 (`ArmFeature` novo a definir, ex. `MEMORY_BARRIERS`): `DMB`, `DSB`,
  `ISB` — nesta implementação single-core/single-thread, o core não reordena memória
  de verdade, então a semântica é NOP observável (documentar em javadoc `///` a
  justificativa, mesmo padrão usado para WFE/SEV em B1.5).
- `MRS`/`MSR` Thumb-2 de 32 bits (equivalente ao MRS/MSR ARM, mas encoding próprio de
  Thumb-2 — reusar o `IrOp` de PSR transfer já existente, só o decode é novo).

## Especificação

1. **Encodings:** ARM ARM Thumb-2 Supplement / DDI 0406, seção A5.3 "Miscellaneous
   16-bit instructions" (hints) e A5.3.6/A5.3.7 (barriers, MRS/MSR de 32 bits sob o
   espaço `11110011100x`/coprocessador 15 hint-space — conferir a tabela exata, não
   assumir).
2. **Gating:** nova `ArmFeature.MEMORY_BARRIERS` (ou nome equivalente) para
   DMB/DSB/ISB, seguindo o padrão de B1.1 (`extending`); hints e MRS/MSR ficam sob
   `ArmFeature.THUMB2` (o encoding é novo, mas a semântica reusa `WAIT_HINTS`/
   `MODE_CHANGE_INSTRUCTIONS` de B1.5 internamente — decidir se APENAS o decode
   precisa de gate novo, com a semântica delegando ao mesmo caminho, ou se faz
   sentido exigir ambas as features simultaneamente; documentar a escolha).
3. **IR:** reusar os `IrOp`s de B1.5 (`PsrTransfer`, o record usado para
   CPS/hints) sem duplicar semântica — o decode Thumb-2 só precisa produzir o mesmo
   `IrOp` que o decode ARM já produz para a instrução equivalente.
4. Registrar os handlers no mecanismo de extensão do B2.1.

## Testes mínimos

- Cada hint Thumb-2 (`NOP`/`YIELD`/`WFE`/`SEV`) produz o MESMO efeito observável que
  o equivalente ARM de B1.5 (reusar os testes de B1.5 como referência/espelho).
- `WFI` Thumb-2 deixa o core em HALT, igual ao ARM (mesmo teste de B1.5 adaptado).
- `DMB`/`DSB`/`ISB`: nenhum efeito observável no estado do core além de consumir
  ciclo/fetch (G4) — teste prova que registradores/memória/flags não mudam.
- `MRS`/`MSR` Thumb-2: ida-e-volta lendo/escrevendo CPSR/SPSR, comparado byte-a-byte
  com o resultado do MRS/MSR ARM equivalente.
- Preset sem `THUMB2` (e sem `MEMORY_BARRIERS`): tudo undefined preservado (G2).

## Aceite

- `mvn test` verde; gbaemu/ndsemu verdes (G5); sem emissão ASM nativa.
- Fecha o épico B2 do ponto de vista de "conjunto de instruções Thumb-2" — o aceite
  final do épico (binário Thumb-2 real rodando no runner B4.0 + harness de IT blocks)
  é validado ao final desta task, não antes, já que depende de B2.1-B2.5 completas.

## Armadilhas

- Verificar se os hints de 16 bits Thumb-2 são LITERALMENTE os mesmos encodings que
  o Thumb-1 hint-space já usa (nesse caso pode já haver decode parcial a reaproveitar
  no `ThumbDecoder` atual) — não duplicar se já existir.
- `DMB`/`DSB`/`ISB` como NOP observável é uma simplificação válida SÓ enquanto o core
  for single-threaded sem memória especulativa — documentar isso como premissa
  explícita (relevante se um dia a trilha B6/AArch64 ou multi-core entrar em cena).
- Confirmar que `MSR` Thumb-2 respeita as mesmas restrições de campo (`_fsxc`) que o
  ARM já valida, para não introduzir um caminho mais permissivo por acidente.

## Resultado

✅ (`Thumb2MiscDecoder` novo, plugado via `thumb32DecoderExtensions` para a forma de 32 bits [`MRS`/`MSR` registrador + `DMB`/`DSB`/`ISB`, confirmados contra o QEMU `target/arm/tcg/t32.decode` — "Hints, and CPS"/"Miscellaneous control"/`MRS_reg`/`MSR_reg`], mais decode inline no `ThumbDecoder` para o espaço de hints de 16 bits (`0xBF00`, `t16.decode`) que hoje não tinha NENHUM tratamento [nem UNDEFINED explícito — caía no fallback genérico]. Armadilha do enunciado confirmada: os hints Thumb-2 NÃO são os mesmos encodings do Thumb-1 [esse espaço só existe desde ARMv6T2] — decode novo dos dois lados, reusando o `IrOp.PsrTransfer`/`WaitForInterrupt` de B1.5 sem duplicar semântica [`NOP`/`YIELD`/`SEV`/reservado → `MSR(#imm)->CPSR` com máscara vazia, mesmo truque implícito que o ARM clássico já usa; `WFI` → `WAIT_FOR_INTERRUPT`]. `ArmFeature.MEMORY_BARRIERS` novo [ARMv7] só gateia `DMB`/`DSB`/`ISB`; `IrOp.MemoryBarrier` novo, documentado como NOP observável sob a premissa explícita de core single-thread sem reordenação especulativa. Gating fino: `WFI`/hints exigem `WAIT_HINTS` além de `THUMB2` [sem a feature, UNDEFINED explícito, espelhando o precedente do `WFI` ARM de B1.5]; `NOP` e `MRS`/`MSR` só exigem `THUMB2`. Fora de escopo (documentado): `CPS`/`CLREX`/`SB` de 32 bits e as formas banked de `MRS`/`MSR` [mesmo espaço de bits, mas não pedidos no Objetivo] caem no UNDEFINED controlado já existente; IT block [`mask≠0000` no mesmo opcode de 16 bits dos hints] fica para B2.4, sem alteração. Bug de decode achado e corrigido durante a implementação: posição do bit `r` [CPSR/SPSR] de `MRS_reg` estava a 4 bits do lugar certo [confundido com o prefixo fixo do nibble vizinho] — pego pelo teste de ida-e-volta contra o MRS ARM clássico. 14 testes novos [`Thumb2MiscDecoderTest`]: hints de 16 e 32 bits sem efeito observável, `WFI` [16 e 32 bits] halting o core, gate `WAIT_HINTS`/`MEMORY_BARRIERS` ausente → UNDEFINED, `DMB`/`DSB`/`ISB` sem efeito além de ciclo/fetch [G4], `MRS`/`MSR` ida-e-volta byte-a-byte contra o ARM clássico [CPSR e SPSR, mask `_f` vs `_fc`], IT block ainda UNDEFINED, regressão G2 sem `THUMB2`. Sem emissão ASM nativa [`AsmNativePolicy` rejeita `IrOp.MemoryBarrier`, mesmo padrão das outras instruções de sistema desde B1.5/B2.2]. Suite arm-jitter 531 + gbaemu 219 + ndsemu 175 verdes. **Não fecha o épico B2 ainda**: apesar do texto original da task supor B2.1-B2.5 como a lista completa, B2.3 [load/store 32-bit] e B2.4 [branches + IT block] seguem ⬜ no índice — o aceite do épico depende delas também)
