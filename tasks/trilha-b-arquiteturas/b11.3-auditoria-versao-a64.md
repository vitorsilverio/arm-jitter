# B11.3 — Auditoria: mapear as instruções A64 já implementadas para a versão/feature ARM real

**Trilha:** B · **Repo:** arm-jitter (+ revalidação G5 nos consumidores) · **Status:** ✅ concluída
2026-08-28 · **Depende de:** B11.1 ✅

Task escrita e executada na mesma sessão (só existia como linha na escada do épico, ver
`trilha-b-arquiteturas/b11-plano-aarch64-feature-gating.md`, tabela "Escada"). Priorizada pelo
usuário entre B11.3/B11.4/lacunas A64 pequenas/B12.1 — escolheu B11.3.

## Contexto

`docs/COBERTURA-ISA.md` trata "A64" como uma coluna monolítica: uma célula `✅` só diz "este
mnemônico decodifica hoje", nunca "em que versão/feature ARM real isso existe". `B11.1` já criou
`Aarch64Feature`/`Aarch64Architecture` (19 features catalogadas a partir de
`docs/isa-nao-aplicavel.tsv`, que documenta o que **falta**). Esta task inverte a lógica: para o
que **já está implementado** (✅ hoje), descobrir se é baseline ARMv8.0-A ou uma extensão
posterior — sem isso, `Aarch64Architecture` não tem o que gatear (B11.4) nem o medidor tem como
render por versão (B11.5).

## Objetivo

Auditar os mnemônicos A64 ✅ de `docs/COBERTURA-ISA.md` (528 únicos) e documentar, para os que NÃO
são baseline ARMv8.0-A, a versão/feature real que os introduziu — mesmo formato/rigor de
`docs/isa-nao-aplicavel.tsv` (fonte real citada, não presumida).

## Inclui

- Levantar os 528 mnemônicos ✅ (deduplicados) e classificar cada grupo/família por versão real,
  usando os achados já registrados nas seções "Resultado" das tasks B6.x/B8.x/B10.x (a maior parte
  já documenta a versão ao implementar) como ponto de partida, cruzando com `a64.decode`/
  `translate-a64.c` reais do QEMU quando a versão não estava clara.
- Investigar qualquer discrepância encontrada durante a auditoria (ex.: um mnemônico ✅ que não
  bate com nenhuma família documentada) em vez de presumir — inclui rodar um probe direto no
  `Aarch64Decoder` (não só ler o código) quando o `Ir64Op` resultante for a única forma de
  confirmar o que uma palavra real decodifica.
- Corrigir, na hora (G8), qualquer bug de decode real encontrado durante a auditoria — um
  mnemônico ✅ que na verdade é um encoding colidindo com outra instrução já implementada é uma
  regressão de correção, não só um dado de versão errado.
- Atualizar `docs/isa-nao-aplicavel.tsv` para os casos em que a auditoria mostrar que um ✅ era
  falso (bug de decode corrigido) — essas linhas voltam a ser trabalho pendente, documentado com a
  versão real.

## Não inclui

- Gatear de fato qualquer feature no decoder (B11.4).
- Medidor por versão em `docs/COBERTURA-ISA.md`/`gerar-cobertura-isa.sh` (B11.5).
- Implementar qualquer instrução ainda não decodificada (isso é o resto da Onda 5/`B8.x`/`B9.x`).

## Achados

### 1. Baseline: a esmagadora maioria já é ARMv8.0-A

Dos 528 mnemônicos ✅, a maioria é parte do conjunto base A-profile ARMv8.0-A (inteiro escalar,
AdvSIMD inteiro/FP, load/store, branch/system, EL0-EL3, registradores de sistema básicos — tudo
que `B6.x`/`B8.1`-`B8.10`/`B8.12`-`B8.19`/`B10.x` implementaram). Não há uma linha por mnemônico
para isso (seria ruído sem informação nova — mesma disciplina que `isa-nao-aplicavel.tsv` já usa
para o lado 32-bit: só exceções entram na lista). **Regra**: qualquer mnemônico A64 ✅ que não
aparece nas listas abaixo é ARMv8.0-A baseline.

### 2. Extensões opcionais ARMv8.0-A já implementadas (Cryptographic Extension)

`AESD`/`AESE`/`AESIMC`/`AESMC`/`PMULL_p64`/`PMULL_p8` (`FEAT_AES`/`FEAT_PMULL`, B8.11) e
`SHA1C`/`SHA1H`/`SHA1M`/`SHA1P`/`SHA1SU0`/`SHA1SU1`/`SHA256H`/`SHA256H2`/`SHA256SU0`/`SHA256SU1`
(`FEAT_SHA1`/`FEAT_SHA256`, B8.11b) são extensões **opcionais desde ARMv8.0-A** (não uma versão
posterior) — o Cortex-A53 do raspi3 as tem, confirmado real na própria B8.11. `SB` (Speculation
Barrier, B8.3) é a mesma categoria (`FEAT_SB`, opcional ARMv8.0-A, mandatório ARMv8.5-A).

### 3. Hint-space, RES NOP mesmo sem a feature (não precisam de gate)

`ESB`/`GCSB`/`CHKFEAT` (achado novo desta auditoria) vivem no MESMO espaço de encoding "hints"
(`0xD503...`) que `PACIA1716`/`PACIASP`/`AUTIB`/etc. já documentado em `isa-nao-aplicavel.tsv`
(comentário da seção `BRAZ`/`BLRAZ`/...): arquiteturalmente definidas para se comportar como `NOP`
quando a feature real (`FEAT_RAS`/`FEAT_GCS`/`FEAT_CHK`) não está implementada. Decodificá-las como
`NOP` incondicional é comportamento ARMv8.0-A **correto**, não uma feature emprestada — confirmado
contra `a64.decode` (mesmo prefixo fixo de todas as `hints`).

### 5. Bug de decode real corrigido nesta sessão (G8) — 10 falsos positivos

Achado durante a auditoria (não presumido — confirmado por probe direto no `Aarch64Decoder`,
alimentando as palavras reais): `CPYFP`/`CPYFM`/`CPYFE`/`SETP`/`SETM`/`SETE` (`FEAT_MOPS`,
ARMv8.8-A), `LDCLRP`/`LDSETP`/`SWPP` (128-bit atomics, `FEAT_LSE128`) e `LDAPR_i`/`STLR_i`
("LDAPUR"/"STLUR", `FEAT_LRCPC2`, ARMv8.4-A) apareciam `✅` em `docs/COBERTURA-ISA.md`, mas **não
tinham nenhuma linha de código implementando-os** — eram misdecodificados como `LDR (literal)`
(`decodeLoadsAndStores`, bucket `SUBCLASS_LITERAL` não checava bit24, que distingue `LDR
(literal)` real de "Memory Copy and Memory Set"/"Atomic 128-bit"/`LDAPUR`/`STLUR` no MESMO bucket
— todos compartilham os mesmos bits `[29:28]`). `LDRA` (`LDRAA`/`LDRAB`, `FEAT_PAuth`, ARMv8.3-A)
tinha o mesmo problema em `decodeLoadStoreSingle`: `idx==POST_INDEX`/`PRE_INDEX` com bit21=1 não
era checado (só `UNSCALED`/`REGISTER_OFFSET` com bit21=1 tinham guarda), colidindo com `STR`/
`STUR`.

**Corrigido** (`Aarch64Decoder.java`, G8, aditivo): `LITERAL_SUBCLASS_RESERVED_BIT_SHIFT` novo
(bit24 checado antes de despachar para `decodeLoadLiteral`) + um `if (bit21) throw` novo em
`decodeLoadStoreSingle`/`decodeFpLoadStoreSingle` para os dois `idx` restantes. Regressão positiva
confirmada (`LDR (literal)`/`STUR`/`STR` post/pre/register-offset continuam decodificando
idênticos). Novo arquivo de teste dedicado:
`Aarch64LoadStoreRegisterReservedSpaceDecoderTest` (11 testes: 6 negativos citando a palavra real
+ 5 positivos de não-regressão). `docs/isa-nao-aplicavel.tsv` ganhou as 10 linhas correspondentes
(voltam a ser trabalho pendente real, com a versão/feature real citada).

  `Aarch64Architecture`).
- O bug de decode corrigido aqui era invisível a qualquer suíte de teste existente antes desta
