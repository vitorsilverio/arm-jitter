# B2.7 — Paridade Thumb-2: encodings de 32 bits de tudo que o ARM clássico já executa

**Trilha:** B · **Depende de:** B2.6 · **Repo:** arm-jitter · **3 PRs**

## Contexto (por que isto é URGENTE e não "completude")

Auditoria de 2026-07-15: o épico B2 implementou os grupos NOVOS do Thumb-2, mas
deixou de fora os encodings Thumb-2 de instruções que o projeto JÁ executa em ARM
clássico desde B1.x — e o gcc emite essas formas o tempo todo em `-mthumb -O2`:

- **`MUL.W`, `MLA.W`, `SMULL`/`UMULL`/`SMLAL`/`UMLAL`** (espaço `0xFB`) — qualquer
  multiplicação compilada;
- **shifts por registrador** (`LSL.W Rd,Rn,Rm` etc.), **`SXTB`/`SXTH`/`UXTB`/
  `UXTH(.W)`** com rotação, **`REV`/`REV16`/`REVSH.W`**, **`CLZ.W`**, **`SEL`**,
  **`QADD`/`QSUB`/`QDADD`/`QDSUB`**, **aritmética paralela** (`SADD8.W`...)
  (espaço `0xFA`);
- **`SSAT`/`USAT`/`SSAT16`/`USAT16`** (espaço plain-binary, `top5=0b11110`);
- **`LDREX`/`STREX`/`LDREXB/H/D`/`STREXB/H/D`/`CLREX` de 32 bits** (espaço
  `EXTRA_TOP7` do `Thumb2LoadStoreDecoder`, explicitamente fora do escopo em B2.3,
  javadoc linha 27) — **atomics**: todo binário musl/pthread/kernel Thumb-2 usa;
- **`CPS.W` e `CLREX` do grupo misc** (documentados fora em B2.5).

Sem isto, o aceite de B4.0.3 (busybox Thumb-2) e o preset `ARMV7A` (B3.7) FALHAM
na prática — o binário cai em UNDEFINED na primeira multiplicação. Nenhuma IR nova
é necessária: **todos os records de `IrOp` já existem** (B1.2-B1.5) e já têm
executor + ASM nativo (B1.6). É só decode + testes.

**Oráculo obrigatório:** QEMU `target/arm/tcg/t32.decode` — seções
"Data-processing (register)" (0xFA), "Multiply, multiply accumulate, and absolute
difference" + "Long multiply, long multiply accumulate, and divide" (0xFB),
"Saturate, Bitfield" (plain-binary), "Load/store exclusive, load-acquire/store-release,
table branch". Transcrever padrão por padrão, citando o nome QEMU no comentário
(protocolo B2.x). NÃO deduzir bits de cabeça.

## PR1 — `Thumb2RegisterDataProcessingDecoder` (espaço `0xFA`) + saturação

Nova extensão em `decoder/`, plugada nos presets junto das demais (atualizar
`ARMV6K_THUMB2` — e `ARMV7A` se B3.7 já existir):

| Grupo | Instruções | IR existente (reusar de B1.x — abrir o decoder ARM correspondente e produzir a MESMA `DecodedInstruction`/IR, idealmente via helper compartilhado) |
|-------|-----------|------|
| Shifts por registrador | `LSL.W`/`LSR.W`/`ASR.W`/`ROR.W` Rd,Rn,Rm (com S) | mesmo caminho dos shifts Thumb-1 por registrador (`IrOp.Alu` + ShiftedRegister) |
| Extend | `SXTB`/`SXTH`/`SXTB16`/`UXTB`/`UXTH`/`UXTB16` (+formas `A` com acumulador) e rotação 0/8/16/24 | B1.2 (`EXTEND_ROTATE`) |
| Misc | `REV.W`/`REV16.W`/`REVSH.W`, `CLZ.W`, `SEL` | B1.2 (`BYTE_REVERSE`), ARMv5 `CLZ`, B1.3 (`SEL`) |
| Saturating | `QADD`/`QSUB`/`QDADD`/`QDSUB` | ARMv5TE (`SATURATING`) |
| Paralelas | as 36 formas `S/U/Q/UQ/SH/UH × ADD8/ADD16/SUB8/SUB16/ASX/SAX` | B1.3 (`PARALLEL_SIMD`, `IrOp.ParallelAlu`) |

Gates: as MESMAS `ArmFeature`s que o encoding ARM usa (tabela acima) — um preset
sem `PARALLEL_SIMD` rejeita a forma Thumb-2 também. `claimsEncodingSpace` para o
prefixo `0xFA` inteiro.

Mais, no `Thumb2DataProcessingDecoder` existente (grupo plain-binary, gate
`PACK_SATURATE`): `SSAT`/`USAT`/`SSAT16`/`USAT16` (op4 `0b10x0`/`0b11x0` — conferir
t32.decode; NÃO confundir o campo `sat_imm` com o `widthm1` do bitfield de B3.2).

## PR2 — multiply/long-multiply (espaço `0xFB`)

Nova extensão `Thumb2MultiplyDecoder` (a MESMA classe que B3.2 estenderá depois
com `SDIV`/`UDIV`/`MLS` — se B3.2 já tiver sido executada, estender a classe dela;
se não, criar aqui e atualizar a spec de B3.2 para "estender a classe de B2.7"):

| Instr | Observação |
|-------|-----------|
| `MUL.W`, `MLA.W` | `IrOp.Multiply` (Ra=1111 em MLA = MUL — decodificar como MUL) |
| `SMULL`/`UMULL`/`SMLAL`/`UMLAL` | `IrOp.LongMultiply` |
| `SMLA<x><y>`/`SMULW`/`SMLAL<x><y>`/`SMUL<x><y>` etc. | `IrOp.DspMultiply` (gate `DSP_MULTIPLY`), formas 0xFB1x-0xFB7x |
| `USAD8`/`USADA8` | B1.3 (`IrOp.AbsDiffSum`, gate `PACK_SATURATE`) |
| `UMAAL` | B1.2 (`LongMultiply.accumulateDouble`, gate `UMAAL`) |

## PR3 — exclusivos + misc de 32 bits

1. `Thumb2LoadStoreDecoder`: dentro do subgrupo `EXTRA_TOP7` com
   `LDRD_MARKER_BIT=0`, decodificar `LDREX`/`STREX` word (imm8×4 de offset!
   — diferente do ARM clássico que não tem offset) e `LDREXB/H/D`/`STREXB/H/D`/
   `TBB`-vizinhos já tratados → IR `LoadExclusive`/`StoreExclusive` de B1.4,
   gates `EXCLUSIVE_WORD`/`EXCLUSIVE_SIZED`.
2. `Thumb2MiscDecoder`: `CLREX` de 32 bits (`IrOp.ClearExclusive`) e `CPS.W`
   (reusar `IrOp.ChangeProcessorState` de B1.5, gate `MODE_CHANGE_INSTRUCTIONS`).
3. **`MCR`/`MRC` Thumb-2** (espaço de coprocessador, hw1 `0xEE`): o raw32 tem o
   MESMO layout do encoding ARM que `CoprocessorDecoder` já decodifica — plugar o
   `CoprocessorDecoder` existente também em `thumb32DecoderExtensions` (ou uma
   casca fina que delega), para que `IrOp.Coprocessor`/`CoprocessorBus` funcionem
   em código Thumb-2 (musl v7 lê TLS via `mrc` em Thumb — pré-requisito real de
   B4.0.3/B4.0.4). Teste de ida-e-volta ARM×Thumb-2 com um bus fake.

## Testes mínimos (por PR, padrão B2.2/B2.3)

1. **Ida-e-volta contra o ARM clássico**: para CADA instrução, o encoding Thumb-2
   e o ARM equivalente produzem estado final idêntico registro-a-registro e
   flag-a-flag (o cross-check que pega bit de campo errado — foi assim que B2.5
   achou o bug do MRS).
2. Gates: cada grupo sem a feature → UNDEFINED; G2 sem `THUMB2`.
3. STREX.W com offset imm8 ≠ 0 (a forma que não existe em ARM — vetor dedicado).
4. Equivalência interpretado×ASM de bloco misto (as IRs já são nativas desde B1.6
   — `perOpFallbackOpCount()==0` esperado; se alguma cair em fallback, é bug de
   política, investigar antes de aceitar).
5. Regressão: BL/BLX de 32 bits (B2.6) intacto com as extensões novas plugadas.

## Armadilhas

- O espaço 0xFA tem `op1`/`op2` que distinguem shift × extend × paralelas × misc —
  a tabela A5-24/A5-25 é densa; siga o t32.decode linha a linha, não o instinto.
- Rd/Rn/Rm ∈ {13,15} → UNDEFINED (A5.3, mesma citação de B2.2.1) em TODO o espaço
  0xFA/0xFB.
- `MLA.W` com Ra=1111 É `MUL.W` (não UNPREDICTABLE) — alias real.
- As formas paralelas Thumb-2 têm os DOIS operandos nos halfwords — não assumir a
  posição do ARM clássico.
