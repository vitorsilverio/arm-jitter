# B8.3 — A64: branch/system

**Trilha:** B · **Depende de:** B8.2 (✅) · **Repo:** arm-jitter

## Contexto

Terceira task da escada A64 (B8) do plano mestre `b7-plano-cobertura-isa.md`. B8.1 fechou
load/store escalar, B8.2 fechou o resto de "inteiro". B8.3 ataca "Branch/system": `CB*`, `BRK`/
`HLT`, `DSB`/`CLREX`/`SB`, `MSR`/`MRS` restantes, `WFET`/`WFIT`, `SYS` — ~35 lacunas no inventário
do QEMU segundo o plano mestre. O plano mestre marca esta escada como a que "é o que um kernel
Linux realmente executa, e destrava a F11" (`virtual-arm-box` raspi3-64).

⚠️ **Sem spec formal escrita antes da implementação** — mesmo padrão ad-hoc de B8.1/B8.2: task
grande o bastante para uma sessão dedicada, mas o plano mestre já traz escopo e protocolo
suficientes. Este arquivo documenta as decisões tomadas e o resultado, não um plano prévio.

## Inclui

- `WFET`/`WFIT` (`FEAT_WFxT`) — mesmo tratamento de `WFE` (NOP)/`WFI` (dorme até IRQ), sem
  timeout modelado.
- `CLREX` — fecha o monitor de exclusividade de verdade (`Aarch64Core#clearExclusiveMonitor`, já
  existia para abort/IRQ; agora também acionável pelo guest).
- `DSB` (variante `nXS`, `FEAT_XS`) — NOP, mesmo tratamento de `DSB`/`DMB`/`ISB`.
- `SB` (`FEAT_SB`) — NOP, sem especulação modelada.
- `MSR (immediate)` restantes: `UAO`/`PAN`/`SPSel`/`SSBS`(nome QEMU `SBSS`)/`DIT`/`TCO` (NOP —
  nenhum campo de `PSTATE` correspondente é lido por nenhum consumidor modelado) e `DAIFSet`/
  `DAIFClr` (semântica real sobre o bit `I`, o único de `DAIF` modelado desde B6.6.7).
- `ALLINT` (NOP, mesmo motivo dos outros campos de `PSTATE` acima).
- `BRK` — exceção síncrona real (`ESR_EL1.EC=0x3C`, `ISS=imm16`), essencial para
  `BUG()`/`WARN_ON()`/UBSAN do Linux.
- `HLT` — sem estado de debug externo modelado, vira `UNDEFINED` (`EC=0x00`), fiel ao
  pseudocódigo real do manual.
- `SYS` (`TLBI`/manutenção de cache): ampliado de "só `VMALLE1`/10 operações específicas" para
  "qualquer `TLBI` do regime EL1" e "qualquer manutenção `IC`/`DC` exceto `DC ZVA`" — ver
  "Decisão: SYS" abaixo.
- **Achado real desta task (G8)**: 3 formas de `MSR (immediate)` (`SBSS`/`DIT`/`ALLINT`) já
  apareciam ✅ na tabela de cobertura ANTES desta task por misdecode silencioso — ver "Bug real
  encontrado e corrigido" abaixo.

## Não inclui

- `CB<cc>` (`CB_cond`/`CB_cond_imm`, `FEAT_CMPBR`, Armv9.5-A) — posterior ao Cortex-A53 (Armv8.0-A)
  do raspi3, alvo primário desta frente. `docs/isa-nao-aplicavel.tsv`.
- `BRAA`/`BRAB`/`BLRAA`/`BLRAB`/`RETAA`/`RETAB`/`ERETAA`/`ERETAB` (`FEAT_PAuth`, ARMv8.3-A) —
  idem, posterior ao Cortex-A53. As formas "hint" de PAC (`PACIA1716`/`PACIASP`/...) já
  decodificavam como NOP desde B6.6.7 (RES NOP arquitetural mesmo sem `FEAT_PAuth`); só as formas
  de branch REAL ficam de fora. `docs/isa-nao-aplicavel.tsv`.
- `MSR SVCR` (`FEAT_SME`) — controla estado de streaming-SVE/ZA, que não existe sem SME nenhum
  implementado (mesma decisão já registrada para todo o grupo SVE/SME).
  `docs/isa-nao-aplicavel.tsv`.
- `AT` (address translation, escreve `PAR_EL1`) e `SYSL`/`MRS`/`MSR (register)` com `op0=2`
  (registradores de debug) — **deliberadamente deferidos, não presumidos desnecessários** (ver
  "Decisão: SYS" abaixo — o precedente EL1/EL2 do plano mestre é levado a sério aqui).
- Suporte ASM nativo para os `Kind`s novos — `Ir64NativePolicy` não os lista (`default -> false`
  já cobre automaticamente), caem no interpretado (mesmo padrão de escopo de B8.1/B8.2).

## Decisão: SYS (TLBI/cache maintenance)

Este emulador não modela NENHUMA TLB nem cache — a spec original (B6.6.3) só reconhecia
`TLBI VMALLE1(IS)` (invalidação total, sem per-VA/per-ASID) e 10 operações `IC`/`DC` específicas
por engano de escopo. Como não existe TLB/cache real para invalidar de forma diferenciada, este
emulador trata **qualquer** `TLBI` do regime EL1 (`op1=0b000`, qualquer `CRm`/`op2` dentro de
`CRn=0b1000`) e **qualquer** manutenção `IC`/`DC` (`CRn=0b0111`, qualquer `op1`/`CRm`/`op2`,
exceto `DC ZVA`) como NOP — invalidar/limpar "demais" nunca corrompe estado (ao contrário de
invalidar "de menos"), então a generalização é segura, não uma aproximação arriscada. `DC ZVA`
continua excluída (efeito observável real — zera memória — e já anunciada como indisponível via
`DCZID_EL0.DZP=1`, B6.10).

`AT` (escreve `PAR_EL1` com um resultado de tradução real) e os registradores de debug
(`MRS`/`MSR` com `op0=2`) ficam de fora: **isto é documentado como próximo passo, não como
"provavelmente desnecessário"** — o plano mestre cita explicitamente o precedente de EL1/EL2
("descartado como desnecessário e depois exigido inteiro pelo `virtual-arm-box`") como o erro a
não repetir. Se um kernel real precisar de `AT`/debug regs para bootar, vira task futura, não
regressão silenciosa.

## Bug real encontrado e corrigido (não eram gaps, era decode ERRADO — G8)

`CFINV`/`XAFLAG`/`AXFLAG` (B8.2) e os `MSR (immediate)` novos desta task compartilham o MESMO
`CRn=0b0100` — só `op1` os distingue (`op1=0b000` para o primeiro grupo, `op1=0b001` para
`ALLINT`, `op1=0b011` para `SBSS`/`DIT`/`TCO`/`DAIFSet`/`DAIFClr`/`SVCR`). O decoder de B8.2 NÃO
checava `op1`, só `CRn`+`op2` — e por coincidência de valores de `op2` (`SBSS.op2=001` colide com
`XAFLAG.op2=001`; `DIT.op2=010` colide com `AXFLAG.op2=010`; `ALLINT.op1=0b001,op2=000` colide
com `CFINV.op2=000`), `MSR SBSS`/`MSR DIT`/`MSR ALLINT` já decodificavam "com sucesso" — só que
como `XAFLAG`/`AXFLAG`/`CFINV`, silenciosamente errado. A tabela de cobertura já marcava as 3
formas `MSR_i_*` como ✅ por esse motivo (mesma classe de achado que `REV32`/`REV64` em B8.2 —
"decode teve sucesso" não é "decode correto"). Corrigido: `op1` agora é checado antes de
despachar por `op2` (`Aarch64Decoder#decodeFlagOrPstateImmediate`).

## Escopo implementado

- **`WFET`/`WFIT`**: subgrupo de encoding PRÓPRIO ("System instructions with register argument",
  `CRn=0b0001`, DIFERENTE do subgrupo "Hints" de `WFE`/`WFI`, `CRn=0b0010`) — único deste bloco
  inteiro em que `Rt` é um registrador de verdade (`Xd`, valor de timeout), não o `11111` fixo de
  barreiras/hints. Reaproveita `Ir64SystemInstructionOp.NOP_HINT`/`WFI` (sem `Kind`/record novo —
  a semântica executada é idêntica a `WFE`/`WFI`, só a origem do encoding muda).
- **`CLREX`/`DSB(nXS)`/`SB`**: mesmo subgrupo "Barriers" (`CRn=0b0011`) de `DSB`/`DMB`/`ISB`, só
  `op2` novo. `CLREX` ganha `Ir64SystemInstructionOp.CLEAR_EXCLUSIVE` (única com efeito real:
  `core.clearExclusiveMonitor()`); `DSB(nXS)`/`SB` reaproveitam `BARRIER`.
- **`MSR (immediate)`**: `Aarch64Decoder#decodeFlagOrPstateImmediate` (novo método, extraído do
  antigo bloco `CFINV`/`XAFLAG`/`AXFLAG` inline) resolve os 3 grupos de `op1` descritos acima.
  `UAO`/`PAN`/`SPSel`/`SBSS`/`DIT`/`TCO`/`ALLINT` viram `Ir64SystemInstructionOp.PSTATE_FIELD_NOP`
  (sem estado modelado). `DAIFSet`/`DAIFClr` ganham um record novo, `Ir64Op.InterruptMask(boolean
  set, int mask)` — só o bit `I` do `mask` (posição 1, ordem `D:A:I:F`) tem efeito
  (`PstateRegister#setIrqDisabled`), `D`/`A`/`F` ignorados (sem consumidor modelado, mesma decisão
  já registrada em B6.6.7).
- **`BRK`/`HLT`**: `Aarch64Core#enterSynchronousException` novo (extraído de `enterMemoryAbort`,
  que passa a só computar `ESR`+`FAR` e delegar) — núcleo comum reaproveitado por
  `enterBreakpointException`/`enterUndefinedInstructionException`. Executor lança
  `Aarch64BreakpointException`/`Aarch64UndefinedInstructionException` (unchecked, sem stack
  trace, mesmo padrão de `MemoryTranslationException64`), capturadas no MESMO ponto de
  `Ir64BlockExecutor#step`/`#executeBlock` que já rastreia o endereço da instrução fetched mais
  recente — nenhum campo de endereço novo no `Ir64Op.Breakpoint`/`UndefinedInstructionTrap`.
- **`SYS` (TLBI/cache)**: ver "Decisão: SYS" acima — `decodeSystemInstructionSys` simplificado
  para `op1==EL1_GERAL && CRn==TLBI` (qualquer `CRm`/`op2`) e `CRn==CACHE && !isDataCacheZva`
  (substituindo a tabela `SYSTEM_INSTRUCTION_CACHE_OPS` de 10 linhas por uma única exclusão).

## Armadilhas encontradas

- `CRn` sozinho não desambigua o subgrupo "System" inteiro — `CFINV`/`XAFLAG`/`AXFLAG` e a maior
  parte de `MSR (immediate)` compartilham `CRn=0b0100`, só `op1` separa os grupos (ver "Bug real
  encontrado e corrigido" acima). Regra prática (mesma lição de B8.2 com `opc2`): ao adicionar um
  novo subgrupo cujo `CRn` colide com um já implementado, procurar ativamente o campo de
  desambiguação completo (`op1` aqui) ANTES de assumir que `op2` sozinho já resolve.
- `WFET`/`WFIT` moram num subgrupo de encoding PRÓPRIO (`CRn=0b0001`, "System instructions with
  register argument"), não dentro de "Hints" (`CRn=0b0010`) como se poderia supor pelo nome
  parecido com `WFE`/`WFI` — e é o único subgrupo do bloco inteiro em que `Rt` é um registrador de
  verdade, não o `11111` fixo universal do resto do grupo "System" nesta fatia.
- "Sem TLB/cache modelada" torna a generalização de `TLBI`/manutenção de cache para "qualquer
  variante = NOP" **correta**, não uma aproximação — mas só vale enquanto isso permanecer
  verdadeiro; se uma TLB real algum dia for modelada (ex. para medir performance de miss), essa
  simplificação precisa ser revisitada (per-VA/per-ASID passam a importar de verdade).
