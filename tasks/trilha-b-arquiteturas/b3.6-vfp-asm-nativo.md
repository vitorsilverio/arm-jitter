# B3.6 — VFP + inteiro v7: emissão ASM nativa

**Trilha:** B (épico B3) · **Depende de:** B3.5 (e B3.1/B3.2 para o lado inteiro) · **Repo:** arm-jitter

## Contexto

Espelho da B1.6: depois que decoder+IR+interpretador estão provados, liberar a
emissão nativa no backend `JVM_BYTECODE` e remover as rejeições do `AsmNativePolicy`
adicionadas em B3.1/B3.4. Dividir em **2 PRs**: PR1 inteiro v7, PR2 VFP.

## PR1 — inteiro v7 (ops de B3.1/B3.2)

Bytecode direto, sem helper (todas são expressão pura sobre ints — seguir o padrão
dos emitters de B1.6/PR1 em `codegen/jvm/` — `StandardJvmEmitters`/`AsmBlockCompiler`):

| IrOp | Emissão |
|------|---------|
| `BitFieldExtract` | `(src << (32-lsb-width))` seguido de `>>` (signed) ou `>>>` (unsigned) por `(32-width)` |
| `BitFieldInsert` | máscara AND/OR com constantes pré-computadas no emit (BFC = AND só) |
| `BitReverse` | `Integer.reverse` (JIT intrínseco) via chamada estática — igual a `Integer.reverseBytes` do REV em B1.6 |
| `Divide` | branch para os 2 casos especiais (divisor 0 → 0; para signed, MIN/−1 → MIN — nota: `IDIV` da JVM já devolve MIN sem trap nesse caso, só o divisor 0 precisa de guard) + `IDIV`; unsigned via `Integer.divideUnsigned` (intrínseco) |
| `Multiply` com `subtractFromAccumulator` | `ISUB` no lugar do `IADD` no caminho MLA já existente |
| `MoveTop`/`MemoryBarrier` | `MoveTop` = AND/OR direto (16 baixos preservados); `MemoryBarrier` = nenhum bytecode além de Cycle/Fetch |

## PR2 — VFP

Estratégia (decidida — não reavaliar): **bytecode direto para o caminho quente**
(`VfpAlu` ADD/SUB/MUL/DIV/NEG/ABS/COPY, `VfpLoad`/`VfpStore`, `VfpCoreTransfer`,
`VfpMoveImmediate`), **helper estático em `AsmRuntimeHelpers` para o resto**
(`SQRT`, `MLA/MLS/NMUL`, `VfpCompare`, `VfpConvert`, `VfpMultipleTransfer`,
`VfpCorePairTransfer`, `VfpSystemTransfer`) — mesmo custo/benefício do padrão
"helpers com efeito colateral no core" que B1.6/PR2 usou para parallel/saturate.

- Acesso ao banco: `core.vfp()` exposto ao bytecode via `GuestToHostMapper`/
  `HostMethodBinding` (espelhar como o bytecode chama `loadWord`/helpers hoje).
  Caminho direto: `vfp().s(i)` → `Float.intBitsToFloat` → `FADD` →
  `Float.floatToRawIntBits` → `setS`. **`floatToRawIntBits`, nunca
  `floatToIntBits`** (o não-raw canonicaliza NaN e quebra bit-exatidão com o
  interpretador).
- Double idem com `DADD` etc. e as views `d()/setD`.
- `AsmNativePolicy`: liberar tudo de FP EXCETO nada — cobertura completa; rejeições
  remanescentes documentadas se alguma sobrar (não deveria).

## Testes mínimos

1. Equivalência exaustiva por grupo, espelhando `ArmV6*NativeEquivalenceTest` de
   B1.6: para cada IrOp novo, bloco sintético rodado interpretado × ASM com
   `CpuSnapshot` (que já inclui banco S + FPSCR desde B3.3) — incluir vetores NaN
   payload, ±0.0, subnormais, MIN_VALUE/−1, x/0.
2. Property test estilo C2: 64 valores float aleatórios com seed fixa × todas as
   `VfpOperation` × single/double — bits idênticos interpretado × ASM.
3. `perOpFallbackOpCount() == 0` nos blocos sintéticos de FP (prova de que nada
   caiu no fallback).
4. 14 condições × VCMP+VMRS (flags de FP → CPSR → execução condicional) no harness.

## Validação

`mvn -o test` raiz + gbaemu/ndsemu verdes. Depois de B3.7: `armbox --check` com o
binário hard-float (divergence-check real). Commits `B3.6: PR1 ...` / `B3.6: PR2 ...`.

## Armadilhas

- `floatToRawIntBits`/`doubleToRawLongBits` SEMPRE — teste 1 com NaN payload pega.
- `FNEG`/`DNEG` da JVM seguem IEEE (trocam sinal de NaN e de ±0.0) — coincide com o
  VNEG do ARM; mas se o interpretador (B3.4) implementou via bit de sinal, os dois
  caminhos devem bater — o property test cobre.
- Guard do `Divide`: a ordem dos branches importa (checar divisor 0 ANTES do IDIV).
- Nenhuma op FP toca CPSR — só `VfpCompare`→FPSCR e `VfpSystemTransfer(15)`→CPSR;
  não deixar o register-cache de flags do compilador invalidar à toa (ver como
  `PsrTransfer` é tratado hoje e espelhar).

## Resultado

✅ PR1 2026-07-22, PR2 2026-07-23 — **PR1** (inteiro v7 de B3.1/B3.2): `AsmNativePolicy` libera `BitFieldExtract`/`BitFieldInsert`/`BitReverse`/`Divide`/`MoveTop`/`MemoryBarrier` e `Multiply` (MLS incluso, sem mais checar `subtractFromAccumulator`). `AsmBlockCompiler` ganha `emitBitFieldExtract` (ISHL+ISHR/IUSHR, o mesmo truque do interpretado), `emitBitFieldInsert` (máscara `(((1<<width)-1)<<lsb)` pré-computada no emit; BFC pula o passo de inserção por inteiro em vez de OR com zero), `emitBitReverse` (`Integer.reverse`, intrínseco JIT — mesmo padrão do REV/`reverseBytes` de B1.6), `emitDivide` (guard do divisor 0 ANTES do `IDIV`, ordem confirmada pela Armadilha da task; `Integer.MIN_VALUE/-1` não precisa de guard — `IDIV` da JVM já devolve MIN sem trap), `emitMoveTop` (AND 0xFFFF + OR imediato«16, preserva a metade baixa). `emitMultiply` ganhou o branch MLS: pilha tem `[produto, acumulador]` após empilhar o acumulador — precisa de `SWAP` antes do `ISUB` para subtrair na ordem certa (`acumulador − produto`), não óbvio na primeira tentativa. `countAccesses` (register cache) ganhou os 5 casos nativos com registrador (BitField*/BitReverse/Divide/MoveTop; MemoryBarrier não tem registrador). 2 testes pré-existentes de B3.1/B3.2 que fixavam o comportamento PRÉ-B3.6 (`perOpFallbackOpCount() > 0`) tiveram a asserção invertida para `== 0`: `Thumb2MultiplyDivideDecoderTest` (suíte normal) e `ArmV7MediaDecoderTest$PerOpEquivalence` (achado: essa classe estática aninhada NÃO é descoberta pelo `mvn test` normal — surefire só casa `*Test`/`Test*` no nome da classe top-level; só rodou explicitamente via `-Dtest='ArmV7MediaDecoderTest$PerOpEquivalence'` — verificação manual necessária, não pega em `mvn -o test` da raiz). Suíte arm-jitter 812 core + 13 truffle verdes (`mvn -o test`, JBR 25) + `mvn -o install` + gbaemu (`JitInterpreterDivergenceTest` sem divergência em 20M blocos) + ndsemu verdes — zero regressão. **PR2** (VFP de B3.4/B3.5): `AsmNativePolicy` libera os 10 records `IrOp.Vfp*` — cobertura completa, nenhuma rejeição remanescente. Bytecode direto (caminho quente) para `VfpAlu` ADD/SUB/MUL/DIV (via `sFloat`/`dDouble` + `FADD`/`DADD`/... nativos da JVM + `setSFloat`/`setDDouble`, que já usam `floatToRawIntBits`/`doubleToRawLongBits` por dentro — nunca a forma não-raw, que canonicalizaria NaN), NEG/ABS (XOR/AND só no bit de sinal via `s`/`d` crus, sem conversão de tipo — evita completamente a armadilha do NaN), COPY (cópia crua), `VfpLoad`/`VfpStore` (reusa os MESMOS helpers `loadWord`/`storeWord` de LDR/STR — dupla precisão via `packDoubleWords` novo), `VfpCoreTransfer` (lê/escreve o registrador ARM pelo register cache via `emitReadRegister`/`emitStoreRegister`, sem spill). Helper estático em `AsmRuntimeHelpers` para o resto: `vfpAluCold` (MLA/MLS/NMUL/VSQRT — MLA/MLS seguem NUNCA usando `Math.fma`, mesma regra de B3.4), `executeVfpCompare`, `executeVfpConvert`, `executeVfpMultipleTransfer`, `executeVfpCorePairTransfer`, `executeVfpSystemTransfer` (incl. o caso `VMRS APSR_nzcv`) — os 3 últimos tocam registrador(es) ARM DIRETAMENTE no core (por índice arbitrário, fora do register cache) e por isso são cercados por `emitSpilled` no ponto de despacho, exatamente o mesmo tratamento que `PsrTransfer`/`Coprocessor` já tinham (a "cautela com o register cache" da task — não havia um cache de flags separado para se preocupar, CPSR/FPSCR nunca são cacheados em local JVM). `GuestToHostMapper` ganhou 9 bindings novos (`vfp()`, `s`/`setS`/`d`/`setD` crus + `sFloat`/`setSFloat`/`dDouble`/`setDDouble`). `VfpNativeEquivalenceTest` novo (15 métodos): equivalência exaustiva por grupo (14 condições × cada família, vetores NaN payload/±0.0/subnormal/MIN_VALUE-(-1)/x÷0), property test de 64 floats aleatórios (seed fixa) × todas as 11 `VfpOperation` × single/double, `perOpFallbackOpCount() == 0` num bloco sintético com os 10 kinds, e 14 condições × VCMP+VMRS incl. `APSR_nzcv`. Os `IrOp` são montados à mão (mesmo padrão de `IrVfpExecutorTest`) em vez de decodificados — `ARMV7A` (B3.7) ainda não existe, e `AsmNativePolicy`/o interpretador não gateiam por arquitetura, só o decoder. Suíte arm-jitter 826 core (812+14) + 13 truffle verdes (`mvn -o test`, JBR 25) + `mvn -o install` + gbaemu 240 (`JitInterpreterDivergenceTest` sem divergência em 20M blocos, 17 skipped pré-existentes) + ndsemu 183 verdes — zero regressão. Fecha B3.6 por completo (PR1+PR2); B3.7 (preset `ARMV7A` + armbox torture) segue como próxima task da trilha.
