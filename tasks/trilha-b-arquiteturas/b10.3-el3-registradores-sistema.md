# B10.3 — EL3: registradores de sistema via `MRS`/`MSR`

**Trilha:** B · **Depende de:** B10.1 ✅ · **Repo:** arm-jitter

## Contexto

Terceira task da escada B10 (`b10-plano-el2-el3.md`), paralela à B10.2 (independente entre si —
ambas só dependem de B10.1). B10.1 generalizou `Aarch64ExceptionState` para bancar `SP`/`ELR`/
`SPSR`/`ESR`/`FAR`/`VBAR` nos 4 níveis (`EL1`-`EL3`); B10.2 acrescentou o grupo EL2 (`op1=4`) ao
decoder de `MRS`/`MSR`. Esta task acrescenta o grupo `op1=6` (EL3), mesma disciplina de B10.2:
puramente como armazenamento — SEM side effect funcional (nenhum código roda em EL3 ainda; isso é
`SMC` real, B10.5).

## Inclui

Decodificar e armazenar (leitura devolve exatamente o que foi escrito) os 7 registradores EL3
listados no plano mestre, todos `op0=3,op1=6`:

| Registrador | CRn | CRm | op2 |
|---|---|---|---|
| `SCTLR_EL3` | 1  | 0 | 0 |
| `SCR_EL3`   | 1  | 1 | 0 |
| `CPTR_EL3`  | 1  | 1 | 2 |
| `MDCR_EL3`  | 1  | 3 | 1 |
| `SPSR_EL3`  | 4  | 0 | 0 |
| `ELR_EL3`   | 4  | 0 | 1 |
| `VBAR_EL3`  | 12 | 0 | 0 |

(Mesma disciplina de B10.2: `S3_6_Cn_Cm_op2` é a forma genérica de `MRS`/`MSR` para
`op0:op1:CRn:CRm:op2`; toolchain devkitA64 indisponível nesta sessão também — ver Armadilhas.)

- `Aarch64SystemRegisterId`: 7 constantes novas.
- `Aarch64Decoder#decodeSystemRegisterId`: novo branch `op1 == SYSREG_OP1_EL3` (constante nova,
  `= 6`) ao lado do branch `op1 == SYSREG_OP1_EL2` já existente, delegando a
  `decodeEl3RegisterId(crn, crm, op2)` espelhando `decodeEl2RegisterId`.
- `Aarch64VmsaSystemRegisters`: estende `handles`/`read`/`write` para os 7 registradores novos.
  - `SPSR_EL3`/`ELR_EL3`/`VBAR_EL3`: delegam a `exceptionState.spsr(EL3)`/`.elr(EL3)`/`.vbar(EL3)`
    (já existem desde B10.1 — mesma fonte única já usada pelos pares EL1/EL2).
  - `SCTLR_EL3`/`SCR_EL3`/`MDCR_EL3`/`CPTR_EL3`: campos novos de armazenamento puro (sem side
    effect — nenhum bit liga roteamento de `SMC`/trap ainda, isso é B10.5). `SCTLR_EL3.M` NÃO
    deve ligar nenhuma MMU (stage-1 de EL3 não é modelada por este épico) — mesma cautela já
    aplicada a `SCTLR_EL2` em B10.2.

## Não inclui

- Roteamento real de `SMC`/IRQ/abort baseado em `SCR_EL3` — B10.5.
- `ESR_EL3`/`FAR_EL3`: NÃO listados no plano mestre para esta task (diferente de EL2, que incluiu
  `ESR_EL2`/`FAR_EL2`) — não implementar por conta própria; se algum consumidor real precisar
  deles, isso é uma task nova (não expandir escopo aqui sem o usuário decidir).
- Registradores EL2 (`HCR_EL2`, ...) — B10.2, já fechada.
- `AT`, registradores de debug, `TLBI` EL3 — demais tasks da escada.

## Validação

- Teste novo cobrindo os 7 registradores: `MSR`/`MRS` round-trip via decoder (mesmo estilo de
  `Aarch64El2SystemRegisterDecoderTest`), valor arbitrário não-trivial.
- `SPSR_EL3`/`ELR_EL3`/`VBAR_EL3` independentes dos seus pares EL1/EL2 (escrever um não deve mudar
  os outros — já é verdade por construção via o array banked de B10.1, precisa de teste que prove).
- `mvn -o test` verde no `core`. `mvn -o install` local.
- **G5**: gbaemu, ndsemu, virtual-arm-box (único consumidor A64), n3dsemu, armbox (40/41
  pré-existente, ver B10.1).
- Sem mudança de comportamento observável em nenhum consumidor hoje — mudança puramente aditiva
  (G3).

## Armadilhas

- `op0` continua `3` (mesma observação de B10.2 — `op0=2` é o grupo de debug real do hardware,
  mas este projeto já trata `MDCR_EL2`/`MDCR_EL3` como `op0=3` por precedente de B10.2, não
  reabrir essa decisão aqui).
- Toolchain devkitA64 indisponível nesta sessão também (mesma situação de B10.2) — encodings
  derivados por FÓRMULA (`0xD5000000 | L<<21 | op0<<19 | op1<<16 | CRn<<12 | CRm<<8 | op2<<5 | Rt`),
  conferida contra os opcodes já existentes no repo (`SCTLR_EL2`/`HCR_EL2`/... de B10.2) antes de
  gerar os valores novos. Pendência: regenerar via toolchain real quando disponível, mesma nota já
  registrada em B10.2.

## Resultado

`ELR_EL3`/`VBAR_EL3`) decodificados (`Aarch64Decoder`, novo branch `op1==6` ao lado do `op1==4` de
B10.2) e armazenados (`Aarch64VmsaSystemRegisters` estendido — `SPSR_EL3`/`ELR_EL3`/`VBAR_EL3`

`Aarch64El2SystemRegisterDecoderTest`), `Aarch64VmsaSystemRegistersTest#el3StorageOnlyRegistersRoundTrip`/
