# B6.3.2 — AArch64: seleção condicional (CSEL family) + bitfield (UBFM/SBFM/BFM)

**Trilha:** B · **Depende de:** B6.3.1 (reaproveita o dispatch novo
`decodeDataProcessingRegister`/`isDataProcessingRegisterClass` — ver D1 de
B6.3.1; sem ele, `CSEL` não tem onde ser adicionado) · **Repo:** arm-jitter

## Contexto

Segunda sub-task da decomposição de B6.3 (ver `b6-aarch64.md` e o registro de
decomposição no início de B6.3.1). Agrupamento escolhido: **`CSEL`/`CSINC`/
`CSINV`/`CSNEG`** (seleção condicional — a única família de A64 que consome
uma condição de 4 bits fora de `B.cond`) **junto com `UBFM`/`SBFM`/`BFM`**
(extração/inserção de campo de bits). Motivo de agrupar os dois: nenhum dos
dois precisa de infraestrutura nova além do que B6.3.1 já criou (`CSEL` usa
o dispatch de "Data Processing — Register"; bitfield é só mais um `case` no
`decodeDataProcessingImmediate` que já existe desde B6.1) — são dois
encodings de tamanho pequeno/médio, sem risco comparável ao `DecodeBitMasks`
de B6.3.1 nem à complexidade de estado do monitor de exclusividade de
B6.3.4, então cabem juntos numa task de porte médio.

**Achado importante desta rodada de pesquisa, que muda a spec**: as ~11
mnemônicas de alias listadas no escopo do épico (`UBFX`/`SBFX`/`BFI`/
`BFXIL`/`LSL(imm)`/`LSR(imm)`/`ASR(imm)`/`UXTB`/`UXTH`/`SXTB`/`SXTH`/`SXTW`)
**não exigem NENHUM decode adicional** — são todas o MESMO encoding de
`UBFM`/`SBFM`/`BFM` com valores específicos de `immr`/`imms`, resolvidos só
pelo assembler na hora de escrever o mnemônico "bonito" (ver Fatos de
referência #2). O decoder só precisa produzir um `Ir64Op.Bitfield` genérico;
o EXECUTOR (não um decode alternativo) implementa a lógica de extração/
inserção que cobre todos os aliases de uma vez, com o mesmo algoritmo de
`immr`/`imms` usado pela forma canônica.

## Fatos de referência (fontes: `ARM DDI 0487` C6.2 + QEMU
`target/arm/tcg/a64.decode`/`translate-a64.c`, HEAD do master 2026-07-24)

1. **`Conditional select`** (`a64.decode`):
   ```
   CSEL   sf:1 else_inv:1 011010100 rm:5 cond:4 0 else_inc:1 rn:5 rd:5
   ```
   Um ÚNICO padrão de decode cobre as 4 mnemônicas — `CSEL`/`CSINC`/`CSINV`/
   `CSNEG` são distinguidas só pelos bits `else_inv`(30)/`else_inc`(10):
   `00`=CSEL, `01`=CSINC, `10`=CSINV, `11`=CSNEG (confirmado em
   `translate-a64.c:9468-9499`, função `trans_CSEL`):
   ```c
   static bool trans_CSEL(DisasContext *s, arg_CSEL *a)
   {
       TCGv_i64 tcg_rd = cpu_reg(s, a->rd);
       TCGv_i64 zero = tcg_constant_i64(0);
       DisasCompare64 c;
       a64_test_cc(&c, a->cond);

       if (a->rn == 31 && a->rm == 31 && (a->else_inc ^ a->else_inv)) {
           /* CSET & CSETM. */
           if (a->else_inv) {
               tcg_gen_negsetcond_i64(tcg_invert_cond(c.cond), tcg_rd, c.value, zero);
           } else {
               tcg_gen_setcond_i64(tcg_invert_cond(c.cond), tcg_rd, c.value, zero);
           }
       } else {
           TCGv_i64 t_true = cpu_reg(s, a->rn);
           TCGv_i64 t_false = read_cpu_reg(s, a->rm, 1);
           if (a->else_inv && a->else_inc) {
               tcg_gen_neg_i64(t_false, t_false);
           } else if (a->else_inv) {
               tcg_gen_not_i64(t_false, t_false);
           } else if (a->else_inc) {
               tcg_gen_addi_i64(t_false, t_false, 1);
           }
           tcg_gen_movcond_i64(c.cond, tcg_rd, c.value, zero, t_true, t_false);
       }
       if (!a->sf) {
           tcg_gen_ext32u_i64(tcg_rd, tcg_rd);
       }
       return true;
   }
   ```
   **Semântica geral (equivalente ao pseudocódigo do manual, `ARM DDI 0487
   C6.2.34-37`)**: se a condição é verdadeira, `Rd = Rn`; senão, `Rd =
   f(Rm)` onde `f` é identidade (CSEL), `+1` (CSINC), `~Rm` (CSINV), ou
   `-Rm` (CSNEG). **Nunca afeta NZCV** (só LÊ os flags para avaliar a
   condição — diferente de `Alu64`/`AluShiftedRegister` com `setFlags`).
   **`Rd` NUNCA é `SP`** (`cpu_reg`, nunca `cpu_reg_sp`); `Rn`/`Rm` também
   nunca `SP` — todos os 3 registradores são normais (`31`=`XZR`).
   **Aliases `CSET`/`CSETM`/`CINC`/`CINV`/`CNEG`** (`ARM DDI 0487 C6.2`,
   tabela de aliases): `CSET Rd,cond` = `CSINC Rd,XZR,XZR,invert(cond)`;
   `CSETM Rd,cond` = `CSINV Rd,XZR,XZR,invert(cond)`; `CINC
   Rd,Rn,cond`=`CSINC Rd,Rn,Rn,invert(cond)`; `CINV`/`CNEG` análogos com
   `CSINV`/`CSNEG`. **Todos são só convenção de escrita do assembler** — o
   encoding decodificado é idêntico a `CSINC`/`CSINV`/`CSNEG` com `Rn==Rm`
   (caso geral) ou `Rn==Rm==31` (CSET/CSETM, caso especial só porque aí a
   condição do usuário já vem pré-invertida pelo assembler — o hardware não
   faz nada diferente). **Nenhum decode extra necessário** — o `Ir64Op`
   novo cobre os 4 opcodes reais (`CSEL`/`CSINC`/`CSINV`/`CSNEG`), e os 5
   aliases são só como o corpus de teste vai nomear os vetores (o objdump
   real do devkitA64 provavelmente imprime `cset`/`csinc` etc. quando
   aplicável — ver Armadilhas sobre golden file por campo, não por
   mnemônico).

2. **`Bitfield`** (`a64.decode`):
   ```
   &bitfield       rd rn sf immr imms
   @bitfield_64    1 .. ...... 1 immr:6 imms:6 rn:5 rd:5      &bitfield sf=1
   @bitfield_32    0 .. ...... 0 0 immr:5 0 imms:5 rn:5 rd:5  &bitfield sf=0

   SBFM   . 00 100110 . ...... ...... ..... ..... @bitfield_64/@bitfield_32
   BFM    . 01 100110 . ...... ...... ..... ..... @bitfield_64/@bitfield_32
   UBFM   . 10 100110 . ...... ...... ..... ..... @bitfield_64/@bitfield_32
   ```
   `opc` (2 bits, bits30:29): `00`=SBFM, `01`=BFM, `10`=UBFM (`11` reservado
   — mesmo espaço de bits de `Extract`/`EXTR`, que é opc=`11`+`N=1` só na
   forma 64-bit; **`EXTR` NÃO está no escopo fechado do épico, ver
   Armadilhas**). Este é o subgrupo `10` (`SUBGROUP_24_23`) de
   `decodeDataProcessingImmediate`, que hoje lança `unsupported` para `10`/
   `11` (`Aarch64Decoder.java:395-396`).
   **Algoritmos de execução, transcritos de `translate-a64.c:5362-5461`**
   (`trans_SBFM`/`trans_UBFM`/`trans_BFM` — `bitsize` = 32 ou 64 conforme
   `sf`; `ri=immr`, `si=imms`):
   ```c
   // SBFM (trans_SBFM):
   if (si >= ri) {
       // Rd<s-r:0> = Rn<s:r>, sign-extended
       len = (si - ri) + 1;
       Rd = sextract(Rn, ri, len);       // + zero-extend para 64 se !sf
   } else {
       // Rd<32+s-r : 32-r> = Rn<s:0>, resto sign-extended a partir do MSB copiado
       len = si + 1;
       pos = (bitsize - ri) & (bitsize - 1);
       if (len < ri) {
           tmp = sextract(Rn, 0, len);   // estende o campo antes de depositar
           len = ri;
       }
       Rd = deposit_zero(tmp_ou_Rn, pos, len);  // resto = 0
   }

   // UBFM (trans_UBFM): igual, mas SEM sign-extend nenhum passo —
   // extract()/deposit_zero() puros (zero-extend implícito).
   if (si >= ri) {
       len = (si - ri) + 1;
       Rd = extract(Rn, ri, len);        // zero-estendido
   } else {
       len = si + 1;
       pos = (bitsize - ri) & (bitsize - 1);
       Rd = deposit_zero(Rn, pos, len);  // resto = 0
   }

   // BFM (trans_BFM): como UBFM, mas DEPOSITA sobre o Rd EXISTENTE
   // (preserva os bits fora do campo, não zera o resto):
   if (si >= ri) {
       tmp = Rn >> ri;
       len = (si - ri) + 1; pos = 0;
   } else {
       len = si + 1;
       pos = (bitsize - ri) & (bitsize - 1);
       tmp = Rn;  // (sem shift — o campo de origem já começa em bit 0)
   }
   Rd = deposit(Rd, tmp, pos, len);   // preserva Rd fora de [pos, pos+len)
   ```
   **Ponto crítico para o executor**: os três (`SBFM`/`UBFM`/`BFM`) têm a
   MESMA divisão de casos (`si>=ri` vs `si<ri`) e os MESMOS `len`/`pos`
   derivados — só o que acontece com os bits FORA do campo copiado muda
   (`SBFM`=estende sinal do bit mais alto copiado; `UBFM`=zera; `BFM`=
   preserva o `Rd` anterior). Isso favorece uma implementação com um
   `switch` pequeno sobre a "política de preenchimento" no fim, não três
   blocos de código separados.
   **Aliases (`ARM DDI 0487 C6.2`, tabela de aliases de bitfield — todos
   sem decode extra, só valores específicos de `immr`/`imms`)**:
   - `LSL Rd,Rn,#shift` = `UBFM Rd,Rn,#(-shift MOD size),#(size-shift-1)`.
   - `LSR Rd,Rn,#shift` = `UBFM Rd,Rn,#shift,#(size-1)`.
   - `ASR Rd,Rn,#shift` = `SBFM Rd,Rn,#shift,#(size-1)`.
   - `UBFX Rd,Rn,#lsb,#width` = `UBFM Rd,Rn,#lsb,#(lsb+width-1)`.
   - `SBFX` análogo com `SBFM`.
   - `BFI Rd,Rn,#lsb,#width` = `BFM Rd,Rn,#(-lsb MOD size),#(width-1)`.
   - `BFXIL Rd,Rn,#lsb,#width` = `BFM Rd,Rn,#lsb,#(lsb+width-1)`.
   - `UXTB`/`UXTH` = `UBFM Rd,Rn,#0,#7`/`#0,#15` (só forma 32-bit).
   - `SXTB`/`SXTH`/`SXTW` = `SBFM Rd,Rn,#0,#7`/`#0,#15`/`#0,#31`.
   **Nenhuma dessas precisa de um `case` de decode dedicado** — o decoder
   produz `Ir64Op.Bitfield` sempre da mesma forma a partir de `opc`/`immr`/
   `imms` crus; a "alias-ness" é só como o texto assembly é impresso.

## Decisões de desenho FECHADAS nesta rodada

### D1 — `Ir64Op.ConditionalSelect` novo

```java
/// `CSEL`/`CSINC`/`CSINV`/`CSNEG` (`ARM DDI 0487 C6.2.34-37`). Nunca afeta
/// NZCV (só lê para avaliar `condition`); `Rd`/`Rn`/`Rm` nunca são `SP`
/// (diferente de `Alu64`/`AluExtendedRegister` — sem campos
/// `dstIsStackPointer` aqui, seriam sempre `false`). Os aliases `CSET`/
/// `CSETM`/`CINC`/`CINV`/`CNEG` (`ARM DDI 0487 C6.2`, tabela de aliases)
/// não têm representação própria — são o MESMO op com `src1==src2` (ou
/// `==XZR`) e a condição já invertida pelo assembler; nada no IR precisa
/// saber disso.
record ConditionalSelect(
        Ir64ConditionalSelectOp opcode,  // CSEL/CSINC/CSINV/CSNEG (enum novo)
        int dst, int src1, int src2,
        boolean wide,
        Ir64Condition condition) implements Ir64Op { ... }
```
Execução (mesma lógica de `trans_CSEL`, sem o atalho `CSET`/`CSETM` — esse
atalho é só uma OTIMIZAÇÃO de codegen do QEMU, o interpretador não precisa
dele): avaliar `condition` via `PstateRegister.evalCond`; se verdadeira,
`dst=src1`; senão, `dst = f(src2)` conforme `opcode` (`CSEL`→identidade,
`CSINC`→`+1`, `CSINV`→`~`, `CSNEG`→`-`, todos na largura `wide`/`!wide`,
com zero-extensão para os 32 bits altos quando `!wide` — mesma disciplina
de qualquer resultado `W` já estabelecida em B6.1 (`setXForWidth`).

### D2 — `Ir64Op.Bitfield` novo, um record cobre os 3 opcodes

```java
/// `SBFM`/`BFM`/`UBFM` (`ARM DDI 0487 C6.2.309/29/369` — verificar números
/// exatos de seção ao implementar). Todos os aliases de bitfield (`UBFX`/
/// `SBFX`/`BFI`/`BFXIL`/`LSL`/`LSR`/`ASR`/`UXTB`/`UXTH`/`SXTB`/`SXTH`/
/// `SXTW`, ver Fatos de referência #2) são o MESMO encoding com valores
/// específicos de `immr`/`imms` — o decoder NUNCA precisa reconhecer o
/// alias, só produzir este record a partir dos campos crus.
record Bitfield(
        Ir64BitfieldOp opcode,   // SBFM/BFM/UBFM (enum novo)
        int dst, int src,
        int immr, int imms,      // campos CRUS do encoding, sem pré-cálculo
        boolean wide) implements Ir64Op { ... }
```
**Decisão explícita: `immr`/`imms` ficam CRUS no IR** (não pré-calculados
em `pos`/`len` pelo decoder) — motivo: o cálculo de `pos`/`len` depende de
`bitsize` (32 vs 64), que já está disponível via `wide` no executor, e os
casos `si>=ri`/`si<ri` são mais claros de auditar contra o pseudocódigo do
manual/QEMU citado acima se o executor trabalhar com os MESMOS nomes de
campo (`immr`/`imms`) que a fonte usa, em vez de uma forma já transformada
que exigiria reconstruir a correspondência na hora de debugar uma
divergência. Mesmo princípio já seguido por `Load64`/`Store64`
(`immediate` "já normalizado" quando cabe, mas aqui a normalização en
verdade dificultaria a auditoria — julgamento registrado, não uma regra
geral).

## Objetivo

- `CSEL`/`CSINC`/`CSINV`/`CSNEG` (com os aliases `CSET`/`CSETM`/`CINC`/
  `CINV`/`CNEG` cobertos de graça, D1).
- `SBFM`/`UBFM`/`BFM` (com os 11 aliases citados cobertos de graça, D2).

## Especificação

1. Novo `case` em `decodeDataProcessingRegister` (criado por B6.3.1) para o
   padrão fixo de `CSEL` (`sf . 011010100 rm cond 0 else_inc rn rd`) →
   `Ir64Op.ConditionalSelect`.
2. Novo `case 0b10` (`SUBGROUP_BITFIELD`) em `decodeDataProcessingImmediate`
   (já existe desde B6.1, só falta o `case`) → `Ir64Op.Bitfield`, com `opc`
   (bits30:29) mapeado para `Ir64BitfieldOp.SBFM/BFM/UBFM`; `opc==0b11`
   continua `unsupported` (é `EXTR`, fora de escopo — ver Armadilhas).
3. Executores novos em `Ir64BlockExecutor`: `executeConditionalSelect` (D1)
   e `executeBitfield` (D2, com a política de preenchimento — sign/zero/
   preserve — compartilhando o cálculo de `len`/`pos`).
4. Corpus: apêndice com pelo menos um vetor por opcode real (`CSEL`,
   `CSINC`, `CSINV`, `CSNEG`, `SBFM`, `BFM`, `UBFM`) e um vetor por alias
   citado na lista do épico (para provar que o objdump real reconhece o
   alias E que o decoder produz os campos corretos por baixo — o teste
   verifica os CAMPOS, não o texto do mnemônico).

## Testes mínimos

- `CSEL`/`CSINC`/`CSINV`/`CSNEG`: condição verdadeira → `dst=src1`;
  condição falsa → `dst=f(src2)` para os 4 `f` (identidade/+1/~/-`);
  confirmar NZCV **inalterado** em todos os casos (a leitura da condição
  não pode ter efeito colateral); `wide=false` zera os 32 bits altos do
  resultado.
  - Caso especial `+1`/`~`/`-` com `src2=XZR`: `CSINC` dá `1`, `CSINV` dá
    `-1` (todos os bits setados), `CSNEG` dá `0` (negação de zero) —
    vetores explícitos, é fácil inverter a lógica sem perceber num desses
    três.
- `CSET`/`CSETM`/`CINC`/`CINV`/`CNEG` do corpus real: decodificados como o
  `ConditionalSelect` genérico esperado (campos batendo com o padrão
  `CSINC`/`CSINV`/`CSNEG` com `src1==src2`), executando para o resultado
  correto do alias.
- `SBFM`/`UBFM`/`BFM`: pelo menos um vetor por ramo (`si>=ri` e `si<ri`) por
  opcode = 6 combinações mínimas; `BFM` confirmando que os bits FORA do
  campo em `Rd` são PRESERVADOS (não zerados) — teste que pré-popula `Rd`
  com um valor não-trivial antes de rodar o `BFM`.
- Aliases do corpus real (`LSL`/`LSR`/`ASR`/`UBFX`/`SBFX`/`BFI`/`BFXIL`/
  `UXTB`/`UXTH`/`SXTB`/`SXTH`/`SXTW`): cada um decodificado para os campos
  `immr`/`imms` exatos que o assembler produziu (golden file), e o
  RESULTADO da execução batendo com a semântica "amigável" do alias (ex.
  `SXTB x0, w1` de fato estende sinal de 8 para 64 bits) — prova indireta
  de que o executor genérico está certo sem precisar de código especial
  por alias.
- `opc==0b11` (`EXTR`, fora de escopo): `UnsupportedOperationException`.
- Regressão: suíte completa de B6.1/B6.2/B6.3.1 sem mudança de
  comportamento.

## Armadilhas

- **`EXTR` (e seu alias `ROR Rd,Rs,#shift` quando `Rn==Rm`) NÃO está no
  escopo fechado do épico** (`b6-aarch64.md` lista "bitfield UBFM/SBFM/BFM
  + aliases" — `EXTR` é uma família de encoding IRMÃ (mesmo subgrupo `11`
  de `SUBGROUP_24_23`), mas não é bitfield nem está citada). **Não
  implementar por conta própria** mesmo sendo tentador (o `case` já existe
  ao lado); registrar como pendência para spec futura se necessário.
- **`CSET`/`CSETM`/etc. não precisam de tratamento especial no executor**
  — a tentação (inspirada no atalho `tcg_gen_negsetcond_i64` do QEMU, que é
  só uma otimização de CODEGEN) é reconhecer `Rn==Rm==31` e ter um caminho
  separado; o interpretador não precisa disso, `CSINC XZR,XZR,cond` com
  `f(XZR)=XZR+1=1` já dá o resultado certo pelo caminho geral. Adicionar um
  atalho aqui seria código morto arriscado (dois caminhos calculando a
  mesma coisa, divergência futura).
- **`BFM` preserva bits fora do campo — `SBFM`/`UBFM` NÃO preservam** (
  zeram ou estendem sinal, respectivamente). É o erro mais fácil de cometer
  copiando código entre os três branches do executor — o teste dedicado de
  `BFM` com `Rd` pré-populado (Testes mínimos) existe exatamente para pegar
  essa troca.
- **Golden file por CAMPO, não por mnemônico**: o `objdump` real vai
  imprimir `cset`/`lsl`/`uxtb`/etc. para os alias — o teste deve comparar os
  CAMPOS decodificados (`opcode`/`immr`/`imms`/registradores), não o texto
  do mnemônico impresso (que pode variar entre versões do binutils/GNU as
  sem que o encoding mude).
- **Pin de versão QEMU**: mesma ressalva de B6.3.1 (fontes lidas do HEAD do
  master em 2026-07-24).
- **B6.2 aceite #2 (busybox aarch64) segue bloqueado no usuário** — mesma
  nota de B6.3.1, não bloqueia esta task.
