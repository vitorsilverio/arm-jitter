# B8.19 — A64 AdvSIMD "vector/scalar × indexed element"

**Trilha:** B · **Depende de:** B8.7 ✅ (`Ir64VectorThreeSameOp`/`Ir64VectorWideningOp`), B8.9 ✅
(`Ir64VectorFpThreeSameOp`) · **Repo:** arm-jitter

## Contexto

Candidata registrada pelo `B8.18` (`b8.18-a64-advsimd-logico-two-register-misc-restante.md`) e
priorizada pelo usuário em 2026-08-27 entre três opções (`B8.19`/`REV16-32-64_v`/
`XTN-SHLL-URECPE-URSQRTE_v`) — a maior das três (~50 lacunas em `docs/COBERTURA-ISA.md`), classe de
encoding própria nunca examinada por nenhuma task anterior da escada AdvSIMD (B8.6-B8.18 cobriram
"three same"/"three different"/"two-register misc"/"shift by immediate"/"permute"/"copy"/Crypto,
nunca "× indexed element").

Triagem real contra `a64.decode` do QEMU (`curl` direto, mesmo método de B8.11b/B9.7): a família
"AdvSIMD {scalar,vector} × indexed element" compartilha o MESMO prefixo de 5 bits
(`bits[28:24]`="01111" vetorial/"11111" escalar) de "shift by immediate" (B8.8) — discriminados só
por `bit10` (`1`=shift, `0`=indexed-element). Dentro dela, um campo `size` de 2 bits (`bits[23:22]`,
MESMA posição do `esz` de "three same") escolhe halfword(`01`, só inteiro)/word(`10`, inteiro E
ponto flutuante, discriminados por `opcode`+`U`)/doubleword(`11`, só ponto flutuante). O índice do
elemento de `Rm` vem de bits espalhados (`H`=bit11 sempre; `L`=bit21; `M`=bit20, só halfword —
também estreita `Rm` a `V0`-`V15`).

**Escopo desta task: só ARMv8.0/Cortex-A53.** Das ~50 lacunas do medidor, ficam de fora (posteriores
ao Cortex-A53, ver "Não inclui"): meia-precisão (`FEAT_FP16`), `SQRDMLAH`/`SQRDMLSH` (`FEAT_RDM`),
`SDOT`/`UDOT`/`SUDOT`/`USDOT`/`BFDOT` (`FEAT_DotProd`/`FEAT_BF16`), `FMLAL`/`FMLSL`/`FMLAL2`/
`FMLSL2`/`BFMLAL` (`FEAT_FHM`/`FEAT_BF16`), `FCMLA` (`FEAT_FCMA`). Documentar cada uma em
`docs/isa-nao-aplicavel.tsv` com a feature real que introduz, nunca como "fora do nosso alvo" (regra
máxima do `tasks/README.md`).

Também fica de fora (achado durante a triagem, categoria DIFERENTE — não é "× indexed element"):
`SQDMULL`/`SQDMLAL`/`SQDMLSL` ESCALARES SEM índice (dois registradores reais, ex.
`sqdmull s0, h1, h2`) — vivem no prefixo "three different" ESCALAR (`bits[28:24]`="11110",
`bit21=1`, `bit10=0`), que `decodeAdvancedSimdInteger` hoje recusa incondicionalmente para
`scalar=true` (`throw unsupported` antes de checar o opcode). QEMU internamente as trata como um
alias de "scalar × indexed, index=0" só para reuso de código do PRÓPRIO tradutor — não é o mesmo
encoding desta task. Candidata a task própria.

## Inclui

- **`Ir64Op`** (`ir64/`): 3 records novos, cada um reaproveitando um enum de operação já existente
  (nenhum `IrOp`/enum novo):
  - `VectorArithmeticThreeSameByElement` (`Ir64VectorThreeSameOp op, boolean scalar, boolean q, int
    esz, int rd, int rn, int rm, int index`) — `MUL`/`MLA`/`MLS`/`SQDMULH`/`SQRDMULH`.
  - `VectorArithmeticWideningByElement` (`Ir64VectorWideningOp op, boolean scalar, boolean q, int
    esz, int rd, int rn, int rm, int index`) — `SMULL`/`UMULL`/`SMLAL`/`UMLAL`/`SMLSL`/`UMLSL`/
    `SQDMULL`/`SQDMLAL`/`SQDMLSL`.
  - `VectorFpArithmeticThreeSameByElement` (`Ir64VectorFpThreeSameOp op, boolean scalar, boolean q,
    int esz, int rd, int rn, int rm, int index`) — `MUL`/`MLA`/`MLS`/`MULX`.
  - 3 `Kind`s novos (`88`-`90`).
- **`Aarch64Decoder`**: desvio novo em `decodeAdvancedSimdInteger` (MESMO prefixo de "shift by
  immediate", `bit10=0`) para `decodeAdvancedSimdIndexedElement`, que lê `size`/índice/`Rm`
  (restrito a 4 bits em halfword) e despacha para `decodeAdvancedSimdIndexedFp`/
  `decodeAdvancedSimdIndexedInt` (tabelas `(U,opcode)`→enum, `null` se não bater — G8 lança no
  chamador).
- **`Ir64VectorArithmeticExecutor`/`Ir64VectorFpArithmeticExecutor`**: `executeThreeSameByElement`/
  `executeWideningByElement` (inteiro) e `executeThreeSameByElement` (FP) — MESMA lógica por
  elemento dos executores irmãos (`executeThreeSame`/`executeWidening`/`executeThreeSame` FP), só
  que `Rm` é lido UMA VEZ fora do laço, sempre no elemento `index` (replicado), nunca
  `fp.element(op.rm(), i, esz)`.

## Não inclui

- Meia-precisão/`SQRDMLAH`/`SQRDMLSH`/dot-product/`FMLAL`-família/`FCMLA` — ver "Contexto" (posteriores
  ao Cortex-A53, `docs/isa-nao-aplicavel.tsv`).
- `SQDMULL`/`SQDMLAL`/`SQDMLSL` escalares SEM índice (dois registradores) — categoria diferente
  ("three different" escalar), ver "Contexto".
- `REV16_v`/`REV32_v`/`REV64_v`, `XTN`/`SHLL_v`/`URECPE_v`/`URSQRTE_v` — candidatas próprias já
  registradas por `B8.18`, não relacionadas a esta task.
- Emissão ASM nativa — mesma decisão de todo `Kind` de AdvSIMD desde B8.6 (cai no interpretado).

## Armadilhas

- O prefixo de 5 bits (`bits[28:24]`) é IDÊNTICO ao de "shift by immediate" (B8.8) — só `bit10`
  discrimina (`1`=shift, `0`=indexed-element). Confirmado bit a bit contra `a64.decode` real antes
  de escrever qualquer decode.
- O campo `size` (`bits[23:22]`) NÃO segue a convenção usual de `esz` livre: `00`=meia-precisão
  (fora de escopo), `01`=halfword (só inteiro), `10`=word (inteiro E FP, mesmo valor cru — só o
  `opcode`/`U` desambiguam), `11`=doubleword (só FP, `bit21` fixo em `0` no encoding real).
- Índice de `Rm`: halfword usa `H:L:M` (bits `11`,`21`,`20`, `Rm` restrito a `V0`-`V15`/4 bits);
  word usa `H:L` (bits `11`,`21`, `Rm` livre `V0`-`V31`); doubleword usa só `H` (bit `11`, `Rm`
  livre). NÃO confundir com o `%hl`/`%hlm` do `a64.decode` — a ORDEM de concatenação importa (`H` é
  sempre o bit MAIS significativo do índice).
- `MUL`/`MLA`/`MLS`/`SMULL`/`UMULL`/`SMLAL`/`UMLAL`/`SMLSL`/`UMLSL` NÃO têm forma escalar real —
  `scalar=true` para esses opcodes é UNALLOCATED (G8: `decodeAdvancedSimdIndexedInt` devolve `null`,
  nunca aceita silenciosamente). Só `SQDMULH`/`SQRDMULH`/`SQDMULL`/`SQDMLAL`/`SQDMLSL` (inteiro) e
  `FMUL`/`FMLA`/`FMLS`/`FMULX` (FP) têm as duas formas.
- A forma ESCALAR alargante (`SQDMULL_si`/etc.) produz um ÚNICO elemento largo — diferente de
  `executeWidening` (não-escalar), que SEMPRE preenche os 128 bits inteiros independente de `Rd`
  anterior. Reaproveita `finishScalarAwareWrite` (B8.8) para a escrita destrutiva ciente de tamanho.
