# B1.3 — SIMD paralelo ARMv6, flags GE, saturação e USAD8/PKH

**Trilha:** B · **Depende de:** B1.1 · **Repo:** arm-jitter
**Nota:** grande — pode ser dividida em 2 PRs (PR1: GE flags + add/sub paralelo;
PR2: SEL/USAD8/PKH/SSAT/USAT).

## Contexto

O bloco "media instructions" do ARMv6: aritmética paralela em lanes de 8/16 bits.
Introduz estado NOVO no CPSR: os bits **GE[3:0]** (bits 19:16), gravados pelas
variantes signed/unsigned básicas e lidos por `SEL`. Também usa o flag Q (bit 27),
que JÁ existe desde o ARMv5TE saturating — verificar como `QADD` o seta hoje e reusar.

## Objetivo

Decodificar/liftar/interpretar (ASM nativo é B1.6):

- Paralelas de 16 bits: `SADD16 SSUB16 SASX SSAX` + variantes `Q* SH* U* UQ* UH*`
- Paralelas de 8 bits: `SADD8 SSUB8` + `Q* SH* U* UQ* UH*`
- `SEL` (seleciona bytes por GE)
- `USAD8`, `USADA8` (soma de diferenças absolutas)
- `PKHBT`, `PKHTB` (pack halfword)
- `SSAT`, `USAT`, `SSAT16`, `USAT16` (saturação — setam Q)

## Especificação

1. **CPSR GE:** adicionar get/set dos bits 19:16 em `core/Cpsr` (ou classe equivalente
   — ler `core/` primeiro), com constantes nomeadas (G6). `MSR` com máscara de campo
   `s` (status, bits 23:16) deve passar a escrever GE **apenas quando o feature
   `PARALLEL_SIMD` existe**; no ARMv4T/v5TE o comportamento atual de MSR não muda um
   bit (testar isso explicitamente).
2. **Semântica das variantes** (prefixos): sem prefixo = wrap + escreve GE;
   `Q` = saturado, NÃO escreve GE; `SH`/`UH` = halving (resultado >>1), NÃO escreve GE;
   `U` = unsigned + escreve GE com regra de carry unsigned; `UQ` = saturado unsigned.
   Regra GE exata (signed: resultado >= 0 por lane; unsigned: carry por lane) —
   confirmar no DDI 0100I, é o ponto mais fácil de errar do ARMv6 inteiro.
3. **IR:** novo record `IrOp.ParallelAlu` (opcode enum próprio + largura de lane +
   variante) em vez de inflar `IrOpCode` — espelhar como `IrOp.DspMultiply` (ARMv5TE)
   foi modelado. Executor novo `IrParallelExecutor` ou caso no `IrAluExecutor`
   (decidir lendo como DspMultiply/Saturating são executados hoje e seguir o mesmo lugar).
4. **Testes:** por instrução, vetores com lanes independentes provando isolamento
   (ex.: `SADD16` de `0x7FFF0001 + 0x00010001 = 0x80000002` com GE refletindo lane
   negativa/positiva; `SSAT` além do limite setando Q; `SEL` com GE misto; `USAD8`
   com bytes maiores/menores misturados). Cada grupo com teste de gating no ARMV4T.

## Aceite

- `mvn test` + gbaemu/ndsemu verdes.
- MSR/MRS no ARMv4T/v5TE comprovadamente inalterados (teste de regressão dedicado).

## Armadilhas

- GE tem semântica DIFERENTE para 8 bits (4 bits GE, um por byte) e 16 bits (GE em
  pares: [1:0] e [3:2]) — ler a tabela do manual com atenção.
- `SASX`/`SSAX` cruzam lanes (add numa metade, sub na outra) — os nomes confundem.
- Q flag é "sticky": instruções saturantes só SETAM, nunca limpam.
- Halving (`SH*`/`UH*`) NÃO satura e NÃO seta GE — só desloca o resultado.
