# B16.5 — MVE: gather/scatter, desentrelaçamento (`VLD2`/`VLD4`/`VST2`/`VST4`) e os `dup` incrementais — 15 encodings

**Trilha:** B · **Repo:** arm-jitter (+ revalidação G5) · **Depende de:** B16.3 (⬜)
**Épico:** `b16-plano-mve-helium.md` · **Status:** ⬜ (spec escrita 2026-09-13, ainda não executada)

## Contexto

Quinto degrau da escada B16 (partição normativa na spec da **B16.1**). O épico rotula esta task como
"Load/store com base em `Rn[3:1]` — gather/scatter, 34 encodings". A medição desta rodada de spec
mostra que o rótulo e a contagem vinham de um corte contíguo do arquivo: as 34 linhas do intervalo
que o épico rotulou assim (linhas 412-493) são, na verdade, os `dup` incrementais **mais** 28 linhas
de `VMLADAV`/`VMLALDAV`/reduções — que aqui vão para a **B16.13**. O que realmente é
gather/scatter/desentrelaçamento são as linhas 191-204, **11 linhas**, e o que realmente usa
"base em `Rn[3:1]`" são os 4 `dup` incrementais (linhas 412/413/418/419) — daí as **15** desta task.

### O encoding real (`target/isa-decode/mve.decode` — medido)

Gather/scatter por registrador de offsets (linhas 53, 64-69, 190-198):

```
&vldst_sg qd qm rn size msize os
&vldst_sg_imm qd qm a w imm

# scatter-gather memory size is in bits 6:4
%sg_msize 6:1 4:1

@vldst_sg .... .... .... rn:4 .... ... size:2 ... ... os:1 &vldst_sg \
          qd=%qd qm=%qm msize=%sg_msize

# Qm is in the fields usually labeled Qn
@vldst_sg_imm .... .... a:1 . w:1 . .... .... .... . imm:7 &vldst_sg_imm \
              qd=%qd qm=%qn

# gather loads/scatter stores
VLDR_S_sg        111 0 1100 1 . 01 .... ... 0 111 . .... .... @vldst_sg
VLDR_U_sg        111 1 1100 1 . 01 .... ... 0 111 . .... .... @vldst_sg
VSTR_sg          111 0 1100 1 . 00 .... ... 0 111 . .... .... @vldst_sg

VLDRW_sg_imm     111 1 1101 ... 1 ... 0 ... 1 1110 .... .... @vldst_sg_imm
VLDRD_sg_imm     111 1 1101 ... 1 ... 0 ... 1 1111 .... .... @vldst_sg_imm
VSTRW_sg_imm     111 1 1101 ... 0 ... 0 ... 1 1110 .... .... @vldst_sg_imm
VSTRD_sg_imm     111 1 1101 ... 0 ... 0 ... 1 1111 .... .... @vldst_sg_imm
```

Desentrelaçamento (linhas 71-73, 200-204):

```
# Deinterleaving load/interleaving store
@vldst_il .... .... .. w:1 . rn:4 .... ... size:2 pat:2 ..... &vldst_il qd=%qd

VLD2             1111 1100 1 .. 1 .... ... 1 111 .. .. 00000 @vldst_il
VLD4             1111 1100 1 .. 1 .... ... 1 111 .. .. 00001 @vldst_il
VST2             1111 1100 1 .. 0 .... ... 1 111 .. .. 00000 @vldst_il
VST4             1111 1100 1 .. 0 .... ... 1 111 .. .. 00001 @vldst_il
```

`dup` incrementais/decrementais (linhas 397-419) — **a origem literal do rótulo "base em `Rn[3:1]`"
do épico**:

```
# VIDUP, VDDUP format immediate: 1 << (immh:imml)
%imm_vidup 7:1 0:1 !function=vidup_imm

# VIDUP, VDDUP registers: Rm bits [3:1] from insn, bit 0 is 1;
# Rn bits [3:1] from insn, bit 0 is 0
%vidup_rm 1:3 !function=times_2_plus_1
%vidup_rn 17:3 !function=times_2

@vidup   .... .... . . size:2 .... .... .... .... .... qd=%qd imm=%imm_vidup rn=%vidup_rn &vidup
@viwdup  .... .... . . size:2 .... .... .... .... .... qd=%qd imm=%imm_vidup rm=%vidup_rm rn=%vidup_rn &viwdup
{
  VIDUP          1110 1110 0 . .. ... 1 ... 0 1111 . 110 111 . @vidup
  VIWDUP         1110 1110 0 . .. ... 1 ... 0 1111 . 110 ... . @viwdup
}
{
  VCMPGT_fp_scalar 1110 1110 0 . 11 ... 1 ... 1 1111  0110 .... @vcmp_fp_scalar size=2   # B16.8
  VCMPLE_fp_scalar 1110 1110 0 . 11 ... 1 ... 1 1111  1110 .... @vcmp_fp_scalar size=2   # B16.8
  VDDUP            1110 1110 0 . .. ... 1 ... 1 1111 . 110 111 . @vidup
  VDWDUP           1110 1110 0 . .. ... 1 ... 1 1111 . 110 ... . @viwdup
}
```

`%vidup_rn 17:3 !function=times_2` = "`Rn` = bits[19:17] × 2" (bit 0 sempre 0 → só registradores
PARES); `%vidup_rm 1:3 !function=times_2_plus_1` = "`Rm` = bits[3:1] × 2 + 1" (só ÍMPARES). É uma
restrição real do encoding, não conveniência do QEMU.

### Regras confirmadas contra o QEMU (`translate-mve.c`, via `WebFetch` nesta rodada)

- `mve_check_qreg_bank(qmask)` → `qmask < 8` (vale para `Qd` **e** `Qm`).
- "Many instructions check `qd == qm` or `qd == qn` are incompatible (e.g. VQDMULLB, **scatter-gather
  loads**)" — nas formas gather de offsets, `Qd == Qm` é UNDEF (o registrador de offsets seria
  sobrescrito no meio da operação, o que a arquitetura não define).
- `Rn == 15` / `Rn == 13 && w` UNDEF (mesma regra da B16.3).

## Objetivo

As 15 linhas decodificam sob `ArmFeature.MVE_INTEGER` e executam: gather por vetor de offsets
(com/sem sinal, com `os` = offset escalado), gather/scatter com imediato e base vetorial
(`*_sg_imm`, incluindo as formas de 64 bits `VLDRD`/`VSTRD`), load/store com desentrelaçamento de 2
e 4 vias, e os quatro geradores de vetor incremental/decremental (`VIDUP`/`VDDUP`/`VIWDUP`/
`VDWDUP`). 15 células `·`/`❌` → `✅`.

## Inclui

1. **Decode das 3 formas gather/scatter por offsets** (`VLDR_S_sg`/`VLDR_U_sg`/`VSTR_sg`):
   `rn:4`, `%qd`, `%qm`, `size:2` (tamanho do elemento no registrador), `%sg_msize 6:1 4:1`
   (tamanho em memória), `os:1` (offset escalado pelo tamanho). Recusas: `Qd>7`/`Qm>7`, `Qd==Qm`,
   `Rn==15`, `msize > size` (alargar num gather de offsets — **confirmar contra o QEMU** se é UNDEF
   ou válido), `size==3` conforme o manual.
2. **Decode das 4 formas `*_sg_imm`** (`VLDRW`/`VLDRD`/`VSTRW`/`VSTRD`): base é um VETOR (`qm=%qn`,
   note o comentário "Qm is in the fields usually labeled Qn" — **não** trocar), `a:1`/`w:1`
   (add/writeback **no registrador vetorial de base**), `imm:7`. As formas `D` transferem 64 bits
   por lane.
3. **Decode de `VLD2`/`VLD4`/`VST2`/`VST4`**: `@vldst_il` com `rn:4`, `%qd`, `size:2`, `pat:2`
   (qual "pedaço" do grupo de registradores esta instrução move — `VLD2` usa 2 padrões, `VLD4` usa
   4) e `w:1`. **`Qd` é a BASE de um grupo de 2 ou 4 registradores consecutivos** (`Qd..Qd+1` /
   `Qd..Qd+3`), logo `Qd+n > 7` é UNDEF.
4. **Decode de `VIDUP`/`VDDUP`/`VIWDUP`/`VDWDUP`** com `%vidup_rn`/`%vidup_rm` (pares/ímpares) e
   `%imm_vidup` (`1 << (immh:imml)`, ou seja o passo é 1/2/4/8 — **confirmar `vidup_imm` no QEMU**).
5. **Execução** de tudo acima, predicada por elemento (máscara da B16.2) + avanço do `VPT`/`ECI`.
6. Testes (ver Aceite).

## Não inclui

- `VLDR_VSTR` (B16.3) e as formas alargantes (B16.4).
- **`VCMPGT_fp_scalar`/`VCMPLE_fp_scalar`** (linhas 416-417) — dividem o bloco `{}` com
  `VDDUP`/`VDWDUP` mas são **B16.8**. Excluí-los explicitamente do decoder desta task (ver
  Armadilha 4).
- Emissão nativa/Truffle.

## Aceite

- As 15 linhas decodificam sob `MVE_INTEGER`; `Qd==Qm` (gather de offsets), `Qd+n>7` (`VLD2`/
  `VLD4`), `Rn==15`, `Qd>7`/`Qm>7` e `Rn` ímpar / `Rm` par nos `dup` são recusados (G8).
- Gather: um vetor de offsets `Qm` produz 4 acessos independentes (testado com offsets fora de
  ordem, para provar que não é um acesso contíguo disfarçado), com `VLDR_S_sg` estendendo sinal e
  `VLDR_U_sg` estendendo zero quando `msize < size`.
- `os=1` escala o offset pelo tamanho do elemento; `os=0` não.
- `*_sg_imm`: a base é o VETOR `Qm` (extraído do campo normalmente chamado `Qn`), e o writeback
  (`w=1`) atualiza esse vetor.
- `VLD2`/`VLD4` desentrelaçam de fato: gravar um padrão conhecido em memória e conferir a
  distribuição pelos 2/4 registradores do grupo; `VST2`/`VST4` fazem o inverso (round-trip).
- `VIDUP`/`VDDUP` produzem `Rn, Rn±passo, Rn±2·passo, ...` e atualizam `Rn`; `VIWDUP`/`VDWDUP`
  envolvem (wrap) em `Rm` — testado o wrap.
- Predicação em todas as sub-famílias; `docs/COBERTURA-ISA.md` com exatamente 15 células novas;
  `mvn -o test` verde; G5 verde.

## Armadilhas

1. **"Qm is in the fields usually labeled Qn"** (comentário literal do arquivo, linha 67) nas formas
   `*_sg_imm`. Reusar `%qm` aqui dá o registrador errado sem nenhum sintoma de decode — é o mesmo
   tipo de armadilha da Armadilha 1 da B16.4.
2. **`Rn` par / `Rm` ímpar nos `dup` é restrição de ENCODING, não convenção.** `%vidup_rn` só
   produz valores pares e `%vidup_rm` só ímpares. Extrair `Rn`/`Rm` de 4 bits crus aqui é erro.
3. **`Thumb2NocpDecoder`/`Thumb2VfpDecoder`**: `bits[27:24] ∈ {1100, 1101}` (as formas `*_sg` e
   `VLD2`/`VLD4` são `111x 1100`/`1111 1101`) caem na **forma 2** do `NOCP` e no espaço de
   extension-register load/store do VFP. Mesmas Armadilhas 1/3 da B16.3 — ordem de registro
   obrigatória, conferida por teste.
4. **`VDDUP`/`VDWDUP` dividem o bloco `{}` com duas `VCMP*_fp_scalar` (B16.8).** O decodetree
   prioriza o padrão mais específico: `VCMPGT_fp_scalar`/`VCMPLE_fp_scalar` têm `bits[21:20]=11`
   fixo e `bits[7:4]` fixos, `VDDUP` tem `bits[7:4]` parcialmente fixos com `size` livre. Máscara
   larga demais nesta task rouba as células da B16.8 — **excluir explicitamente**, mesma técnica das
   máscaras `VLLDM_VLSTM_MASK`/`VSCCLRM_MASK` da B15.2.
5. **`VLD4` move um grupo de 4 `Q` = TODO o meio do banco.** Com só `Q0`-`Q7`, `VLD4` com `Qd=Q6`
   seria `Q6..Q9` — UNDEF. Checar `Qd + grupo - 1 <= 7`, não só `Qd <= 7`.
6. **`pat` não é "qual registrador"**: `VLD2`/`VLD4` são executadas em múltiplas instruções (uma por
   `pat`), cada uma movendo uma fatia. Implementar como se `pat` selecionasse um registrador
   produziria resultado plausível e errado — ler `do_vldst_il` no QEMU.
7. **G4/predicação e writeback**: writeback de `Rn`/`Qm` não é predicado.

## Não fazer

- Não implementar `VCMPGT_fp_scalar`/`VCMPLE_fp_scalar` (B16.8) nem as reduções/`VMLADAV`
  (B16.13), mesmo que o épico as tenha contado neste intervalo.
- Não reusar `%qm` nas formas `*_sg_imm`.
- Não extrair `Rn`/`Rm` de 4 bits crus nos `dup`.
- Não tratar gather como acesso contíguo "otimizado".
