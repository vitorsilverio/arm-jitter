# B3.4 — VFP: IrOps de FP + executor interpretado

**Trilha:** B (épico B3) · **Depende de:** B3.3 · **Repo:** arm-jitter

## Contexto

Com o banco S/D + FPSCR prontos (B3.3), esta task cria a semântica: os `IrOp`s de FP
e o executor interpretado (o oráculo, G1). Decode fica em B3.5 — aqui os testes
constroem IR à mão, como os testes de executor de B1.x fazem.

## Inclui — records novos em `ir/IrOp.java` (seguir a forma dos vizinhos: `Condition condition` no fim, javadoc `///`)

```java
enum VfpOperation { ADD, SUB, MUL, DIV, MLA, MLS, NMUL, NEG, ABS, SQRT, COPY }

record VfpAlu(VfpOperation op, boolean doublePrecision,
              int vd, int vn, int vm, Condition condition)
// MLA: vd += vn*vm · MLS: vd -= vn*vm · NMUL: vd = -(vn*vm) · unárias usam só vm
// (VMLA/VMLS do VFP acumulam SEM fused multiply-add: arredonda o produto, depois a
//  soma — em Java: duas operações separadas, NUNCA Math.fma)

record VfpMoveImmediate(boolean doublePrecision, int vd, long immediateBits,
                        Condition condition)         // VMOV.F32/.F64 #imm (v3-d16)

record VfpCompare(boolean doublePrecision, boolean compareWithZero,
                  boolean signalOnQuietNaN /*bit E: VCMPE*/,
                  int vd, int vm, Condition condition)
// escreve APENAS FPSCR.NZCV: EQ→Z, LT→N, GT→(nenhum), unordered→C+V; exato: A2.9.1
// (N,Z,C,V) = eq→(0,1,1,0) · lt→(1,0,0,0) · gt→(0,0,1,0) · unordered→(0,0,1,1)

enum VfpConversion { F32_TO_F64, F64_TO_F32, S32_TO_F32, S32_TO_F64,
                     U32_TO_F32, U32_TO_F64, F32_TO_S32, F64_TO_S32,
                     F32_TO_U32, F64_TO_U32 }

record VfpConvert(VfpConversion conversion, int vd, int vm, Condition condition)
// para-inteiro = round-toward-zero (o encoding default VCVT usa RZ; a forma VCVTR
//  que usa FPSCR.RMode fica FORA — RMode≠RN já é rejeitado pela B3.3)
// F32_TO_U32/F64_TO_U32: clampa em [0, 0xFFFFFFFF] (negativo→0, overflow→0xFFFFFFFF)
// F32_TO_S32/F64_TO_S32: NaN→0, satura em MIN/MAX (≠ do (int) do Java só no caso
//  NaN e overflow — CONFERIR: (int)Float.NaN==0 e (int)1e30f==MAX_VALUE em Java,
//  então (int)/(long) cast cobre o caso signed; unsigned precisa de clamp manual)

record VfpLoad(boolean doublePrecision, int vd, int base, int offsetBytes,
               Condition condition)                   // VLDR: P=1 W=0, offset ±imm8*4
record VfpStore(boolean doublePrecision, int vd, int base, int offsetBytes,
                Condition condition)                  // VSTR
record VfpMultipleTransfer(boolean load, boolean doublePrecision, int base,
                           int firstRegister, int count, boolean writeback,
                           boolean decrementBefore, Condition condition)
// VLDM/VSTM/VPUSH/VPOP: só IA e DB (as únicas formas VFP); registradores
// consecutivos firstRegister..firstRegister+count-1

record VfpCoreTransfer(boolean toArmRegister, int armRegister, int vn,
                       Condition condition)           // VMOV Rt↔Sn (FMSR/FMRS)
record VfpCorePairTransfer(boolean toArmRegisters, int armLow, int armHigh, int vm,
                           Condition condition)       // VMOV Rt,Rt2↔Dm (FMDRR/FMRRD)
record VfpSystemTransfer(boolean read, int armRegister, Condition condition)
// VMSR/VMRS FPSCR; read com armRegister==15 → "VMRS APSR_nzcv, FPSCR": copia
// FPSCR.NZCV para CPSR.NZCV (obrigatório — decisão nº 4 do épico)
```

## Inclui — executor

- `codegen/executor/IrVfpExecutor.java` novo, espelhando `IrMemoryExecutor` na forma;
  casos novos no switch de `IrBlockExecutor#executeOp`.
- Aritmética: operar via `VfpRegisters.sFloat/dDouble` (float/double do Java —
  decisão nº 3 do épico). SQRT single: `(float) Math.sqrt((double) x)` é
  corretamente arredondado (IEEE) — usar direto.
- Loads/stores: delegar aos MESMOS helpers de memória que `IrMemoryExecutor` usa
  (double = 2 acessos de 32 bits, metade baixa no endereço menor), com os mesmos
  ciclos de acesso — G4 vale.
- `Cycle`/`Fetch`: continuam vindos do lifter, nada especial aqui.

## Inclui — otimizador e política

- `DeadCodeEliminationPass`/`ConstantFoldPass`/`FlagMergePass`: registrar os records
  novos como opacos/efeito-colateral (NÃO otimizar FP nesta rodada): o jeito seguro é
  colocá-los no mesmo balde que `Coprocessor`/`Swi` (nunca eliminados, barreira de
  fold). `VfpCompare`/`VfpSystemTransfer(read,15)` tocam flags → tratar como
  `PsrTransfer` no `FlagMergePass`.
- `AsmNativePolicy`: rejeitar TODOS os records Vfp* (B3.6 libera).

## Não inclui

- Decode (B3.5), ASM nativo (B3.6), preset (B3.7).
- VCVT fixed-point, VCVTR, NEON, FPEXC/FPSID — UNDEFINED/fora (decisões do épico).

## Testes mínimos (`IrVfpExecutorTest`)

Vetores concretos por op (montar IR à mão, executar no interpretador, assertar bits):

1. ADD/SUB/MUL/DIV single e double (ex. 0.1f+0.2f → bits exatos de 0.3000000119...f).
2. MLA/MLS NÃO fundido: caso que distingue de FMA
   (ex. single: a=1.0000001f b=1.0000001f c=−1.0000002f → comparar com o resultado
   de duas operações arredondadas; assertar `!=` do `Math.fma`).
3. NEG/ABS preservam payload de NaN (operação de sinal é bit-a-bit, A2.9: usar
   manipulação de bit de sinal, NÃO `0-x`: `-0.0` e NaN quebram com subtração).
4. SQRT(−1) → NaN; SQRT single arredondado (vetor: sqrtf(2) bits `0x3FB504F3`).
5. VCMP: os 4 quadrantes da tabela NZCV (eq/lt/gt/unordered com NaN).
6. VCVT: cada membro do enum com vetor (incl. NaN→0, 1e30f→S32 satura MAX,
   −1.5→U32 → 0, 4294967040.0→U32 = 0xFFFFFF00).
7. Load/store: double ida-e-volta na memória, metade baixa no endereço menor;
   VLDM/VSTM com writeback IA e DB (VPUSH/VPOP são aliases DB/IA com writeback —
   testar via os records diretos).
8. VMRS APSR_nzcv: FPSCR.NZCV copiado para CPSR sem tocar Q/GE/IT/modo.
9. Condição falsa: op FP pulada não altera banco nem FPSCR mas consome Cycle/Fetch (G4).

## Validação

`mvn -o test` raiz + gbaemu/ndsemu verdes. Commit `B3.4: ...`.

## Armadilhas

- **NUNCA `Math.fma`** (vira fused, diverge do VFP não-fundido).
- **NEG via bit de sinal**, não `0-x`.
- Conversão unsigned: Java não tem u32 — trabalhe em `long` e clampe explicitamente.
- `VfpCompare` escreve FPSCR.NZCV, NÃO o CPSR — só `VMRS APSR_nzcv` move para o CPSR.
- Double na memória: 2 words little-endian (low word primeiro) — igual a LDRD/STRD;
  copie o caminho do `DoubleTransfer` em `IrMemoryExecutor`.
