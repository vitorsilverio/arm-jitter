# B1.6 — Emissão nativa ASM das ops ARMv6/v6K

**Trilha:** B · **Depende de:** B1.2, B1.3, B1.4, B1.5 · **Repo:** arm-jitter

## Contexto

Após B1.2–B1.5, as ops v6 executam via fallback PER_OP (interpretado inline). Este é o
mesmo estado em que as ops ARMv5TE ficaram antes do commit `bfbedca` ("Codegen: emissao
nativa das ops ARMv5TE") — **ler esse commit inteiro (`git show bfbedca`) e usar como
gabarito é obrigatório**.

## Objetivo

Emitir nativamente no `AsmCodeEmitter` as ops de B1.2–B1.5, zerando o
`perOpFallbackOpCount` em código ARMv6 típico.

## Especificação

Padrão a seguir (o mesmo do ARMv5TE nativo):

1. **Helpers estáticos primeiro.** Para ops de semântica densa (paralelas SIMD, USAD8,
   saturação), a emissão é um `INVOKESTATIC` para um helper em
   `codegen/jvm/AsmRuntimeHelpers.java` que implementa a operação — e esse helper deve
   ser O MESMO código que o executor interpretado chama (extrair o miolo do executor
   para o helper e fazer o executor chamá-lo). Isso garante identidade semântica por
   construção (G1) e a JVM inlina.
2. Ops triviais (REV = `Integer.reverseBytes`, SXTB = `I2B`, UXTH = `AND 0xFFFF`...)
   podem ser bytecode direto no `AsmBlockCompiler` — mas só onde o bytecode é óbvio;
   na dúvida, helper.
3. `AsmNativePolicy.supports(...)`: aceitar as ops novas (remover da lista de rejeição).
4. LDREX/STREX: helper que manipula o monitor do core (mesmo método do interpretador).
5. CPS/SRS/RFE/SETEND/WFI: são raras (kernel-only) — avaliar custo/benefício; é
   ACEITÁVEL deixá-las PER_OP permanentemente, documentando em `AsmNativePolicy`.
   Decidir com dado: se o profiling do alvo (homebrew 3DS/Pi) mostrar que não aparecem
   em hot path, não emitir.

## Ordem dos PRs

1. Extend/reverse/UMAAL (B1.2) — mais simples, calibra o padrão.
2. Paralelas + GE + saturação (B1.3) — helpers.
3. Exclusive (B1.4).

## Aceite

1. Testes de equivalência por op (harness) incluindo variantes condicionais
   (cond verdadeira E falsa — reusar a técnica 14×16 NZCV existente).
2. Bloco sintético só de ops v6: `perOpFallbackOpCount() == 0`.
3. `mvn test` + gbaemu/ndsemu verdes (G5).
4. Se houver ROM de teste v6 disponível (homebrew 3DS/Pi bare-metal), run de
   divergence-checking sem divergências (instruções para o usuário rodar).

## Armadilhas

- GE flags: o guard condicional lê CPSR — ops que ESCREVEM GE não podem clobberar
  NZCV; helpers devem mexer só nos bits 19:16 (máscara nomeada, G6).
- STREX nativo: a checagem do monitor vem ANTES do write — mesma ordem do executor.
- NÃO relaxar `AsmNativePolicy` para uma op antes de o caso do `AsmBlockCompiler`
  existir — a policy é o contrato do que o compilador sabe emitir.

## Resultado

✅ (3 PRs) — PR1 extend/reverse/UMAAL (B1.2): bytecode direto (I2B/I2S/AND/`Integer.reverseBytes`) + helpers `extendByte16`/`reverseHalfwords`/`reverseSignedHalfword`; UMAAL soma RdLo/RdHi como duas parcelas u32 no `LMUL` já emitido. PR2 paralelas+GE+PKH+saturação+USAD (B1.3): helpers `parallelAlu`/`sel`/`saturate`/`absDiffSum` em `AsmRuntimeHelpers` (GE e Q sticky como efeito colateral no core, espelhando o padrão ARMv5TE); PKHBT/PKHTB viram bytecode direto (AND+OR). PR3 LDREX/STREX/CLREX (B1.4): helpers `loadExclusive`/`markExclusive`/`exclusiveMonitorCovers`/`clearExclusiveMonitor`; STREX checa o monitor ANTES de qualquer escrita via branch no bytecode (mesma ordem do interpretador — falha não toca a memória), formas doubleword (LDREXD/STREXD) desenroladas inline (mark + 2×loadWord/storeWord). `AsmNativePolicy` só rejeita mais as instruções de sistema da B1.5 (CPS/SETEND/SRS/RFE/WFI — raras/kernel-only, decisão documentada); `supportedAluOpcodes()` virou `EnumSet.allOf`. Equivalência exaustiva 14 cond × 16 NZCV por grupo de op (`ArmV6ExtendReverseNativeEquivalenceTest` + `ArmV6ParallelSaturateNativeEquivalenceTest` + `ArmV6ExclusiveNativeEquivalenceTest`, esta última cobrindo B/H/D + falha de monitor) + `perOpFallbackOpCount()==0` nos blocos sintéticos. Suites arm-jitter 498 + gbaemu 216 (JitInterpreterDivergenceTest sem divergência) + ndsemu 175 verdes em todas as 3 PRs
