# B8.17 — A64 `SPSel`/`PAN`/`UAO`/`DIT`/`SSBS`/`TCO`/`ALLINT` via `MRS`/`MSR (register)`

**Trilha:** B · **Depende de:** B8.3 ✅ (mesmos campos via `MSR (immediate)`) · **Repo:** arm-jitter

## Contexto

Fecha o resto do espaço de campos `PSTATE` opcionais (ARMv8.1-ARMv8.8) que `B8.3` já tinha
tratado pela via `MSR (immediate)` como NOP puro — sem consumidor real modelado (nenhuma MMU
checando `PAN`/`UAO`, sem banking real de `SP_EL0`/`SP_EL1` por `SPSel`, sem telemetria de `DIT`,
sem mitigação Spectre de `SSBS`, sem MTE que `TCO` afetaria, sem NMI que `ALLINT` mascararia).
Faltava a via `MRS`/`MSR (register)` — usuário pediu fechar mesmo com baixo impacto prático
esperado (esses bits são majoritariamente preocupação de KERNEL, não de código de usuário como o
`busybox`), como parte da varredura sistemática rumo a 100% de cobertura ARM.

## Inclui

- **7 `Aarch64SystemRegisterId` novos**: `DIT`/`SSBS`/`TCO` (grupo EL0, `op0=3,op1=3,CRn=4,CRm=2`,
  op2=5/6/7 — MESMO `CRn`/`CRm` de `NZCV`/`DAIF`, B8.16, só `op2` muda) e `SPSEL`/`PAN`/`UAO`
  (grupo EL1 "geral", `op0=3,op1=0,CRn=4,CRm=2`, op2=0/3/4) + `ALLINT` (`CRm=3,op2=0`).
- **`Aarch64Core`**: 7 escaninhos `long` novos, armazenamento puro (mesmo padrão de `FPCR`/`FPSR`,
  B8.15) — um `MRS` tem que devolver o que foi escrito por um `MSR` anterior, mesmo sem efeito
  semântico real (diferente de `NZCV`/`DAIF`, B8.16, que ligam no estado REAL de `PstateRegister`
  — estes 7 não têm estado real nenhum para ligar, `B8.3` já confirmou isso pela via imediata).
- **`Aarch64Decoder`**: `decodeCrn4RegisterId` estendido (`DIT`/`SSBS`/`TCO`); 2 branches novos no
  grupo EL1 geral (`CRn=4,CRm=2` para `SPSel`/`PAN`/`UAO`; `CRn=4,CRm=3` para `ALLINT`).

## Não inclui

- Qualquer efeito semântico real destes 7 campos — decisão já tomada por `B8.3`, esta task só
  estende a mesma decisão para a via de acesso por registrador. Se um dia um consumidor real
  precisar de efeito de verdade (ex. um kernel real checando `PAN` antes de um acesso EL0), isso
  vira task própria — não presumido desnecessário, só sequenciado depois (Regra Máxima).

## Validação

- `Aarch64PstateFieldRegistersTest` (novo, 8 testes): decode via corpus real
  (`aarch64-none-elf-as -march=armv8.5-a`/`objdump`, devkitA64 — precisou da flag `-march` porque
  `DIT`/`SSBS`/`TCO`/`ALLINT` são de extensões posteriores ao default do assembler) + round-trip
  dos 7 registradores confirmando que são escaninhos INDEPENDENTES (nenhum vaza pro outro).
- `mvn -o test` verde (core+truffle) + `mvn -o install` local.
- **G5**: gbaemu 240/240 ✅, ndsemu 183/183 ✅, armbox 47/47 ✅.

## Resultado

✅ (2026-08-27) — fecha o espaço de campos `PSTATE` opcionais via `MRS`/`MSR (register)` iniciado
por B8.3 (`MSR (immediate)`). Junto com B8.13-B8.16, fecha esta rodada de varredura sistemática de
registradores de sistema A64 priorizada pelo usuário em 2026-08-27.
