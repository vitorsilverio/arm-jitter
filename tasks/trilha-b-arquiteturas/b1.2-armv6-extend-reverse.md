# B1.2 — Instruções ARMv6 de extensão, reverse e UMAAL

**Trilha:** B · **Depende de:** B1.1 · **Repo:** arm-jitter

## Contexto

O grupo mais simples do ARMv6: operações puramente de registrador, sem memória, sem
flags de estado novas. Precedente interno a espelhar: como o `CLZ` (ARMv5) foi
adicionado — decoder gateado por `ArmFeature`, `IrOpCode` novo, caso no
`IrAluExecutor`, testes de vetor conhecido.

## Objetivo

Decodificar, liftar para IR e interpretar corretamente (backend ASM fica para B1.6;
até lá essas ops caem no fallback PER_OP automaticamente):

- `SXTB, SXTH, SXTB16, UXTB, UXTH, UXTB16` (extensão com rotação do operando: ROR 0/8/16/24)
- `SXTAB, SXTAH, SXTAB16, UXTAB, UXTAH, UXTAB16` (idem + acumulador Rn)
- `REV, REV16, REVSH`
- `UMAAL` (Rd_lo/Rd_hi = Rd_lo + Rd_hi + Rm*Rs, sem flags)

## Especificação

1. **Encodings:** consultar o ARM Architecture Reference Manual (DDI 0100I, capítulo
   ARMv6) — NÃO confiar em memória para bits de encoding. GBATEK NÃO cobre ARMv6
   direito (é GBA/NDS).
2. **Gating:** cada grupo decodifica somente se `architecture.has(...)` do feature
   correspondente de B1.1; sem o feature, o opcode segue o caminho atual (undefined).
3. **IR:** para extend/reverse, adicionar valores em `IrOpCode` e tratar no
   `IrAluExecutor` (espelhar CLZ). A rotação do operando dos SXT/UXT usa o operando
   `ShiftedRegister` com ROR existente, se encaixar; se não encaixar limpo, adicionar
   campo próprio — decidir lendo o código do IR primeiro, e preferir reuso.
   Para `UMAAL`, estender `IrOp.LongMultiply` com uma variante de acumulador duplo
   (ver como UMLAL/SMLAL são representados hoje).
4. **Testes por instrução** com vetores concretos, no mínimo:
   - `REV(0x12345678) = 0x78563412`
   - `REV16(0x12345678) = 0x34127856`
   - `REVSH(0x00008380) = 0xFFFF8083` (sign-extend do halfword invertido)
   - `SXTB(0x000000FF) = 0xFFFFFFFF`; `SXTB` com ROR 8 de `0x0000FF00` = `0xFFFFFFFF`
   - `UXTH(0x12345678) = 0x00005678`
   - `SXTAB(acc=5, 0x000000FF) = 4` (5 + (-1))
   - `UMAAL`: `0xFFFFFFFF*0xFFFFFFFF + 0xFFFFFFFF + 0xFFFFFFFF = 0xFFFFFFFF_FFFFFFFF`
     (caso de borda que NÃO estoura — provar que não perde carry)
   - Cada instrução também com teste no `ARMV4T` provando que continua undefined (G2).
5. Testes de equivalência: os blocos com essas ops devem passar no harness com o
   backend ASM em modo PER_OP (a op cai no interpretado inline — já deve funcionar
   sem mudança; o teste PROVA isso).

## Aceite

- `mvn test` verde; suites gbaemu/ndsemu verdes (G5) — nada muda para v4T/v5TE.
- Nenhuma emissão nativa ASM nesta task.

## Armadilhas

- SXTB16/UXTB16 operam nos DOIS bytes pares (bits 23:16 e 7:0) — fácil de errar.
- REVSH inverte o halfword BAIXO e estende o sinal — não inverte a word toda.
- UMAAL não seta flags NUNCA (diferente de UMLAL com S).

## Resultado

✅ (decoder gateado + IR + interpretador; extend via ShiftedRegister ROR, UMAAL como `LongMultiply.accumulateDouble`; ASM rejeita até B1.6 — equivalência PER_OP provada; suites arm-jitter 389 + gbaemu 215 + ndsemu 175 verdes)
