# B19.28 — A64: `FEAT_SME` residual (`MSR (immediate) SVCR`) — 1 linha

**Trilha:** B · **Repo:** arm-jitter (+ revalidação G5) · **Depende de:** B19.9
**Épico:** `b19-plano-a64-gap-remanescente.md` · **Status:** ⬜ spec pronta para execução

## Contexto

Degrau nomeado pela varredura de fechamento do épico B19 (`b19.9-a64-fechamento.md`, seção
"Varredura do que sobrou", 2026-09-10). `Aarch64Feature.SCALABLE_MATRIX_EXTENSION` **já existe** e
**já está declarada** em `Aarch64Architecture.ARMV9_2_A`; o Javadoc da constante já registra a
intenção: "nenhum estado ZA/SVE é modelado ainda — esta feature só existe para permitir que `MSR
SVCR` continue recusado (`UNIMPLEMENTED`) de forma explicitamente rastreável, não silenciosa, quando
o decoder passar a consultá-la". **Esta task é exatamente esse "quando".**

A linha (`target/isa-decode/a64.decode`):

```
311:MSR_i_SVCR      1101 0101 0000 0 011 0100 0 mask:2 imm:1 011 11111
```

O decoder já tem o comentário deixado pela B8.3, `Aarch64Decoder.java` ~linha 598-604:
`SYSTEM_INSTRUCTION_PSTATE_IMM_OP1 = 0b011` cobre `SBSS`/`DIT`/`TCO`/`DAIFSet`/`DAIFClr`, e o
comentário diz explicitamente: **"`SVCR` (`op2=0b011`) fica de fora do `switch` abaixo — cai no
`default -> unsupported`"**. Esta task adiciona o `case` que falta.

### O que `SVCR` é, e por que "armazenamento puro" é a decisão certa

`SVCR` ("Streaming Vector Control Register") é o registrador de PSTATE do SME (Scalable Matrix
Extension) com dois bits observáveis: `SM` (streaming SVE mode ativo) e `ZA` (armazenamento da
matriz `ZA` ativo). `MSR SVCRSM, #imm` / `MSR SVCRZA, #imm` / `MSR SVCRSMZA, #imm` (a instrução real
por trás de `MSR_i_SVCR` — o campo `mask` de 2 bits seleciona quais dos dois bits `imm` afeta) SETAM
ou LIMPAM esses bits. O projeto **não implementa SME/SME2** (épico **B18**, não iniciado,
`sme.decode` fora de escopo) — então, hoje, este `MSR` não teria NENHUM consumidor real de
"streaming mode" para checar (nenhuma instrução SME que se comporte diferente com `SM=1`).

Isso é o **mesmo padrão** que a B8.15 (`FPCR`/`FPSR`), B8.16 (`NZCV`/`DAIF`/`CNTVCT_EL0`) e B8.17
(`SPSel`/`PAN`/`UAO`/`DIT`/`SSBS`/`TCO`/`ALLINT`) já normalizaram no projeto: armazenamento puro,
sem enforcement, registrado para que uma leitura de volta (`MRS`) veja o que foi escrito, e para que
o dia em que B18 chegar tenha onde ler o estado real em vez de reconstruir do zero.

**Leitura obrigatória**: `## Resultado` da **B8.16** e da **B8.17** (o padrão de campo de PSTATE
armazenado sem consumidor), `Aarch64Decoder.java` ~linha 590-610 (o comentário que já aponta
exatamente onde `SVCR` falta), `Aarch64Feature.SCALABLE_MATRIX_EXTENSION` (Javadoc já escrito).

## Objetivo

`MSR (immediate) SVCR` decodifica e executa (armazenamento puro dos bits `SM`/`ZA`) sob
`ARMv9.2-A`+, gateada por `Aarch64Feature.SCALABLE_MATRIX_EXTENSION`, e é recusada antes.

## Inclui

1. **Escaninhos `SM`/`ZA`** em `PstateRegister` (ou equivalente), mesmo padrão de armazenamento puro
   dos campos soltos da B8.17.
2. **Decode**: novo `case` no `switch` de `op2` dentro de `SYSTEM_INSTRUCTION_PSTATE_IMM_OP1`
   (`Aarch64Decoder.java` ~linha 598), tratando `op2 == 0b011` (`SVCR`) — ler `mask` (bits[9:8]) e
   `imm` (bit[?]) do encoding, aplicando aos escaninhos conforme `mask` selecionar `SM`/`ZA`/ambos.
3. **Gate** `Aarch64Feature.SCALABLE_MATRIX_EXTENSION`.
4. **Verificar se `MRS`/`MSR (register)` de `SVCR`** (a forma de LEITURA — `SVCR` só é ESCRITO via
   `MSR` imediato; a leitura é via `MRS Xt, SVCR`, forma de registrador de sistema) já existe no
   decoder. Se não existir, é gap IRMÃO — registrar como task nomeada no `## Resultado` (nunca
   "não vamos fazer"), não implementar aqui se estiver fora do orçamento desta sessão.
5. Testes (ver Aceite).

## Não inclui

- Qualquer estado ZA/streaming-SVE real (nenhuma instrução SME modelada — épico B18).
- Enforcement: nenhuma outra instrução do projeto passa a se comportar diferente por causa de
  `SM`/`ZA` — puro armazenamento, mesma disciplina de `FPCR.RMode`/`FZ`.
- Emissão nativa.

## Armadilhas

1. **Não modelar enforcement.** É tentador, ao ver "streaming mode", querer fazer alguma instrução
   se comportar diferente — não há nenhuma instrução SME no projeto para isso fazer sentido; B18
   cuida disso quando chegar.
2. **`SVCR` só é ESCRITO por `MSR` imediato** — a leitura é por `MRS` (forma de registrador de
   sistema geral, não a forma "immediate" desta linha). Confundir os dois é fácil pelo nome.
3. **Comentário do decoder já aponta o lugar exato** — não reinventar a localização; o `switch` de
   `op2` sob `SYSTEM_INSTRUCTION_PSTATE_IMM_OP1` já está escrito, só falta o `case`.

## Não fazer

- Não implementar qualquer instrução SME/SME2 real.
- Não modelar `GCSPR_EL0`/GCS (task B19.27, feature diferente).
- Não adicionar caso nativo em `Ir64NativePolicy`.
