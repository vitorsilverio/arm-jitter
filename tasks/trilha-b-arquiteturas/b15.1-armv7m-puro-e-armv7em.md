# B15.1 — Presets `ARMV7M_PURE` (ARMv7-M sem DSP) e `ARMV7EM` (alias correto do preset DSP)

**Trilha:** B · **Repo:** arm-jitter · **Status:** ⬜ · **Depende de:** — · **Encodings:** 0

## Contexto

`ArmArchitecture.ARMV7M` (B7.4 + features DSP completadas pela B9.16) já inclui a extensão DSP
inteira (`PACK_SATURATE`/`PARALLEL_SIMD`/`SIGNED_MULTIPLY_MEDIA`/`DSP_MULTIPLY`/`UMAAL`) — ou seja,
o que hoje se chama `ARMV7M` é, de fato, um **ARMv7E-M** (Cortex-M4/M7), não um ARMv7-M puro
(Cortex-M3). A B12.4 (catálogo de processadores) documentou isso explicitamente ao deixar
`SC300`/`Cortex-M3` de fora: mapear `Cortex-M3` para `ARMV7M` seria uma entrada factualmente
errada (o Cortex-M3 não tem DSP). Ver `b15-plano-armv8m.md` para o épico completo.

## Objetivo

Introduzir, **ao lado** do preset `ARMV7M` existente (G3 — nunca redefinir, comportamento e nome
atuais intocados):

1. `ARMV7M_PURE` — ARMv7-M sem a extensão DSP (para Cortex-M3/SC300).
2. `ARMV7EM` — alias explícito do preset DSP-completo já existente, para o catálogo (B15.7) poder
   nomear corretamente Cortex-M4/M7 sem reaproveitar o nome ambíguo `ARMV7M`.

Zero células novas em `docs/COBERTURA-ISA.md` (nenhuma das duas entra no mapa `ARM_ARCHITECTURES`
de `IsaCoverageReport` nesta task — isso exigiria decidir coluna própria, fora do escopo aqui).

## Inclui

1. `ArmArchitecture.ARMV7M_PURE`: mesmas features de `ARMV7M` **menos** as 5 de DSP
   (`PACK_SATURATE`, `PARALLEL_SIMD`, `SIGNED_MULTIPLY_MEDIA`, `DSP_MULTIPLY`, `UMAAL`) — resto
   idêntico (`EXTEND_ROTATE`, `BYTE_REVERSE`, `EXCLUSIVE_WORD`, `EXCLUSIVE_SIZED`, `MOVW_MOVT`,
   `BIT_FIELD`, `BIT_REVERSE`, `MLS_MULTIPLY`, `DIVIDE`, `SATURATING`, `M_FAULT_MASKING`,
   `M_PROFILE_WIDE_MISC_CONTROL`, `CLZ`, `LDRD_STRD`, `PRELOAD_HINTS`, mais tudo herdado de
   `ARMV6M_FEATURES`). Mesmas extensões de decoder Thumb-2 que `ARMV7M` usa, só que instanciadas
   com `ARMV7M_PURE` (os decoders recebem a arquitetura no construtor para gating).
2. `ArmArchitecture.ARMV7EM = ARMV7M` — alias direto (mesmo objeto), documentado em Javadoc: "é o
   preset `ARMV7M` existente, sob o nome arquiteturalmente correto". Não duplica objeto nem lógica.
3. Javadoc explicando a relação entre os três nomes (`ARMV7M` legado/intocado, `ARMV7M_PURE` novo,
   `ARMV7EM` alias) para quem ler o código depois não reabrir a dúvida.
4. Teste novo espelhando `ArmArchitectureMProfilePresetsTest`: `ARMV7M_PURE` rejeita uma instrução
   DSP (ex. `SADD16`) que `ARMV7M`/`ARMV7EM` aceitam; `ARMV7M_PURE` continua aceitando o resto do
   Thumb-2 largo (`LDR.W`, `ADD.W`, `BASEPRI` via `M_FAULT_MASKING`) igual a `ARMV7M`; `ARMV7EM ==
   ARMV7M` (mesma referência, não só mesmas features).

## Não inclui

- Presets `ARMV8M_BASELINE`/`ARMV8M_MAINLINE`/`ARMV8_1M` (B15.4/B15.6).
- Entradas no catálogo `ArmProcessor` para `SC300`/`Cortex-M3`/`M4`/`M7` (B15.7 — depende de
  B15.5/B15.6 fecharem primeiro, por reunir todos os presets do épico de uma vez).
- Qualquer mudança em `docs/COBERTURA-ISA.md` (não adiciona coluna).
- Qualquer mudança de decode/execução — só composição de features.

## Aceite

- `ARMV7M` permanece byte a byte idêntico em nome e comportamento (G3) — nenhum teste existente
  quebra.
- `ARMV7M_PURE.has(ArmFeature.DSP_MULTIPLY)` etc. → `false`; resto do Thumb-2 largo → `true`.
- `ArmArchitecture.ARMV7EM == ArmArchitecture.ARMV7M` (identidade de referência).
- `docs/COBERTURA-ISA.md` byte a byte idêntica (`ARM_ARCHITECTURES` de `IsaCoverageReport` não
  ganha entrada nova nesta task).
- `mvn -o test` verde, G5 verde nos 5 consumidores.

## Armadilhas

1. **Não usar `extending(ARMV7M_FEATURES, ...)` para tirar features** — a API só soma
   (`extending` nunca remove). `ARMV7M_PURE` tem que nascer de `of(...)` com a lista positiva.
2. **Os `Thumb2*Decoder` recebem a arquitetura no construtor** (mesmo quebra-cabeça ovo-e-galinha
   documentado no Javadoc de `ARMV7M_FEATURES`/`ARMV7M`) — declarar o campo `ARMV7M_PURE_FEATURES`
   privado antes de instanciar os decoders, no mesmo padrão de `ARMV7M_FEATURES`/`ARMV7M`.
3. **`ARMV7EM` é identidade, não uma cópia com mesmo conteúdo** — usar `ARMV7EM = ARMV7M` (mesma
   referência), não `of(...)`/`extending(...)` reconstruindo os mesmos valores (isso quebraria o
   teste de identidade e duplicaria manutenção se `ARMV7M` mudar no futuro).

## Não fazer

- Não popular `ArmProcessor` (catálogo) nesta task — isso é B15.7.
- Não adicionar `ARMV7M_PURE`/`ARMV7EM` ao mapa `ARM_ARCHITECTURES` de `IsaCoverageReport` (decisão
  de coluna nova fica para quando o épico B15 tiver os presets todos, ou task própria).

## Resultado

Implementado exatamente como especificado, sem desvio.

### Implementação

1. **`ArmArchitecture.ARMV7M_PURE`**: campo privado `ARMV7M_PURE_FEATURES = extending(ARMV6M_FEATURES,
   "ArmV7-M (sem DSP)", ...)` com a lista POSITIVA das 15 features não-DSP que `ARMV7M_FEATURES` já
   tinha (`EXTEND_ROTATE`, `BYTE_REVERSE`, `EXCLUSIVE_WORD`, `EXCLUSIVE_SIZED`, `MOVW_MOVT`,
   `BIT_FIELD`, `BIT_REVERSE`, `MLS_MULTIPLY`, `DIVIDE`, `SATURATING`, `M_FAULT_MASKING`,
   `M_PROFILE_WIDE_MISC_CONTROL`, `CLZ`, `LDRD_STRD`, `PRELOAD_HINTS`) — as 5 de DSP
   (`PACK_SATURATE`/`PARALLEL_SIMD`/`SIGNED_MULTIPLY_MEDIA`/`DSP_MULTIPLY`/`UMAAL`) ficaram de fora.
   `ARMV7M_PURE` público é essa base com os mesmos 7 `Thumb2*Decoder` que `ARMV7M` usa, cada um
   instanciado com `ARMV7M_PURE_FEATURES` (mesmo quebra-cabeça ovo-e-galinha do preset original —
   os decoders recebem a arquitetura no construtor, por isso o campo privado antes do público).
2. **`ArmArchitecture.ARMV7EM = ARMV7M`**: alias por identidade de referência (não `of(...)`/
   `extending(...)` reconstruindo os mesmos valores), exatamente como a spec pedia — existe só para
   o catálogo (B15.7, ainda não pega) nomear Cortex-M4/M7 corretamente sem reaproveitar o nome
   ambíguo `ARMV7M`.
3. `ARMV7M` (nome e comportamento) não foi tocado em nenhuma linha — confirmado pelo teste
   `armv7mPureHasExpectedFeatureComposition` (`ARMV7M` continua com `PACK_SATURATE`/`UMAAL`) e pela
   suíte completa de `ArmArchitectureMProfilePresetsTest` (pré-existente) passando sem alteração.
