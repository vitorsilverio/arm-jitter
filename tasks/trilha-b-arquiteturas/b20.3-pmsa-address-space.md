# B20.3 — Perfil R: `PmsaAddressSpace` (checagem por região, sub-regiões, `AP`/`XN`, aborts de PMSA)

**Trilha:** B · **Repo:** arm-jitter (+ revalidação G5) · **Depende de:** B20.2
**Épico:** `b20-plano-perfil-r.md` · **Status:** ⬜ (spec escrita 2026-09-14, ainda não executada)

## Contexto

B20.2 criou o banco de registradores da MPU (PMSAv7) e a via `MCR`/`MRC` que o programa. Esta task
é o **coração do épico**: o componente que efetivamente PERMITE ou NEGA cada acesso de memória
conforme as regiões programadas, e que converte a negação em `DATA_ABORT`/`PREFETCH_ABORT` com
`DFSR`/`IFSR` **de PMSA** (códigos diferentes dos de VMSA).

O padrão de design é o mesmo que a `docs/RFC-SOFTMMU.md` decisão 1 fixou e o B4.1.1 provou:
**wrapper de `AddressSpace`**, não tradução inline no JIT. A diferença estrutural em relação ao
`TranslatingAddressSpace` é que PMSA **não traduz**: o endereço de saída é sempre igual ao de
entrada. Isso torna este wrapper mais simples (sem page-walk, sem TLB, sem `translationGeneration`
— ver Armadilha 6) e ao mesmo tempo mais fácil de errar na parte que importa: a **prioridade de
região**.

### Semântica real de PMSAv7 (medida nesta rodada de spec contra o QEMU real)

Fonte: `target/arm/ptw.c` do QEMU (`get_phys_addr_pmsav7`, `get_phys_addr_pmsav7_default`,
`pmsav7_use_background_region`), lido via `WebFetch` em 2026-09-14, mais a ARM DDI 0406C (seção
PMSA) e o
[`ARM: add ARMv7R MPU support`](https://www.mail-archive.com/barebox@lists.infradead.org/msg51092.html)
do barebox para o layout de bits (já tabulado na B20.2).

1. **Prioridade invertida**: o laço do QEMU é
   `for (n = (int)cpu->pmsav7_dregion - 1; n >= 0; n--)` e faz `break` no PRIMEIRO acerto — ou
   seja, varre do índice MAIOR para o MENOR: **a região de maior número vence** em sobreposição.
   Esta é a armadilha nº 1 do épico, agora confirmada em fonte real.
2. **Região habilitada**: `DRSR.EN` (bit 0) tem que estar ligado; `RSIZE == 0` faz o QEMU logar
   erro de guest e **pular a região inteira** (`continue`), não tratá-la como tamanho 2.
3. **Faixa**: `rsize = RSIZE + 1`; `rmask = (1<<rsize) - 1`; o acerto é
   `address >= base && address <= base + rmask`. Há checagem de erro de guest quando
   `base & rmask != 0` (base não alinhada ao tamanho) — decidir se replicamos o aviso.
4. **Sub-regiões**: só existem quando `rsize >= 8` (regiões ≥ 256 bytes) — comentário literal do
   QEMU "no subregions for regions < 256 bytes". O índice da sub-região sai dos 3 bits do endereço
   logo abaixo do topo da região, e `srdis = extract32(DRSR, snd + 8, 1)`; sub-região desabilitada
   → a região **não** conta como acerto (`continue`, segue para a região de índice menor).
   ⚠️ A expressão exata do índice (`snd`) veio parafraseada nas duas consultas de `WebFetch` desta
   rodada (uma devolveu `((address - base) >> rsize) & 0x7`, o que não pode estar certo — com
   `>> rsize` o resultado é sempre 0 dentro da região). **Reconfirmar lendo o código real** antes
   de implementar: a forma que faz sentido dimensionalmente é `extract32(address, rsize - 3, 3)`
   (os 3 bits imediatamente abaixo do topo da região). Ver Armadilha 2.
5. **Nenhuma região casou** → `ARMFault_Background`, **exceto** se a região de background estiver
   habilitada (`SCTLR.BR`) e o acesso for privilegiado — aí vale o mapa default
   (`get_phys_addr_pmsav7_default`), que dá acesso pleno. Regra real do
   `pmsav7_use_background_region`: **usuário nunca** usa background; privilegiado usa se `BR=1`.
   (Confirmar o detalhe "e nunca para fetch de instrução"/XN do default contra o manual.)
6. **Permissão negada pelos `AP`** → `ARMFault_Permission`.

### Códigos de falha `DFSR`/`IFSR` de PMSA (≠ VMSA) — a armadilha nº 2 do épico

Confirmados na tabela "PMSAv7" da base de conhecimento da SEGGER
(`kb.segger.com/Cortex-A/R_Fault`, que rotula explicitamente os valores como PMSAv7), a conferir
contra a tabela B5-8 do ARM DDI 0406C:

| Falha | `FS` |
|---|---|
| Background fault (nenhuma região casou) | `0b00000` |
| Alignment fault | `0b00001` |
| Debug event (watchpoint) | `0b00010` |
| Synchronous external abort | `0b01000` |
| **Permission fault** | `0b01101` |
| Asynchronous external abort | `0b10110` |
| Async/sync parity error | `0b11000`/`0b11001` |

Não existe "translation fault" nem "domain fault" em PMSA — os códigos `0x5`/`0x7`/`0x9`/`0xB` do
`FaultStatus` (VMSA) **não têm significado aqui**. Os bits usados são \[10\] e \[3:0\] do `DFSR`
(mesma fonte). A `DFSR` de PMSA também tem `WnR` e o campo de domínio é RAZ — confirmar.

## Objetivo

`PmsaAddressSpace implements AddressSpace` envolve o `AddressSpace` físico de um hospedeiro de
perfil R: cada `read*`/`write*`/`fetch*` é checado contra as regiões de `Pmsav7MpuRegisters`
(B20.2) e, quando negado, levanta uma exceção que os DOIS motores (interpretador e bloco JIT)
convertem em `ArmException.DATA_ABORT`/`PREFETCH_ABORT` com `DFSR`/`IFSR`/`DFAR`/`IFAR` de PMSA
preenchidos. Com `SCTLR.M=0`, o wrapper é transparente (tudo passa).

## Inclui

1. **`PmsaFaultStatus`** (enum, pacote `memory/mpu/`) — os códigos da tabela acima (pelo menos
   `BACKGROUND`, `PERMISSION`, `ALIGNMENT`), com `code()` pronto para `DFSR`/`IFSR`. **Enum novo**,
   irmão de `memory/mmu/FaultStatus`, nunca uma extensão dele (semânticas incompatíveis).
2. **A exceção de falha**: decidir entre (a) `PmsaAccessException` nova, espelhando
   `MemoryTranslationException` (unchecked, sem stack trace, com `address`/`accessType`/
   `faultStatus`), ou (b) generalizar `MemoryTranslationException` para aceitar um código de falha
   de qualquer origem. **Recomendação desta spec: (a)** — `MemoryTranslationException` é tipada com
   `FaultStatus` (VMSA) e capturada por nome nos dois motores; mexer nela é G3-sensível. Mas isso
   implica **acrescentar um `catch` novo em cada motor** (ver item 4 e Armadilha 4): medir o custo
   antes de decidir, e documentar a escolha no `## Resultado`.
3. **`PmsaAddressSpace implements AddressSpace`**:
   - construtor `(AddressSpace physical, Pmsav7MpuRegisters mpu)` — o físico nunca é alterado (G3);
   - `read8/16/32`, `write8/16/32` → checagem de dados; `fetch16`/`fetch32` → checagem de
     instrução (`XN` e `PREFETCH_ABORT`, mesma separação que `AddressSpace#fetch16` documenta);
   - `withUnprivilegedAccess` → alterna a checagem para "usuário" no escopo do `Runnable` (mesmo
     padrão de "efeito mínimo restaurado no `finally`" já usado pelo VMSA, para `LDRxT`/`STRxT`);
   - `notifyWrite`/`accessCycles` delegam ao físico;
   - `translationGeneration()` fica no default `0` — ver Armadilha 6;
   - `mpuEnabled == false` → **bypass total**, delega tudo ao físico sem checar.
4. **Estado de privilégio**: PMSA distingue privilegiado×usuário nos `AP` exatamente como VMSA.
   Reusar o gancho `ModeChangeListener` (o `Cp15VmsaCoprocessor` implementa; aqui quem deve
   implementá-lo é o `Pmsav7MpuCoprocessor` da B20.2 ou este wrapper — decidir e documentar).
5. **Preenchimento de `DFSR`/`IFSR`/`DFAR`/`IFAR`** no bus da B20.2, via `MemoryAbortListener`
   (mesmo gancho `ArmCore#setMemoryAbortListener` que o VMSA usa desde B4.1.3) — com os códigos de
   **PMSA**.
6. **Conversão nos motores**: capturar a exceção nova em `ArmCore.stepReturningInternalCycles`
   (interpretador) e no caminho equivalente do bloco JIT, convertendo em
   `ArmException.DATA_ABORT`/`PREFETCH_ABORT` — **espelhando byte a byte** o que a B4.1.3 já fez
   para `MemoryTranslationException` (incluindo a semântica *base-restored* de `LDM`/`STM`).
7. Testes (ver Aceite).

## Não inclui

- **TCM** (B20.4) — o TCM sobrepõe o barramento ANTES da MPU no hardware real; a ordem de
  composição dos wrappers é decisão da B20.4, não desta task.
- **PMSAv8** (`PRBAR`/`PRLAR`, regiões por base+limite, sem sub-região) — B20.7. **Não escrever
  nenhuma abstração "comum às duas versões"** (armadilha explícita do épico).
- **MPU separado instrução/dados** (`IRBAR`/`IRSR`/`IRACR`) — ver "Não inclui" da B20.2.
- **Alignment fault (`SCTLR.A`)** — o projeto já modela `UNALIGNED_ACCESS` por feature; gerar
  `PmsaFaultStatus.ALIGNMENT` de verdade exigiria modelar `SCTLR.A`, que nenhum preset faz. Incluir
  o código no enum (documentado como ainda não produzido) e deixar a produção para task futura
  nomeada.
- **Cache/`TEX`/`S`/`C`/`B`** — sem cache modelado; armazenados (B20.2) e ignorados aqui.
- **Emissão nativa/Truffle** — decode+interpretado apenas, mesmo padrão do resto da trilha B.

## Aceite

- **Prioridade invertida provada por teste**: duas regiões sobrepostas, a de índice MAIOR com
  permissão mais restritiva — o acesso é negado. O teste gêmeo (região restritiva no índice MENOR)
  permite. Sem esse par, a armadilha nº 1 do épico passa despercebida.
- **Sub-regiões**: região de 4KiB com uma sub-região de 512 bytes desabilitada — acesso dentro dela
  cai para a região de índice menor (ou vira background fault se não houver), e acesso nas outras
  7 sub-regiões passa. Teste também uma região < 256 bytes provando que `SRD` é ignorado lá.
- **Background**: nenhuma região casa → `DATA_ABORT` com `DFSR.FS = 0b00000` quando `SCTLR.BR=0`;
  com `SCTLR.BR=1` e modo privilegiado, o acesso passa; em modo usuário aborta mesmo com `BR=1`.
- **Permissão**: `AP` negando escrita → `DATA_ABORT` com `FS = 0b01101` e `DFAR` = endereço.
- **`XN`**: `fetch32` numa região com `XN=1` → `PREFETCH_ABORT` (não `DATA_ABORT`) com `IFSR`
  preenchido; leitura de dados do MESMO endereço continua passando.
- **`SCTLR.M=0` é bypass total** (nenhum abort, delegação direta) — inclusive com regiões
  programadas de forma restritiva.
- **Equivalência G1**: o mesmo programa abortando roda idêntico em INTERPRETED e JIT
  (`BlockEquivalenceHarness`/o equivalente que a B4.1.3 usou: `MemoryAbortEquivalenceTest`).
- **G3**: nenhum consumidor sem `PmsaAddressSpace` muda de comportamento; `TranslatingAddressSpace`
  intocado. `docs/COBERTURA-ISA.md` zero-diff; `mvn -o test` verde + G5 verde nos 5 consumidores.

## Armadilhas

1. **Prioridade de região invertida** (armadilha nº 1 do épico, confirmada no QEMU): varrer do
   índice MAIOR para o MENOR e parar no primeiro acerto. Escrever o laço "natural" (0..N) dá
   permissão errada em silêncio — nada quebra, o software só passa a poder o que não deveria.
2. **O índice de sub-região não foi confirmado com certeza nesta rodada de spec** — as duas
   consultas de `WebFetch` devolveram expressões diferentes e uma delas é dimensionalmente
   impossível. Ler o código real antes de implementar e registrar a expressão correta no
   `## Resultado`. Um erro aqui só aparece com regiões ≥ 256 bytes usando `SRD`.
3. **A tabela `AP[2:0]` da Especificação é leitura desta spec, não fonte confirmada** — validar
   contra o manual/QEMU. E `AP` de PMSAv7 tem **3 bits** (\[10:8\] de `DRACR`), ao contrário dos 2
   bits do AP clássico de VMSA que `TranslatingAddressSpace` usa: copiar o `switch` de lá produz
   permissões erradas.
4. **Capturar a exceção nova nos DOIS motores** — o interpretador e o corpo do bloco JIT. A B4.1.3
   já pagou essa lição para o VMSA; um `catch` esquecido no JIT faz a exceção escapar como
   `RuntimeException` do host (crash), não como abort do guest. Se a decisão (b) (reusar
   `MemoryTranslationException`) for tomada, esse risco some — mas aí o tipo `FaultStatus` vira
   inconsistente, e o encoder de FSR do VMSA pode ser chamado por engano, que é exatamente a
   armadilha nº 2 do épico ("um kernel de tempo real diagnosticando a falha errada").
5. **`DFSR` de PMSA usa os bits \[10\] e \[3:0\]** — o código `0b10110` (async external abort) não
   cabe em 4 bits; qualquer encoder que assuma "FS são 4 bits" está errado para metade da tabela.
6. **`translationGeneration()` deve continuar `0`** e isso é uma decisão, não esquecimento: PMSA
   não troca mapeamento de VA→PA (não há VA), então um bloco JIT compilado continua válido mesmo
   depois de reprogramar a MPU. **Confirmar o raciocínio**: se alguma reprogramação puder mudar o
   CONTEÚDO visto num mesmo endereço (ex. TCM da B20.4 sobrepondo o barramento!), aí sim é preciso
   bumpar geração — registrar essa conclusão para a B20.4 consumir.
7. **Não cachear a decisão de permissão**. A política (`AP` × privilégio) é reavaliada a cada
   acesso — mesma regra que o `TranslatingAddressSpace` documenta para o `DACR`/modo. Sem TLB não
   há nem a tentação, mas um "cache da última região que casou" reintroduz o problema.

## Não fazer

- Não implementar TCM (B20.4), PMSAv8 (B20.7) nem MPU separado I/D.
- Não reusar `FaultStatus` (VMSA) nem o encoder de FSR do `Cp15VmsaCoprocessor`.
- Não escrever uma superclasse/interface "comum a PMSAv7 e PMSAv8" antes de as duas existirem.
- Não tocar em `TranslatingAddressSpace`/`Cp15VmsaCoprocessor`.
- Não decidir sozinho, sem ler o código real do QEMU, a expressão de sub-região nem a tabela de
  `AP` (Armadilhas 2 e 3).
