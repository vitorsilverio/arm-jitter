# B7.5 — Runner bare-metal Cortex-M no armbox (`--machine=cortex-m`) + firmware torture

**Trilha:** B (épico B7, fechamento) · **Depende de:** B7.3, B7.4 · **Repo:** armbox (+ arm-jitter só se sair bug)

## Contexto

armbox hoje é um runner Linux user-mode (ELF + syscalls). Cortex-M é bare-metal:
sem SO, boot pela tabela de vetores, saída via semihosting. Em vez de repo novo,
armbox ganha um segundo modo de máquina — reusa loader ELF, os 3 backends
(JIT/`--interp`/`--check`) e o padrão de torture test de B4.0.1/B4.0.2.

## Inclui

### 1. `--machine=cortex-m` (default continua `linux-user`)

- `--arch=armv6m|armv7m` seleciona o preset (B7.4); `--machine=cortex-m` exige um
  desses.
- Memória: mapa fixo simples — flash `0x00000000` (imagem carregada), RAM
  `0x20000000` (tamanho por flag, default 1 MiB), SCS `0xE000E000` →
  `MProfileSystemControl` (B7.3). Usar `PagedAddressSpace` (C3) — primeiro
  consumidor real do utilitário; `setContainsCode` na flash.
- Aceitar `.elf` (usar o loader existente, carregando pelos endereços físicos dos
  program headers) e `.bin` cru em 0x0.
- Boot (B1.5.5): `MSP = read32(VTOR+0)`, `PC = read32(VTOR+4) & ~1`, Thumb,
  Thread mode, MSP ativo.
- Loop de execução: `runBlocks` + `systemControl.tick(ciclosConsumidos)` (SysTick),
  reusando o esqueleto do `Armbox.run` atual (incluindo o wake de WFI documentado
  em B4.0.1 — em cortex-m, WFI acorda quando `hasPendingException`).

### 2. Semihosting (saída/exit do firmware)

`BKPT 0xAB` com a convenção ARM: R0 = operação, R1 = ponteiro de args.
Implementar SÓ: `SYS_WRITE0` (0x04, string NUL-terminated → stdout),
`SYS_WRITEC` (0x03), `SYS_EXIT` (0x18, R1 = código → exit do processo).
Onde: o decode de `BKPT` hoje deve virar UNDEFINED/hook — implementar no armbox
como handler instalado (ver como o armbox já intercepta SWI para syscalls e
espelhar; se `BKPT` não tiver hook no arm-jitter, criar um mínimo no core gateado
por listener — registrar no PR o que foi preciso).

### 3. Firmware de teste (testdata/, com fontes e `build-testdata.ps1` atualizado)

1. `cortexm-torture.s` (handwritten, `arm-none-eabi-as -mcpu=cortex-m3`; linker
   script mínimo `flash.ld` com a tabela de vetores na origem) — checagens
   auto-verificáveis com exit-code único (padrão B4.0.1):
   - reset entra com MSP correto;
   - `SVC #7` → handler lê o número 7 do frame empilhado (byte em
     `[ReturnAddress-2]`), devolve valor em R0 alterando o frame;
   - troca para PSP em Thread mode via CONTROL, SVC de novo (frame vai na PSP,
     handler roda em MSP);
   - SysTick: RVR curto, TICKINT, contador em RAM incrementado ≥3 vezes;
   - PendSV pendido de dentro do SysTick, entra depois (prioridades);
   - PRIMASK segura SysTick, liberar entrega a pendida;
   - MRS/MSR de MSP/PSP/CONTROL/PRIMASK ida-e-volta;
   - (v7-M) SDIV/UDIV/UBFX/MOVW/MOVT/LDREX+STREX.
   Gêmeo `-broken` (uma checagem falsa) prova o harness.
2. `cortexm-torture-m0.s`: subconjunto ARMv6-M (sem divide/bitfield/exclusive),
   montado com `-mcpu=cortex-m0`, rodado com `--arch=armv6m`.
3. `hello-cortexm.c`: `arm-none-eabi-gcc -mcpu=cortex-m3 -mthumb -nostartfiles
   -T flash.ld` com startup mínimo em asm + `SYS_WRITE0("hello cortex-m\n")` +
   `SYS_EXIT(0)` — o sinal de compilador real.

### 4. Testes JUnit (`CortexMTortureTest`, espelha `Thumb2TortureTest`)

Torture m3 + m0 + hello nos 3 backends; `-broken` exit ≠ 0; um teste de que
`--machine=linux-user` (default) segue intacto (regressão B4.0.x).

## Armadilhas

- Cortex-M é little-endian e a tabela de vetores tem SP em 0x0 e Reset em 0x4 —
  inverter os dois é o erro clássico de runner novo.
- No linker script, a flash em 0x0: `KEEP(*(.isr_vector))` primeiro — sem KEEP o
  gc-sections come a tabela e o boot lê lixo.
- `SYS_WRITE0` lê memória do guest byte a byte até NUL — limite de segurança
  (ex. 64 KiB) para firmware quebrado não travar o runner.
- O `--check` (divergence) exige que SysTick/tick seja alimentado pelos MESMOS
  ciclos nos dois backends — alimentar com os ciclos reportados pelo runtime, não
  com contagem própria por backend.
