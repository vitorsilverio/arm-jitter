# B7.4 — MRS/MSR SYSm + CPS M-profile + presets `ARMV6M`/`ARMV7M`

**Trilha:** B (épico B7) · **Depende de:** B7.2 (e B3.2 para o v7-M pleno) · **Repo:** arm-jitter
**Referência:** ARMv7-M ARM B5.2 (MRS/MSR/CPS encodings M) · **Oráculo:** QEMU
`t32.decode` + `m_helper.c` (`v7m_msr_xpsr`, `arm_v7m_mrs`).

## Contexto

O software Cortex-M conversa com MSP/PSP/PRIMASK/CONTROL via `MRS`/`MSR` com campo
**SYSm** — encoding igual ao MRS/MSR Thumb-2 do perfil A (B2.5), mas o campo que no
A é "CPSR/SPSR + máscara" no M é um NÚMERO de registrador especial. `CPSIE`/`CPSID`
em M só tocam PRIMASK/FAULTMASK. Sem isso nenhum RTOS/startup real roda.

## Inclui

### 1. Decoder (estender `Thumb2MiscDecoder` + o espaço de 16 bits do `ThumbDecoder`)

Gate: `ArmFeature.M_PROFILE` (de B7.2). Com M_PROFILE, o decode de `MRS`/`MSR` de
32 bits troca de significado (A-profile CPSR/SPSR → SYSm) — implementar como ramo
no `Thumb2MiscDecoder` consultando a feature (a arquitetura chega ao decoder — ver
como ele já consulta `WAIT_HINTS`):

| SYSm | Registrador | MRS | MSR |
|------|------------|-----|-----|
| 0-3 | APSR/IAPSR/EAPSR/XPSR | compõe do CpsrRegister+IPSR | só APSR bits |
| 5-7 | IPSR/EPSR/IEPSR | IPSR do modelo; EPSR lê 0 (B5.2.2) | ignorado (RAZ/WI) |
| 8 | MSP | do modelo | para o modelo |
| 9 | PSP | idem | idem |
| 16 | PRIMASK | idem | idem |
| 17/18 | BASEPRI/BASEPRI_MAX | v7-M only — gate: feature nova `M_FAULT_MASKING` (presente só no preset ARMV7M) | idem |
| 19 | FAULTMASK | v7-M — mesma feature `M_FAULT_MASKING` | idem |
| 20 | CONTROL | do modelo | escrita troca SP ativo se SPSEL mudar em Thread mode |

SYSm não listado → UNDEFINED. IR: reusar `IrOp.PsrTransfer`? NÃO — criar
`record MProfileSystemRegister(boolean read, int armRegister, int sysm, Condition condition)`
(o PsrTransfer A-profile carrega semântica de máscara/SPSR que não se aplica);
executor no `IrSystemExecutor` delegando ao modelo M (que é quem tem MSP/PSP/etc.).

`CPS` de 16 bits (`0xB662/0xB672` CPSIE/CPSID i; f com FAULTMASK): com M_PROFILE
mapeia para PRIMASK/FAULTMASK (não o CPS A-profile de B1.5).

### 2. Presets

```java
// Cortex-M0/M0+/M1 — ARMv6-M: Thumb-1 + subconjunto mínimo de 32 bits
public static final ArmArchitecture ARMV6M = of("ARMv6-M",
        ArmFeature.THUMB2,            // só para o fetch de 32 bits funcionar…
        ArmFeature.M_PROFILE, ArmFeature.WAIT_HINTS, ArmFeature.MEMORY_BARRIERS)
        .withThumb32DecoderExtensions(List.of(new Thumb2MiscDecoder(),
                new Thumb2BranchDecoder()));   // BL é decodificado pelo ThumbDecoder (B2.6)
// Cortex-M3 — ARMv7-M: Thumb-2 completo + divide + bitfield
public static final ArmArchitecture ARMV7M = extending(ARMV6M, "ARMv7-M",
        ArmFeature.EXTEND_ROTATE, ArmFeature.BYTE_REVERSE, /* v6 ops que o v7-M tem */
        ArmFeature.EXCLUSIVE_WORD, ArmFeature.EXCLUSIVE_SIZED,
        ArmFeature.MOVW_MOVT, ArmFeature.BIT_FIELD, ArmFeature.BIT_REVERSE,
        ArmFeature.MLS_MULTIPLY, ArmFeature.DIVIDE, ArmFeature.SATURATING,
        ArmFeature.M_FAULT_MASKING)
        .withThumb32DecoderExtensions(List.of(/* as 4 de ARMV6K_THUMB2 +
                Thumb2MultiplyDivideDecoder (B3.2) */));
```

**ARMV6M — restrição real do decode**: v6-M NÃO tem o Thumb-2 largo (sem LDR.W,
sem dataproc de 32 bits) — por isso o preset NÃO pluga
`Thumb2DataProcessingDecoder`/`Thumb2LoadStoreDecoder`; os únicos 32-bit são
BL (nativo do ThumbDecoder pós-B2.6), DMB/DSB/ISB e MRS/MSR (Misc). Conferir a
lista exata na Tabela A5-1 do ARMv6-M ARM (DDI 0419) ao implementar. O gcc
`-mcpu=cortex-m0` respeita isso sozinho.

Checar/ajustar: instruções Thumb-1 que em M são UNDEFINED (ex. `SETEND` não existe;
`SWI`→`SVC` mesmo encoding, ok; `BLX reg` existe, `BX` ok; `POP {PC}` faz
interworking/EXC_RETURN — já coberto pelo intercept de B7.1).

## Não inclui

ARMv8-M, MPU, FP extension (FPCA/CONTROL bit 2), sleep-on-exit, WIC.

## Testes mínimos

1. MRS/MSR de cada SYSm da tabela (ida-e-volta; CONTROL.SPSEL trocando SP ativo em
   Thread mode e IGNORADO em Handler mode — B5.2.3).
2. CPSID i → PRIMASK=1 (e não o CPS A-profile); com preset A-profile o
   comportamento antigo intacto (regressão B1.5/B2.5).
3. ARMV6M rejeita (UNDEFINED) um `LDR.W` e um `ADD.W`; ARMV7M os aceita.
4. `SVC` em ARMV6M entra pela exceção M (não SwiDispatcher).
5. G2/G3: presets A-profile inalterados (diff de features vazio em teste que
   enumera as features de ARMV4T/V5TE/V6K/V6K_THUMB2/ARMV7A).

## Armadilhas

- `THUMB2` no ARMV6M é só o mecanismo de fetch 32-bit; NÃO significa "Thumb-2
  completo" — o javadoc do preset deve explicar isso para ninguém "consertar"
  depois plugando os decoders largos.
- MSR APSR (SYSm 0-3): escreve SÓ NZCVQ (e GE se DSP) — nunca IPSR/EPSR.
- A escrita de CONTROL em Thread mode com SPSEL 0→1 troca o `registers[13]` ativo
  na hora (swap com o shadow) — mesmo cuidado da armadilha de B7.2.

## Resultado

✅ (2026-07-23) — `IrOp.MProfileSystemRegister` (kind 54) + `InstructionKind.MPROFILE_MRS`/`MPROFILE_MSR` novos: `MRS`/`MSR` na forma SYSm (número de registrador especial), distinta da forma A-profile CPSR/SPSR+máscara que continua em `PsrTransfer`. `Thumb2MiscDecoder` ganha ramo M-profile em `decodeMrs`/`decodeMsr` gateado por `ArmFeature.M_PROFILE` (com M_PROFILE, `lo[7:0]` deixa de precisar ser zero e vira SYSm; sem ela, comportamento A-profile bit a bit intacto, G3); SYSm fora da tabela → UNDEFINED, e BASEPRI/BASEPRI_MAX/FAULTMASK (17/18/19) gateados no decode pela feature nova `ArmFeature.M_FAULT_MASKING` (ausente no v6-M). `ThumbDecoder` ganha o `CPS` de 16 bits (`0xB660` T1, encoding NOVO — não existia em A nem M antes) gateado por `M_PROFILE`, reusando `InstructionKind.CPS`/`IrOp.ChangeProcessorState` (empacotamento idêntico ao CPS ARM/Thumb-2); `CPS f` exige `M_FAULT_MASKING`. Executor: `IrSystemExecutor.executeMProfileSystemRegister` delega a dois métodos novos do `MProfileExceptionModel` (`readSystemRegister`/`writeSystemRegister`, tabela SYSm completa: APSR/IAPSR/EAPSR/XPSR compõem NZCVQ+GE do CPSR + IPSR; IPSR/EPSR/IEPSR RAZ/WI na escrita; MSP/PSP via `readMsp`/`writeMsp`/`readPsp`/`writePsp` novos com a regra de "SP ativo vs sombra"; PRIMASK/BASEPRI/FAULTMASK/CONTROL; BASEPRI_MAX só abaixa o limite; EPSR modelado como 0), e `executeChangeProcessorState` ganha ramo M-profile (CPS toca só PRIMASK/FAULTMASK, ignora A/modo) ANTES do caminho A-profile. Estado novo no modelo: `basepri`/`faultmask` (armazenamento simples, NÃO integrados à preempção — documentado, fica p/ task futura, mesmo padrão do SHCSR inerte da B7.3). Wiring dos switches exaustivos: `IrBlockExecutor` (2 pontos), `AsmNativePolicy` (→ false, interpretado), `DeadCodeEliminationPass` (regUse/regDef: MSR lê o reg ARM fonte, MRS escreve o reg ARM destino — correção real de DCE, não cosmética), `StandardIrBlockLifter.isTerminal` (não-terminal). Presets `ARMV6M` (Thumb-1 + só Misc/Branch de 32 bits — v6-M NÃO tem Thumb-2 largo, `THUMB2` aqui é só o fetch) e `ARMV7M` (Thumb-2 completo + divide/bitfield + `M_FAULT_MASKING`; **sem VFP**, fora de escopo). 21 testes novos (`MProfileSystemRegisterTest` 13 fim-a-fim via `core.step()` incl. G1 interp×ASM; `ArmArchitectureMProfilePresetsTest` 8: v6-M rejeita LDR.W/ADD.W que v7-M aceita, gating SYSm/CPS-f, SVC entra pela exceção M, e diff de features vazio nos presets A-profile). Suítes arm-jitter (core 868 + truffle 13) + gbaemu (240) + ndsemu (183) verdes (G5). **Desvio documentado**: o `CPS` de 16 bits foi implementado via reuso de `InstructionKind.CPS`+`ChangeProcessorState` (opção (b) do plano) em vez de IR nova, roteando por `exceptionModel instanceof MProfileExceptionModel` no executor — mais simples e zero duplicação de semântica
