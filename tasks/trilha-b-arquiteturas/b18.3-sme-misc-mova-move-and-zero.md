### Os encodings reais

**Misc** — `ZERO` de tiles por máscara de 8 bits, e `ZERO ZT0`:

```
ZERO            11000000 00 001 00000000000 imm:8
ZERO_zt0        11000000 01 001 00000000000 00000001
```

**`MOVA` tile↔vetor, predicada** (`&mova_p esz rs pg zr za off v:bool`) — 5 linhas por direção,
uma por `esz` (`B`/`H`/`S`/`D`/`Q`), com o campo `za` (índice do tile) encolhendo e o `off`
(índice da slice) crescendo conforme o elemento diminui:

```
%mova_rs        13:2 !function=plus_12
&mova_p         esz rs pg zr za off v:bool

MOVA_tz         11000000 00 00000 0 v:1 .. pg:3 zr:5 0 off:4  \
                &mova_p rs=%mova_rs esz=0 za=0
MOVA_tz         11000000 01 00000 0 v:1 .. pg:3 zr:5 0 za:1 off:3  \
                &mova_p rs=%mova_rs esz=1
...
MOVA_tz         11000000 11 00000 1 v:1 .. pg:3 zr:5 0 za:4  \
                &mova_p rs=%mova_rs esz=4 off=0
```

`MOVA_zt` é o espelho (array → vetor), com `zr` no fim do padrão. **`v:1` é o eixo**: `0` =
slice horizontal, `1` = slice vertical. `rs` é `bits[14:13] + 12`, ou seja o registrador de
propósito geral `W12`-`W15` que fornece o índice dinâmico da slice.

**`MOVA` multi-vetor (SME2)** — `&mova_t` (sem predicado, 2 ou 4 vetores) e `&mova_a` (tile↔array
vector):

```
&mova_a         rv zr off
&mova_t         esz rs zr za off v:bool
%mova_rv        13:2 !function=plus_8

MOVA_tz2        11000000 00 00010 0 v:1 .. 000  zr:4 0 00      off:3  &mova_t rs=%mova_rs esz=0 za=0
MOVA_zt4        11000000 00 00011 0 v:1 .. 001 000      off:2 zr:3 00 &mova_t rs=%mova_rs esz=0 za=0
MOVA_az2        11000000 00 00010 00 .. 010 zr:4  000 off:3          &mova_a rv=%mova_rv
MOVA_za4        11000000 00 00011 00 .. 011 00 off:3 zr:3 00         &mova_a rv=%mova_rv
```

Note `%mova_rv = bits[14:13] + 8` (`W8`-`W11`) — **registrador-base DIFERENTE** de `%mova_rs`
(`W12`-`W15`). Os 10 mnemônicos da seção: `MOVA_tz`, `MOVA_zt`, `MOVA_tz2`, `MOVA_zt2`,
`MOVA_tz4`, `MOVA_zt4`, `MOVA_az2`, `MOVA_az4`, `MOVA_za2`, `MOVA_za4`.

**Move and zero (`MOVAZ`, SME2.1)** — 5 mnemônicos, 15 encodings: lê do array **e zera a origem**
na mesma instrução:

```
MOVAZ_za2       11000000 00000110 0 .. 01010 off:3 zr:4 0    &mova_a rv=%mova_rv
MOVAZ_za4       11000000 00000110 0 .. 01110 off:3 zr:3 00   &mova_a rv=%mova_rv
MOVAZ_zt        11000000 00 00001 0 v:1 .. 0001 off:4 zr:5   &mova_t rs=%mova_rs esz=0 za=0
MOVAZ_zt2       11000000 00 00011 0 v:1 .. 00010 off:3 zr:4 0 &mova_t rs=%mova_rs esz=0 za=0
MOVAZ_zt4       11000000 00 00011 0 v:1 .. 001100 off:2 zr:3 00 &mova_t rs=%mova_rs esz=0 za=0
```

### Como o QEMU traduz (medido por `WebFetch` de `translate-sme.c`)

```c
static bool do_mova_tile(DisasContext *s, arg_mova_p *a, bool to_vec)
{
    t_za = get_tile_rowcol(s, a->esz, a->rs, a->za, a->off, 1, 0, a->v);
    t_zr = vec_full_reg_ptr(s, a->zr);
    t_pg = pred_full_reg_ptr(s, a->pg);

    if (a->v) { /* Vertical */
        zc_fns[a->esz](t_zr, t_za, t_pg, t_desc);
    } else {    /* Horizontal */
        h_fns[a->esz](t_zr, t_za, t_zr, t_pg, t_desc);
    }
}
```

e o endereçamento:

```c
static TCGv_ptr get_tile_rowcol(DisasContext *s, int esz, int rs,
                                int tile, int imm, int div_len,
                                int vec_mod, bool vertical)
{
    /* Computes (Rs+imm) MOD (svl >> esz) for indexing */
    len = ctz32(streaming_vec_reg_size(s) / div_len) - esz;
    offset = tile * sizeof(ARMVectorReg) + offsetof(CPUARMState, za_state.za);
}
```

Dois fatos que a implementação tem que copiar: **o índice de slice é `(W<rs> + imm) MOD (SVL >>
esz)`** (módulo, não saturação nem exceção), e **os caminhos horizontal e vertical são funções
diferentes** — de `sme_helper.c`: *"Recall that `ZAnH.D[m]` is spread across `ZA[n+8*m]`, so each
row is discontiguous within `ZA[]`"* (horizontal = `memcpy` contíguo; vertical = passo por
`tile_vslice_offset()`).

## Objetivo

`ZERO`, `ZERO ZT0`, as 10 formas de `MOVA` e as 5 de `MOVAZ` decodificam sob `FEAT_SME`
(`FEAT_SME2`/`FEAT_SME2p1` para as formas multi-vetor e `MOVAZ`) e executam contra o banco `ZA` da
B18.1, em modo streaming (B18.2). `docs/COBERTURA-ISA.md`: 47 células do grupo `sme.decode` saem de
`❌`.

## Inclui

1. **Endereçamento de tile/slice reutilizável** — um utilitário (não código inline espalhado)
   que, dado `esz`, `tile`, `off`, `W<rs>` e `v`, devolve a slice de `ZA`: horizontal ou vertical,
   com o índice `(W<rs> + off) MOD (SVL >> esz)`. **É a peça que B18.4/B18.5/B18.9+ reusam** — se
   ela nascer embutida no executor de `MOVA`, o épico inteiro paga.
   Naming obrigatório (G6) para os deslocamentos `+12`/`+8` de `%mova_rs`/`%mova_rv`.
2. **Decode das 47 linhas**, com a disciplina de que o par (`esz`, largura de `za`, largura de
   `off`) é **transcrito do `.decode`**, não gerado por loop (ver Armadilha 3).
3. **Execução**:
   - `ZERO imm8` — cada bit de `imm` zera um tile (a correspondência bit→tile **depende de `esz`**
     e é regra arquitetural: medir, não deduzir);
   - `MOVA` predicada (`&mova_p`): elemento com predicado falso **não é escrito** (merging), nos
     dois sentidos;
   - `MOVA` multi-vetor (`&mova_t`/`&mova_a`): 2 ou 4 vetores consecutivos, sem predicado;
   - `MOVAZ`: lê e zera a origem — o zeramento é da **slice inteira**, não só dos elementos lidos
     (confirmar contra o manual).
4. **Gates**: `SCALABLE_MATRIX_EXTENSION` para `ZERO`/`MOVA_tz`/`MOVA_zt`; `..._2` para as formas
   `x2`/`x4` e `ZERO_zt0`; `..._2_1` para `MOVAZ` — **confirmar cada uma** contra o QEMU
   (`dc_isar_feature(aa64_sme2, s)` / `aa64_sme2p1`), e ver Armadilha 5.
5. **Checagem de acesso** (`sme_za_enabled_check` equivalente da B18.1) em toda instrução que toca
   `ZA`; `ZERO_zt0` usa a checagem de `ZT0`.
6. Testes (ver Aceite).

## Aceite

- As **47** células de `sme.decode` correspondentes saem de `❌` em `docs/COBERTURA-ISA.md`
  (conferir o delta exato, e que **nenhuma outra** célula mudou — o achado da B15.2 é o
  precedente: máscara larga demais acende células de tasks futuras por engano).
- **Ida e volta**: escrever um padrão em `Z<n>`, `MOVA` para uma slice de tile, `MOVA` de volta
  para `Z<m>`, e comparar — para **cada** `esz` (`B`/`H`/`S`/`D`/`Q`) e para **ambos** os eixos
  (`v=0` e `v=1`). É o teste que pega erro de layout vertical.
- **Horizontal ≠ vertical**: um teste que escreve por slice horizontal e lê por slice vertical
  mostra a transposição real (não o mesmo valor) — sem ele, um bug de "vertical implementado como
  horizontal" passa despercebido.
- **Índice modular**: `W<rs>` com valor maior que `SVL >> esz` acessa a slice
  `(W<rs> + off) MOD (SVL >> esz)`, não estoura e não levanta exceção.
- **`rs` é `W12`-`W15` e `rv` é `W8`-`W11`** — teste que grava valores diferentes em `W8` e `W12` e
  confirma que cada família lê o registrador certo (Armadilha 2).
- Predicado falso não escreve (merging), nos dois sentidos.
- `MOVAZ` zera a origem; ler duas vezes a mesma slice devolve zero na segunda.
- Testado em **pelo menos dois `SVL`** (256 e 512) — a disciplina VLA herdada da RFC B17.2.
- Sem `FEAT_SME`, as 47 continuam `UNIMPLEMENTED` (G8/G3).
- `mvn -o test` verde + G5 verde nos 5 consumidores.

## Armadilhas

1. **O layout vertical é descontíguo por construção.** `sme_helper.c` avisa: *"ZAnH.D[m] is spread
   across ZA[n+8*m]"*. Implementar a slice vertical como "a horizontal com índices trocados" só
   funciona se o array subjacente for realmente bidimensional; num `long[]` plano é preciso o passo
   correto por `esz`. **Este é o bug mais provável da task**, e o teste "horizontal ≠ vertical" do
   Aceite existe exatamente para pegá-lo.
2. **São DOIS registradores-base diferentes.** `%mova_rs = bits[14:13] + 12` (`W12`-`W15`) para as
   formas predicadas/`_t`; `%mova_rv = bits[14:13] + 8` (`W8`-`W11`) para as formas `_a`. Os mesmos
   dois bits do encoding, bases diferentes. Um único helper "lê o registrador de slice" com a base
   errada corrompe metade da família silenciosamente.
3. **Transcrever, não gerar.** As larguras de `za`/`off` por `esz` **não** seguem uma fórmula
   uniforme entre as famílias: compare `MOVA_tz4` (`esz=2` ⇒ `za:2`, `off=0`) com `MOVA_tz2`
   (`esz=2` ⇒ `za:2`, `off:1`). O mesmo achado que a B17.16 registrou para as unárias predicadas —
   gerar por loop produz encodings errados que só um golden corpus pega.
4. **`ZERO imm8` não é "zera 8 tiles fixos".** A correspondência bit→tile depende de `esz` (com
   `esz=0` há 1 tile de bytes; com `esz=3` há 8 tiles de doublewords), e é regra arquitetural.
   Medir contra o manual/`helper_sme_zero`; implementar "bit `i` zera tile `i`" sem conferir é
   corrupção silenciosa de estado (G8 aplicado a dado, não a encoding).
5. **Gate por feature fatiada.** As formas `x2`/`x4` são `FEAT_SME2` e `MOVAZ` é `FEAT_SME2p1` — se
   a B18.1 tiver declarado só `SME`/`SME2`, **parar e resolver lá**, não improvisar aqui. Declarar
   tudo sob `FEAT_SME` faz um preset ARMv9.2-A prometer instruções ARMv9.4-A+.
6. **`SVL`, nunca `VL`.** Todo laço de lane tem que usar `streamingVectorLengthBytes()`. Um
   `grep -n "128"` (e por `vectorLengthBytes`) nos arquivos novos é item de Aceite informal.
7. **G8 no espaço de decode**: o prefixo `11000000` (`0xC0...`) cobre muito mais do que as 47
   linhas desta task — o resto do épico mora lá. Garantir que o que não bate nas 47 continua
   caindo em `UNIMPLEMENTED`, não numa delas por máscara frouxa.
