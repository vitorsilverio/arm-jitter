# B20.2 — Perfil R: registradores de MPU no CP15 (PMSAv7) — `MPUIR`/`RGNR`/`DRBAR`/`DRSR`/`DRACR`

**Trilha:** B · **Repo:** arm-jitter (+ revalidação G5) · **Depende de:** B20.1
**Épico:** `b20-plano-perfil-r.md` · **Status:** ⬜ (spec escrita 2026-09-14, ainda não executada)

## Contexto

B20.1 criou o preset `ARMV7R` e as features `R_PROFILE`/`PMSA`, sem nenhum modelo de memória. Esta
task cria o **banco de registradores da MPU** e o `CoprocessorBus` que o expõe a `MCR`/`MRC` — o
estado que a B20.3 (`PmsaAddressSpace`) vai LER para decidir permitir/negar cada acesso. Aqui
ninguém checa nada ainda: é só estado + a via de programação.

O precedente estrutural é o `Cp15VmsaCoprocessor` (B4.1.2, RFC-SOFTMMU decisão 4): composição, não
herança; o hospedeiro instala o bus via `ArmCore#setCoprocessorBus` e encadeia outro bus decorator
para o que não for MPU (`handles()` decide).

### Encodings CP15 reais (medidos nesta rodada de spec, não supostos)

Confirmados contra a **ARM DDI 0406C, "CP15 c6, Memory region programming registers"**
(`developer.arm.com/documentation/ddi0406/b/System-Level-Architecture/Protected-Memory-System-Architecture--PMSA-/CP15-registers-for-a-PMSA-implementation/CP15-c6--Memory-region-programming-registers`)
e contra código real que programa a MPU de um Cortex-R: a série
[`[PATCH 01/20] ARM: add ARMv7R MPU support`](https://www.mail-archive.com/barebox@lists.infradead.org/msg51092.html)
do barebox e `arch/arm/kernel/head-nommu.S` do Linux.

| Registrador | Encoding (`p15`, opc1=0) | Papel |
|---|---|---|
| `MPUIR` | `MRC p15,0,Rt,c0,c0,4` | só leitura: quantas regiões o MPU tem |
| `RGNR` | `MCR/MRC p15,0,Rt,c6,c2,0` | índice da região que `DRBAR`/`DRSR`/`DRACR` acessam |
| `DRBAR` | `MCR/MRC p15,0,Rt,c6,c1,0` | base da região selecionada (dados/unificada) |
| `DRSR` | `MCR/MRC p15,0,Rt,c6,c1,2` | tamanho + habilitação + sub-regiões |
| `DRACR` | `MCR/MRC p15,0,Rt,c6,c1,4` | atributos de acesso (`AP`/`XN`/`TEX`/`S`/`C`/`B`) |
| `IRBAR`/`IRSR`/`IRACR` | `c6,c1,{1,3,5}` | espelho de instrução, **só** quando o MPU é separado (`MPUIR.nU=1`) — ver "Não inclui" |

Layout de bits (mesmas fontes):

- **`DRSR`**: `EN` = bit 0; `RSIZE` = bits\[5:1\]; `SRD` (Sub-Region Disable, 1 bit por
  sub-região) = bits\[15:8\]. **Tamanho da região = `2^(RSIZE+1)` bytes** — confirmado no QEMU real
  (`get_phys_addr_pmsav7` em `target/arm/ptw.c`: `rsize = extract32(drsr,1,5); rsize++; rmask =
  (1ull << rsize) - 1;`). `RSIZE = 0` é erro de guest (QEMU loga `LOG_GUEST_ERROR` e IGNORA a
  região). Mínimo arquitetural real = 32 bytes (`RSIZE=4`) — **confirmar contra o manual**.
- **`DRACR`**: `B` = bit 0, `C` = bit 1, `S` = bit 2, `TEX` = bits\[5:3\], **`AP` = bits\[10:8\]**
  (3 bits), **`XN` = bit 12**. (Confirmado nas duas fontes; note que o perfil **M** usa as MESMAS
  siglas em posições DIFERENTES — `AP` em 24, `XN` em 28 —, o que o patch do barebox trata com
  `AP_SHIFT`/`XN_SHIFT` distintos por perfil. Não copiar de código de Cortex-M.)
- **`MPUIR`**: `DREGION` = bits\[15:8\]; `IREGION` = bits\[23:16\]; `nU` = bit 0 (0 = MPU
  unificado). Só leitura.
- **`SCTLR`**: `M` = bit 0 (habilita o MPU); **`BR` = bit 17 (Background Region)** — habilita o
  mapa de fundo "default" quando nenhuma região casa, em modo privilegiado. **A posição do bit
  `BR` é a única desta tabela que não pôde ser confirmada contra duas fontes independentes nesta
  rodada de spec** (QEMU define `SCTLR_BR (1U << 17)` em `target/arm/cpu.h`); ver Armadilha 1.

## Objetivo

Um `Pmsav7MpuCoprocessor implements CoprocessorBus` (mais o banco de estado que ele programa)
permite que software real de perfil R execute a sequência canônica de configuração de MPU
(`MRC MPUIR` → laço: `MCR RGNR` / `MCR DRBAR` / `MCR DRACR` / `MCR DRSR` → `MCR SCTLR` com `M=1`)
sem cair em `UNDEFINED`, e expõe esse estado por uma API que a B20.3 consome. **Nenhuma checagem de
acesso acontece ainda.**

## Inclui

1. **`Pmsav7MpuRegisters`** (nome sugerido; pacote `memory/mpu/`, irmão de `memory/mmu/`) — o banco:
   - `regionCount` fixado na construção (vira `MPUIR.DREGION`; default sugerido **16**, o do
     Cortex-R5 — **confirmar** e deixar configurável pelo construtor);
   - arrays `drbar[]`/`drsr[]`/`dracr[]` de `regionCount` posições;
   - `rgnr` (índice corrente, com escrita fora de faixa tratada explicitamente — ver Armadilha 3);
   - `mpuEnabled` (`SCTLR.M`) e `backgroundRegionEnabled` (`SCTLR.BR`);
   - getters de leitura crua por região (`base(n)`, `sizeRegister(n)`, `accessControl(n)`) que a
     B20.3 usa — **desenhar essa API pensando no consumidor da B20.3**, não só no `MCR`.
2. **`Pmsav7MpuCoprocessor implements CoprocessorBus`** — `handles()`/leitura/escrita dos encodings
   da tabela acima, no MESMO estilo de despacho por `CRn`/`CRm`/`opc1`/`opc2` de
   `Cp15VmsaCoprocessor` (constantes nomeadas, G6 — nada de números soltos).
3. **`SCTLR` (`c1,c0,0`)** neste bus: armazenamento fiel de 32 bits com `M`/`BR` recalculados do
   estado autoritativo na leitura — **exatamente** a lição já paga pelo `Cp15VmsaCoprocessor` (o
   achado real da F3: RAZ/WI para bits sem efeito modelado quebra software que relê o próprio
   `SCTLR`). Também sincronizar o bit `V` com `ArmCore#setHighVectors`, igual ao VMSA.
4. **Gate por feature**: o bus só é útil sob um preset com `ArmFeature#PMSA`. Decidir (e documentar)
   se o gate é em tempo de construção (lançar se a arquitetura não tem `PMSA`) ou puramente
   documental — ver Armadilha 5.
5. Testes (ver Aceite).

## Não inclui

- **Qualquer checagem de permissão / `AddressSpace`** — B20.3. Esta task não decide se um acesso
  passa; só guarda o que o software escreveu.
- **`DFSR`/`IFSR`/`DFAR`/`IFAR` de PMSA** — B20.3 (é lá que nasce a falha que os preenche). Se o
  software ler esses registradores antes da B20.3, decidir aqui se o bus já os atende como
  armazenamento cru (recomendado, para não dar `UNDEFINED` gratuito) e documentar.
- **MPU separado instrução/dados** (`IRBAR`/`IRSR`/`IRACR`, `MPUIR.nU=1`) — o modelo desta escada é
  **unificado** (`nU=0`), que é o caso do Cortex-R4/R5/R7/R8 e do que Linux/barebox programam.
  MPU separado fica como task futura NOMEADA (nunca "fora de escopo"): quando entrar, o
  `PmsaAddressSpace` da B20.3 precisará de duas listas de regiões e `fetch16`/`fetch32` passam a
  consultar a de instrução.
- **TCM** (`c9`) — B20.4.
- **Cache/`c7`, TLB/`c8`** — não existem em PMSA como em VMSA; `c7` (manutenção de cache/barreiras)
  pode ser NOP/RAZ igual ao VMSA se algum software real tocar, decidir na execução.
- **PMSAv8** (`PRBAR`/`PRLAR`) — B20.7. **Não tentar generalizar** (armadilha do épico).

## Aceite

- A sequência canônica de configuração de MPU (escrever `RGNR`, `DRBAR`, `DRACR`, `DRSR` para N
  regiões; ligar `SCTLR.M`) roda num `ArmCore` com preset `ARMV7R` sem nenhum `UNDEFINED`, e cada
  registrador relê o valor escrito (round-trip fiel, incluindo bits sem efeito modelado — lição da
  F3).
- `MPUIR` é só leitura e reporta o `regionCount` configurado em `DREGION`; escrever nele não
  corrompe estado (decidir: ignorar ou `UNDEFINED` — documentar, coerente com o manual).
- `RGNR` seleciona qual entrada dos arrays `DRBAR`/`DRSR`/`DRACR` um `MCR` seguinte atinge — teste
  com pelo menos 3 regiões diferentes, provando que não há aliasing.
- Escrita de `RGNR` fora de faixa tem comportamento definido e testado (ver Armadilha 3).
- `SCTLR.M`/`SCTLR.BR` são observáveis pela API que a B20.3 vai consumir, e `SCTLR.V` continua
  ligando em `ArmCore#setHighVectors` como no VMSA.
- **Nenhuma mudança de comportamento para qualquer preset existente** (G3): o bus novo só existe se
  o hospedeiro o instalar.
- `docs/COBERTURA-ISA.md` zero-diff; `mvn -o test` verde + G5 verde nos 5 consumidores.

## Armadilhas

1. **`SCTLR.BR` (bit 17) é o único campo desta spec sem confirmação dupla** — a fonte é o
   `SCTLR_BR (1U << 17)` do QEMU (`target/arm/cpu.h`). Confirmar contra a descrição de `SCTLR` na
   seção PMSA do ARM DDI 0406C ANTES de implementar; errar o bit faz a região de background ficar
   ligada/desligada ao contrário, e o sintoma (B20.3) será "acesso permitido onde deveria abortar",
   silencioso.
2. **Não copiar layout de MPU do perfil M.** `DRACR` (perfil R) tem `AP` em \[10:8\] e `XN` em 12;
   o `RASR` do Cortex-M tem `AP` em \[26:24\] e `XN` em 28. É a mesma MPU conceitual com layouts
   diferentes — a maior parte do material na internet sobre "ARM MPU" é de Cortex-M.
3. **`RGNR` fora de faixa**: o manual define o comportamento (provavelmente UNPREDICTABLE). Uma
   implementação que indexa o array cru vira `ArrayIndexOutOfBoundsException` atravessando o core —
   decidir explicitamente (clamp, ignorar a escrita, ou lançar de forma controlada) e testar. G8
   aplicado a registrador: nunca "acontecer alguma coisa" por acidente.
4. **`RSIZE = 0` é inválido** e o QEMU real IGNORA a região inteira (não trata como tamanho 2). A
   B20.3 precisa dessa regra; decidir aqui se o banco já a normaliza (perigoso: perde round-trip
   fiel da leitura) ou se a B20.3 a aplica na hora de checar (**recomendado**).
5. **Gate por `ArmFeature#PMSA`**: a exclusão mútua PMSA×VMSA é invariante do épico. Nada impede
   fisicamente um hospedeiro de instalar `Cp15VmsaCoprocessor` e `Pmsav7MpuCoprocessor` ao mesmo
   tempo (ambos reivindicam `c1,c0,0`!) — decidir se isso é detectado (recomendado: falhar cedo e
   alto) ou apenas documentado, e registrar a decisão.
6. **G3**: `Cp15VmsaCoprocessor` **não é tocado**. Nem "refatorado para compartilhar o despacho de
   `SCTLR`" — o épico é explícito: `PmsaAddressSpace`/PMSA nascem AO LADO.

## Não fazer

- Não implementar checagem de acesso, `PmsaAddressSpace`, nem `MemoryTranslationException` de PMSA
  (B20.3).
- Não implementar `IRBAR`/`IRSR`/`IRACR` / MPU separado.
- Não implementar `PRBAR`/`PRLAR` (PMSAv8, B20.7) nem "um modelo genérico que sirva para os dois".
- Não mexer no `Cp15VmsaCoprocessor` nem em `TranslatingAddressSpace`.
