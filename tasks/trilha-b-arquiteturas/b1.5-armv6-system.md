# B1.5 — Instruções de sistema ARMv6: CPS, SRS/RFE, SETEND, hints

**Trilha:** B · **Depende de:** B1.1 · **Repo:** arm-jitter

## Contexto

Instruções que um kernel (Linux/3DS OS) usa para trocar de modo e atender interrupção.
O core já tem toda a infraestrutura de modos bancados, SPSR e entrada de exceção —
estas instruções são interfaces novas para mecanismos existentes.

## Objetivo

- `CPS` (`CPSIE`/`CPSID` + troca de modo): altera bits A/I/F do CPSR e/ou o modo,
  apenas em modo privilegiado (em USER é NOP/undefined conforme manual — conferir).
- `SRS` (store return state): empilha LR e SPSR atuais na pilha de um modo alvo, com
  os 4 modos de endereçamento (IA/IB/DA/DB) e writeback opcional.
- `RFE` (return from exception): carrega PC e CPSR da pilha, com os 4 modos.
- `SETEND` + bit E do CPSR (ver "Escopo do bit E" abaixo).
- Hints v6K (`WAIT_HINTS`): `WFI` → usar o estado HALT existente do core (`core.halt()`
  — ler como HALT/STOP funciona hoje); `WFE`/`SEV`/`YIELD` → NOP em single-core
  (javadoc explicando); `NOP` (encoding de hint) → NOP.

## Escopo do bit E (decisão de escopo — MVP)

Implementar: `SETEND` decodifica e seta/limpa o bit E do CPSR; `MRS` reflete o bit.
**Acessos de dados com E=1 (big-endian) NÃO são implementados neste MVP**: se uma
instrução de load/store executar com E=1, lançar exceção Java clara
(`UnsupportedOperationException` com mensagem citando esta task) — Linux/3DS rodam
little-endian e nunca ligam E; um jogo/SO que ligue vai falhar ALTO em vez de
corromper silenciosamente. Testar esse comportamento.

## Especificação

1. Gating: `MODE_CHANGE_INSTRUCTIONS` para CPS/SRS/RFE; `SETEND_BIG_ENDIAN_DATA` para
   SETEND; `WAIT_HINTS` para os hints. Tudo undefined nos presets v4T/v5TE (testar).
2. CPS que troca modo deve usar o MESMO caminho de troca de banco que `MSR`/exceções
   usam hoje (procurar no `core/` o método que rebanca registradores ao mudar de modo
   — reusar, não duplicar).
3. SRS escreve na pilha do MODO ALVO mesmo estando em outro modo — usar os bancos
   `setBankedRegister`-style existentes.
4. RFE carrega CPSR **inteiro** (inclusive T bit → pode trocar para THUMB e trocar
   modo) — reusar o caminho do "retorno com S via SPSR" existente.
5. IR: SRS/RFE parecem `MultipleTransfer` especializados; CPS/SETEND parecem
   `PsrTransfer`. Ler os records existentes e estender o que couber; criar novo record
   só se ficar mais claro.

## Testes mínimos

- CPS: desabilita/habilita I e F; troca SYSTEM→SVC rebancando SP/LR; em USER não
  altera nada.
- SRS/RFE: ida e volta (SRS numa pilha, RFE recupera PC/CPSR idênticos), nos 4 modos
  de endereçamento, com e sem writeback.
- RFE que retorna para THUMB (T bit) e para outro modo.
- WFI deixa o core em HALT e `setInterruptLine(true)` acorda (espelhar teste de HALT
  existente).
- SETEND: bit E visível no CPSR; load com E=1 lança a exceção clara.

## Aceite

- `mvn test` + gbaemu/ndsemu verdes; sem emissão ASM nativa (B1.6).

## Armadilhas

- SRS/RFE em USER mode são UNPREDICTABLE — tratar como undefined, com teste.
- O encoding de CPS/SRS/RFE/SETEND vive no espaço "unconditional" (cond=0b1111) do
  ARM — o decoder atual pode tratar cond=1111 de outro jeito (BLX imediato do v5 vive
  lá); ler o caminho de decode de cond=1111 ANTES de mexer.
