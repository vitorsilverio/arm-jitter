# B11.8 — quarto gate real de feature A64: `FEAT_NMI` (`MSR (immediate) ALLINT` + `MRS`/`MSR (register) ALLINT`)

**Trilha:** B · **Repo:** arm-jitter (+ revalidação G5 nos consumidores) · **Status:** ✅ fechada 2026-08-28
**Depende de:** B11.2 ✅ (fiação `Aarch64Architecture` no decoder), B11.3 ✅ (auditoria — confirmou
`ALLINT` como `ARMv8.8-A`/`FEAT_NMI`, já implementada sem gate desde B8.3/B8.17), B11.5 ✅
(`Aarch64Feature.NMI` já existe e já está mapeada em `Aarch64Architecture.ARMV8_8_A`)

## Contexto

Quarta da escada de gate real iniciada por B11.4 (`FEAT_RDM`), B11.6 (`FEAT_WFxT`) e B11.7
(`FEAT_FlagM`). Como nas anteriores, o decoder DEFAULT (`ARMv8.0-A`) hoje aceita `ALLINT`
incondicionalmente — um Cortex-A53 real (`ARMv8.0-A`) não tem `FEAT_NMI` (introduzida em
`ARMv8.8-A`), então o gate é o comportamento correto, não uma restrição nova.

Diferente das 3 anteriores (cada uma isolada num método/switch só seu), `ALLINT` tem DUAS formas de
encoding que precisam do MESMO gate, em dois métodos diferentes:

1. **`MSR (immediate) ALLINT`** — `Aarch64Decoder#decodeFlagOrPstateImmediate`
   (`Aarch64Decoder.java:4281-4285`): bloco isolado (`if (op1 == SYSTEM_INSTRUCTION_ALLINT_OP1 &&
   op2 == SYSTEM_INSTRUCTION_FLAG_MANIP_OP2_CFINV)`), sem colisão de switch com `CFINV`/`XAFLAG`/
   `AXFLAG`/`UAO`/`PAN`/`SPSel` (que vivem no `if (op1 == SYSTEM_INSTRUCTION_FLAG_MANIP_OP1)`
   anterior, `op1` diferente) — não precisa tocar nesse outro bloco.
2. **`MRS`/`MSR (register) ALLINT`** — `Aarch64Decoder#decodeSystemRegister`
   (`Aarch64Decoder.java:4443-4458`): resolve `Aarch64SystemRegisterId` via o método ESTÁTICO
   `decodeSystemRegisterId` (linha 4510-4512, sem acesso a `architecture`) e SÓ DEPOIS constrói o
   `Ir64Op.SystemRegister` — o gate entra no método de INSTÂNCIA `decodeSystemRegister`, depois de
   resolver `register == Aarch64SystemRegisterId.ALLINT`, sem mexer no método estático (mesmo
   padrão de não invadir estrutura de resolução compartilhada com `SPSEL`/`PAN`/`UAO`/`DIT`/`SSBS`/
   `TCO`, que ficam de fora desta task).

## Achados de investigação (nesta sessão)

- Corpus real (devkitA64, `-march=armv8.5-a`) tem `MSR (immediate) ALLINT` em `corpus.bin` offset
  `0x5e4` (`0xd501411f`) — usado hoje por `Aarch64DecoderCorpusTest#msrAllint` no `DECODER` default.
- A forma registrador (`MRS x6, allint` / `MSR allint, x6`) não está no corpus real — os testes
  existentes (`Aarch64PstateFieldRegistersTest#allintDecodes`) usam palavras sintéticas
  (`0xd5384306`/`0xd5184306`) construídas a partir do encoding documentado (mesmo padrão já usado
  pelas outras 6 do mesmo teste). Reaproveitar as mesmas palavras.
- `Aarch64PstateFieldRegistersTest#allSevenRoundTripIndependentlyThroughExecutor` constrói
  `Ir64Op.SystemRegister` diretamente (sem passar pelo decoder) — ortogonal ao gate, NÃO muda.

## Inclui

1. `Aarch64Decoder#decodeFlagOrPstateImmediate`: o bloco `ALLINT` (linha ~4281) só decodifica quando
   `architecture.has(Aarch64Feature.NMI)` — caso contrário, `throw unsupported(word, address)` (G8).
2. `Aarch64Decoder#decodeSystemRegister`: depois de resolver `register` via
   `decodeSystemRegisterId(...)`, se `register == Aarch64SystemRegisterId.ALLINT &&
   !architecture.has(Aarch64Feature.NMI)`, `throw unsupported(word, address)` — antes de construir o
   `Ir64Op.SystemRegister`. O método estático `decodeSystemRegisterId` não muda.
3. Atualizar `Aarch64DecoderCorpusTest#msrAllint` para esperar `UnsupportedOperationException` no
   `DECODER` default (`ARMv8.0-A`), mesmo padrão de `rmif`/`setf8`/`setf16` (B11.7).
4. Atualizar `Aarch64PstateFieldRegistersTest#allintDecodes` para esperar
   `UnsupportedOperationException` no `DECODER` default (`ARMv8.0-A`) para as duas palavras
   (`0xd5384306` MRS, `0xd5184306` MSR).
5. Teste novo `Aarch64NmiDecoderTest` (mesmo padrão de `Aarch64FlagManipulationDecoderTest`):
   decoder default rejeita as 3 palavras (`0xd501411f` do corpus real +
   `0xd5384306`/`0xd5184306` sintéticas); decoder `Aarch64Architecture.ARMV8_8_A` decodifica as 3
   corretamente (`MSR ALLINT`→`Ir64Op.SystemInstruction(PSTATE_FIELD_NOP)`, `MRS`/`MSR
   allint`→`Ir64Op.SystemRegister` com `register()==ALLINT`).
6. `mvn -o test` verde + `mvn -o install`; G5 nos 5 consumidores (nenhum usa `ARMV8_8_A`+ —
   zero-diff esperado, já que `ALLINT` não é emitida por toolchains alvo de `ARMv8.0-A`/raspi3).

## Não inclui

- Qualquer outra das 6 features restantes (`LSE`/`PAN`/`SHA3`/`UAO`/`DIT`/`FLAG_MANIPULATION_2`) —
  cada uma vira sua própria task `B11.x`. **Atenção**: `LSE` continua precisando de checagem extra
  de consumidor real antes de ser pega (ver Resultado de B11.6).
- Gatear `SPSEL`/`PAN`/`UAO`/`DIT`/`SSBS`/`TCO` na forma registrador (mesmo método
  `decodeSystemRegister`/`decodeSystemRegisterId`) — cada um é feature própria (`SPSEL` é baseline,
  sem gate; `PAN`/`UAO`/`DIT` são as próprias tasks futuras da escada; `SSBS`/`TCO` não têm
  `Aarch64Feature` dedicada catalogada ainda, fora de escopo aqui).
- Mudar `Aarch64Feature`/`Aarch64Architecture` (já existem desde B11.1/B11.5 — `NMI` já mapeada em
  `ARMV8_8_A`).
- `docs/COBERTURA-ISA.md` (o medidor por versão já reflete `ALLINT` corretamente desde B11.5 —
  gatear o decoder não muda o que já era medido para a coluna `ARMv8.8-A`+).

## Armadilhas

- Não tocar no bloco `if (op1 == SYSTEM_INSTRUCTION_FLAG_MANIP_OP1)` (linha 4268) — `CFINV`/
  `XAFLAG`/`AXFLAG`/`UAO`/`PAN`/`SPSel` (immediate) vivem lá, `op1` diferente do de `ALLINT`.
- Não tocar no método estático `decodeSystemRegisterId` nem no `if` de `SPSEL`/`PAN`/`UAO` (linha
  4498-4509) — o gate de `ALLINT` entra em `decodeSystemRegister` (instância), depois da resolução.
- `assertThrows` já importado nos dois arquivos de teste tocados (confirmar antes de usar).

## Resultado (2026-08-28)

Implementado exatamente como especificado, sem desvio:

- `Aarch64Decoder#decodeFlagOrPstateImmediate`: o bloco `ALLINT` agora começa com `if
  (!architecture.has(Aarch64Feature.NMI)) throw unsupported(word, address);` antes de devolver o
  `PSTATE_FIELD_NOP`.
- `Aarch64Decoder#decodeSystemRegister`: depois de `decodeSystemRegisterId(...)`, gate `if (register
  == Aarch64SystemRegisterId.ALLINT && !architecture.has(Aarch64Feature.NMI)) throw
  unsupported(word, address);` antes de construir `Ir64Op.SystemRegister` — método estático
  `decodeSystemRegisterId` intocado.
- `Aarch64DecoderCorpusTest#msrAllint` e `Aarch64PstateFieldRegistersTest#allintDecodes`: passam a
  esperar `UnsupportedOperationException` no `DECODER` default, com comentário citando esta task.
- `Aarch64NmiDecoderTest` novo (4 testes): default rejeita `0xd501411f` (`msr allint,#1`, corpus real
  offset `0x5e4`), `0xd5384306` (`mrs x6,allint`) e `0xd5184306` (`msr allint,x6`);
  `Aarch64Architecture.ARMV8_8_A` decodifica as 3 corretamente (`PSTATE_FIELD_NOP` para a forma
  imediata, `Ir64Op.SystemRegister` com `register()==ALLINT` para as duas formas registrador).
- `mvn -o test` verde (core+truffle) + `mvn -o install`; G5 completo nos 5 consumidores
  (`gbaemu`/`ndsemu`/`armbox`/`virtual-arm-box`/`n3dsemu`, todos `BUILD SUCCESS`, zero-diff esperado
  e confirmado — nenhum usa `ARMV8_8_A`+, e nenhum binário-alvo de `ARMv8.0-A` emite `ALLINT`). Sem
  mudança em `docs/COBERTURA-ISA.md` (o medidor por versão, desde B11.5, já classificava `ALLINT`
  como `ARMv8.8-A`; gatear o decoder não muda o que já era medido).
- **Próximo da escada B11, não pego automaticamente**: gatear qualquer uma das 6 features restantes
  (`LSE`/`PAN`/`SHA3`/`UAO`/`DIT`/`FLAG_MANIPULATION_2`), mesmo padrão desta task. `LSE` continua
  precisando de checagem extra de consumidor real antes de ser pega (ver Resultado de B11.6) — as
  outras 5 não têm esse risco conhecido.
