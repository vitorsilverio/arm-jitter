# B3.2 — Inteiro ARMv7, encodings Thumb-2 (bitfield, MLS, RBIT, SDIV/UDIV)

**Trilha:** B (épico B3) · **Depende de:** B3.1 · **Repo:** arm-jitter

## Contexto

B3.1 entregou features + IR + interpretador para o grupo inteiro v7 usando os
encodings ARM. Os MESMOS `IrOp`s têm encodings Thumb-2 (é assim que `gcc -mthumb
-march=armv7-a` os emite, e é o único jeito no perfil M — B7.4 depende disto).
Nenhuma IR nova: só decode.

## Inclui

- `SBFX`/`UBFX`/`BFI`/`BFC` Thumb-2 → estender `Thumb2DataProcessingDecoder`
  (grupo "plain binary immediate", `top5=0b11110`, `hi[9]=1` — o mesmo
  `decodePlainGroup` que hoje só conhece ADD/SUB/MOVW/MOVT; os op de bitfield são
  valores novos de `raw[24:21]`, gateados por `ArmFeature.BIT_FIELD`).
- `MLS`, `SDIV`/`UDIV`, `RBIT` → **estender os decoders criados em B2.7**
  (`Thumb2MultiplyDecoder` para o espaço `0xFB`; `Thumb2RegisterDataProcessingDecoder`
  para RBIT no espaço `0xFA`) — se B2.7 ainda não tiver sido executada, PARE e
  execute-a antes (ela cobre MUL.W/UMULL/etc., sem os quais nenhum binário Thumb-2
  real roda; esta task só adiciona os op-values v7 aos mesmos decoders). Gates:
  `MLS_MULTIPLY`, `DIVIDE`, `BIT_REVERSE`; os decoders ficam plugados onde B2.7 os
  plugou (`ARMV6K_THUMB2` — os v7 ficam inertes lá pelos gates de feature) e no
  `ARMV7A` (B3.7).
- `claimsEncodingSpace` da extensão nova cobrindo os prefixos estruturais que ela
  reconhece (padrão B2.2.2) — nota: com B2.6 o `ThumbDecoder` já trata todo candidato
  não decodificado como UNDEFINED, então isto é só documentação/consistência.

## Não inclui

- IR nova, executor, otimizador, ASM (tudo pronto em B3.1/B3.6).
- MUL/MLA/SMULL/etc Thumb-2 de 32 bits (mesmo espaço `0xFB`) — se o decode exigir
  distinguir os vizinhos, os vizinhos não implementados viram `null` (UNDEFINED via
  B2.6), NUNCA um decode parcial errado.

## Especificação

Encodings (ARM DDI 0406C A5.3; oráculo obrigatório: QEMU `target/arm/tcg/t32.decode`,
seções "Data-processing (plain binary immediate)", "Multiply, multiply accumulate,
and absolute difference", "Long multiply, long multiply accumulate, and divide",
"Data-processing (two source registers)"):

| Instr | hw1 (bits 31:16 do raw32) | hw2 | Campos |
|-------|---------------------------|-----|--------|
| `SBFX` | `1111 0011 0100 Rn` | `0 imm3 Rd imm2 0 widthm1` | lsb = imm3:imm2 |
| `UBFX` | `1111 0011 1100 Rn` | idem | |
| `BFI`/`BFC` | `1111 0011 0110 Rn` | `0 imm3 Rd imm2 0 msb` | `Rn=1111` → BFC |
| `MLS` | `1111 1011 0000 Rn` | `Ra Rd 0001 Rm` | Ra≠1111 (Ra=1111 é MUL, não decodificar aqui) |
| `SDIV` | `1111 1011 1001 Rn` | `1111 Rd 1111 Rm` | |
| `UDIV` | `1111 1011 1011 Rn` | `1111 Rd 1111 Rm` | |
| `RBIT` | `1111 1010 1001 Rm` | `1111 Rd 1010 Rm` | Rm repetido nos dois halfwords (assertar iguais; diferentes → UNDEFINED) |

UNPREDICTABLE (Rd/Rn/Rm ∈ {13,15}, `lsb+width>32`) → UNDEFINED (mesma citação
A5.3.x usada em B2.2.1).

Reuso: produza as MESMAS `DecodedInstruction`/IR que `ArmV7MediaDecoder` (B3.1)
produz — ideal: extrair para métodos estáticos package-private compartilhados
(ex. `ArmV7MediaDecoder.bitFieldExtract(rd, rn, lsb, width, signed, cond)`) em vez
de duplicar a montagem dos records.

## Testes mínimos (`Thumb2MultiplyDivideDecoderTest` + casos novos no `Thumb2DataProcessingDecoderTest`)

1. Ida-e-volta contra o encoding ARM de B3.1: mesma instrução nos dois encodings →
   mesmo estado final de CPU, registrador a registrador (o padrão "byte-a-byte contra
   o ARM clássico" que B2.5 usou para MRS/MSR).
2. Vetores concretos: os mesmos números de B3.1 (−7/2, x/0, MIN_VALUE/−1, RBIT
   palíndromo, BFI/BFC).
3. Gates: sem `BIT_FIELD`/`DIVIDE`/`MLS_MULTIPLY`/`BIT_REVERSE` → UNDEFINED (com
   `THUMB2` ativo — o gate é da feature específica, não do THUMB2).
4. G2: preset `ARMV6K` puro não decodifica nada disso.
5. Vizinho não implementado (ex. `MUL` Thumb-2 `0xFB00 F00x` com Ra=1111) → UNDEFINED
   controlado, não decode errado.

## Armadilhas

- O grupo plain-binary de `Thumb2DataProcessingDecoder` REJEITA hoje op4 fora de
  {ADD,SUB,MOVW,MOVT} devolvendo `null` — ao adicionar bitfield, mantenha a rejeição
  dos demais valores intacta.
- `imm3:imm2` do lsb Thumb-2 NÃO é contíguo no encoding (bits 14:12 e 7:6) — copie do
  t32.decode, não deduza.
- No `BFI` Thumb-2 o campo final é `msb` (como no ARM), não `widthm1` — os dois
  formatos convivem na MESMA tabela acima; não misturar.
