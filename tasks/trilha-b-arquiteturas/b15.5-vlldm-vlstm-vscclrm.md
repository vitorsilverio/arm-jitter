# B15.5 — Perfil M: `VLLDM_VLSTM` + `VSCCLRM` (lazy FP state preservation) — 6 células

**Trilha:** B · **Repo:** arm-jitter (+ revalidação G5) · **Depende de:** B15.4 (⬜), B15.3 (⬜)
**Épico:** `b15-plano-armv8m.md` · **Status:** ⬜ (spec escrita 2026-09-14, ainda não executada)

## Contexto

`b15-plano-armv8m.md` reserva as 6 células finais de `m-nocp.decode` (das 11 originais — 2 já
fechadas por B15.2, 3 por B15.3) para esta task: `VLLDM`/`VLSTM` (lazy save/restore de estado FP) e
`VSCCLRM` (limpeza de registradores em transição de segurança). A spec da **B15.2** já deixou o
terreno preparado: `Thumb2NocpDecoder` **exclui explicitamente** os dois padrões (`VLLDM_VLSTM_MASK`/
`VSCCLRM_MASK`) do `NOCP` genérico, exatamente para que esta task os capture sem conflito — ver
`Thumb2NocpDecoder.java`, comentário da Armadilha central.

### Os encodings reais (`target/isa-decode/m-nocp.decode`, já citados pela B15.2/B15.3 — reproduzidos
### aqui com o contexto que falta)

```
{
  # Special cases which do not take an early NOCP: VLLDM and VLSTM
  VLLDM_VLSTM  1110 1100 001 l:1 rn:4 0000 1010 op:1 000 0000
  # VSCCLRM (new in v8.1M) is similar:
  VSCCLRM      1110 1100 1.01 1111 .... 1011 imm:7 0   vd=%vd_dp size=3
  VSCCLRM      1110 1100 1.01 1111 .... 1010 imm:8     vd=%vd_sp size=2
  ...
}
```

- **`VLLDM`/`VLSTM`** (`l` distingue load/store): salva/restaura o banco FP completo (`S0-S31`/
  `FPSCR`) a partir do endereço em `Rn`, SEM incrementar `Rn` no encoding puro (o "lazy" do nome vem
  de um mecanismo de HARDWARE que este projeto não precisa replicar — ver Achado central). `op`
  distingue a forma "completa" (32 registradores) da forma "só os 16 primeiros" (ARMv8.1-M, quando
  só `S0-S15` existem sem o resto do banco D16-D31 lazy). Byte a byte: **6 encodings nomeados**
  (2 mnemônicos × formas), mas o `.decode` só tem 1 linha — confirmar a contagem real de células que
  `IsaCoverageReport` mede antes de assumir 2 vs 6 (ver Passos).
- **`VSCCLRM`** (2 linhas: precisão dupla `size=3` e simples `size=2`): zera um conjunto de
  registradores FP (`Vd` até `Vd+imm`) — usado na transição Non-secure→Secure para apagar
  informação residual de registradores FP que o código Secure não deveria poder ler (mesma classe de
  proteção que `BLXNS` dá para a pilha, agora para o banco FP).

### Achado central (pesquisado nesta rodada de spec — não há cópia local de `translate-m-nocp.c`
### cobrindo isto; `WebFetch` de `target/arm/tcg/translate-m-nocp.c` na B15.3 resumiu a função mas
### não transcreveu o corpo completo)

- **"Lazy" é uma OTIMIZAÇÃO DE HARDWARE, não uma semântica que este projeto precisa modelar**: no
  silício real, uma exceção NÃO salva o banco FP completo de imediato — ela reserva o espaço na
  pilha e marca `FPCCR.LSPACT=1` ("lazy state pending"), e o banco só é salvo de verdade na PRIMEIRA
  instrução FP executada pelo handler (economiza ciclos se o handler nunca usa FP). `VLLDM`/`VLSTM`
  são o par que o SOFTWARE (não o hardware) usa para completar essa troca manualmente quando
  necessário (ex. ao trocar de thread num RTOS). **Para este emulador, que não tem pipeline real, o
  jeito honesto de implementar é tratar `VLLDM`/`VLSTM` como um save/restore SÍNCRONO e completo do
  banco FP** — sem o atraso "lazy" (que só existe para economizar ciclos de hardware, irrelevante
  aqui) — desde que `FPCCR.LSPACT` nunca seja consultada em nenhum outro lugar para decidir
  comportamento observável diferente. Documentar essa simplificação com destaque.
- **`VLLDM`/`VLSTM` são as 2 exceções do bloco `m-nocp` que TOMAM UNDEF em vez de cair em `NOCP`**
  quando o coprocessador está ausente — o comentário do `.decode` diz isso: "these are the two UNDEFs
  that must take precedence over NOCP" (por chamarem `unallocated_encoding()` explicitamente). Ou
  seja: **sem FPU real (que este projeto nunca terá para perfil M, ver B15.2/B15.3), `VLLDM`/`VLSTM`
  devem ser `UNDEFINED`, NUNCA `NOCP`** — diferente de `VMSR_VMRS`/`VLDR_sysreg`/`VSTR_sysreg`
  (B15.3), que a B15.3 decidiu reusar `ArmCore.fpscr()` mesmo sem FPU real. Essa assimetria é
  arquitetural (o próprio QEMU documenta), não uma inconsistência a corrigir.

## Objetivo

`VLLDM`/`VLSTM`/`VSCCLRM` decodificam sob `ArmFeature#M_PROFILE`; ao executar, **`VLLDM`/`VLSTM`
tomam `UNDEFINED`** (mesma disciplina que a arquitetura real exige na ausência de FPU — ver Achado
central), e `VSCCLRM` (que não depende de FPU real da mesma forma — zera registradores que já
existem como armazenamento puro desde a B3.3, mesmo raciocínio do `FpscrRegister` reusado por B15.3)
zera de verdade o intervalo de registradores indicado. `docs/COBERTURA-ISA.md`: as células de
`VLLDM_VLSTM`/`VSCCLRM` saem de `❌` para `✅` (decode presente, comportamento definido — recusa
NOMEADA de `VLLDM`/`VLSTM` conta como `✅` no medidor, mesmo padrão que a B19.28 já estabeleceu para
`MSR SVCR` sem estado ZA: "trocar o `default` genérico por um `case` próprio que decodifica de
verdade e produz recusa NOMEADA e distinguível" satisfaz o medidor sem exigir semântica completa).

## Inclui

1. **Decode de `VLLDM`/`VLSTM`** — reconhece o encoding fixo (`Rn`, `l`, `op`), gateado por
   `ArmFeature#M_PROFILE`, registrado ANTES de `Thumb2NocpDecoder` na lista de
   `thumb32DecoderExtensions` (a exclusão da B15.2 já impede a COLISÃO, mas alguém ainda precisa
   decodificar de verdade — sem este decoder, o padrão cai em `UNIMPLEMENTED` genérico em vez de um
   `InstructionKind` nomeado).
2. **Executor de `VLLDM`/`VLSTM`**: produz `UNDEFINED` (via `MProfileExceptionModel`, `USAGE_FAULT`
   — mesmo mecanismo de exceção que `NOCP` já usa, mas SEM setar `UFSR.NOCP`; setar o bit correto de
   `UFSR` para UNDEF — `UNDEFINSTR`, ver ARMv7-M ARM B3.2.15) — documentar a simplificação
   "sem FPU real, sempre UNDEF" com a MESMA proeminência que B15.2/B15.3 já deram a essa decisão.
3. **Decode + executor de `VSCCLRM`** — zera os registradores FP indicados (`Vd` até `Vd+imm`,
   forma simples ou dupla por `size`) usando o armazenamento de `Aarch64FpRegisters`/o banco FP de
   32 bits que a B3.3 já criou (mesmo `ArmCore.fpscr()`/banco V que a B15.3 reusa) — **sem FPU real
   isso ainda é seguro de fazer** (zerar um registrador que existe como armazenamento puro não exige
   nenhuma semântica aritmética).
4. Testes (ver Aceite).

## Não inclui

- **Qualquer estado `FPCCR.LSPACT`/lazy stacking real** — ver Achado central; a simplificação
  "síncrono, sem FPU real → sempre UNDEF em `VLLDM`/`VLSTM`" evita precisar desse estado.
- **`VSCCLRM` interagindo com `CONTROL_S.SFPA`/`FPCCR.ASPEN`** (os predicados reais que decidem se
  `VSCCLRM` faz NOP ou zera de verdade, dependentes da Security Extension da B15.4) — se a B15.4
  estiver completa quando esta task rodar, decidir se consultar esses bits é viável nesta task ou
  fica para depois; se B15.4 NÃO estiver completa, `VSCCLRM` sempre zera (comportamento mais simples,
  documentar).
- **FPU real para perfil M** — fora de escopo do projeto inteiro por ora (mesma nota de B15.2/B15.3).
- **Emissão nativa/Truffle** — decode + interpretado apenas.

## Armadilhas

1. **Não inventar semântica de lazy stacking real** — ver Achado central; a simplificação
   "`VLLDM`/`VLSTM` sempre UNDEF sem FPU" é a única honesta sem hardware FP de verdade.
2. **`VLLDM`/`VLSTM` tomam UNDEF, não `NOCP`** — inverter isso (fazer cair em `NOCP` como qualquer
   outra instrução de coprocessador ausente) contradiz o comentário explícito do `.decode` real
   ("these are the two UNDEFs that must take precedence over NOCP") — G8 aplicado à escolha certa de
   exceção, não só à recusa de decodificar.
3. **`VSCCLRM` não deve exigir FPU real** para zerar registradores — são armazenamento puro (banco
   `V`/`S`/`D` já existe desde B3.3), zerar não é uma operação aritmética que dependa de FPU.
4. **Contagem de células**: confirmar antes de reportar "6" no `## Resultado` — pode ser 2 (um
   `Kind` por mnemônico agrupado) ou mais, dependendo de como `IsaCoverageReport` sonda campos livres
   como `op`/`size`. Não assumir o número do plano do épico sem medir (mesma disciplina que B15.2 já
   aplicou às suas próprias contagens).
5. **G3**: presets M-profile existentes não podem regredir. Rodar suíte completa.

## Não fazer

- Não implementar estado `FPCCR.LSPACT`/lazy stacking real — "Não inclui".
- Não implementar FPU real — fora de escopo do projeto inteiro por ora.
- Não decidir sozinho se `VSCCLRM` deve consultar `CONTROL_S.SFPA`/`FPCCR.ASPEN` sem a B15.4 estar
  fechada primeiro — documentar a dependência, não antecipar.
