### Achados desta rodada de spec

1. **`WHILE*` NÃO está aqui.** As 12 linhas de `WHILE_lt`/`WHILE_gt`/`WHILE_ptr`/`WHILE_*_pair`/
   `WHILE_*_cnt2|4`/`PEXT_*`/`CTERM` vivem em `### SVE Integer Compare - Scalars Group`
   (linhas 874-904) e foram para a **B17.9**, que é onde a tabela normativa as põe. Elas geram
   predicado e setam NZCV — se a B17.9 for executada antes desta, o executor de predicado tem que
   existir; por isso B17.9 depende de B17.4, não o contrário.
2. **`SETFFR`/`RDFFR`/`RDFFR_p`/`WRFFR` estão aqui**, não na B17.17 (que é a task do `FFR` "de
   verdade", isto é, dos loads tolerantes a falha que o ESCREVEM). São 4 das 10 linhas do grupo
   misc. Isso é bom: o QEMU implementa `RDFFR` reusando a operação de predicado
   (`arg_rprr_s alt_a = {… .rn = FFR_PRED_NUM, .rm = FFR_PRED_NUM}`), então sai quase de graça se o
   `FFR` for o 17º predicado (decisão da B17.3).
3. **Flags NZCV de predicado têm fórmula própria** — `predtest`, confirmado por `WebFetch` em
   `sve_helper.c`:
   ```c
   #define PREDTEST_INIT  1
   static uint32_t iter_predtest_fwd(uint64_t d, uint64_t g, uint32_t flags) {
       if (likely(g)) {
           if (!(flags & 4)) {
               flags |= ((d & (g & -g)) != 0) << 31;   /* N = primeiro elemento ativo */
               flags |= 4;
           }
           flags |= ((d & g) != 0) << 1;               /* "Z" (invertido: algum ativo) */
           flags = deposit32(flags, 0, 1, (d & pow2floor(g)) == 0);  /* C = último inativo */
       }
       return flags;
   }
   ```
   Ou seja: **N** = "primeiro elemento ativo do resultado é 1" (`First`), **Z** = "nenhum elemento
   ativo é 1" (`None`, e o bit acumulado é o INVERSO), **C** = "último elemento ativo é 0"
   (`!Last`), **V** = 0 sempre. É a semântica de `PTEST` e de todas as formas com `s:1` (`S`).
   **Transcrever essa função** (e a variante `_bwd`, para `PNEXT`/operações que varrem de trás) é o
   coração desta task.
4. **`PTRUE_cnt`/`CNTP_c`/`%pnd`/`%pnn` são SVE2.1** (predicado-como-contador, `PN8`-`PN15`:
   `%pnd 0:3 !function=plus_8`). São um **estado diferente** de `P0-P15` — um predicado-como-contador
   não é uma máscara de bits, é um par (contagem, invertido). Ver Armadilha 4.

## Objetivo

As 40 células de predicado saem de `❌` (medidas a partir da B17.26) e o projeto ganha o substrato
`PredicateOps` (lógica, `predtest`/NZCV, partition break, contagem) que as 21 tasks seguintes usam.

## Inclui

1. **Lógica de predicado** (8) — `AND`/`BIC`/`EOR`/`SEL`/`ORR`/`ORN`/`NOR`/`NAND`, todas com
   predicado governante `pg` e sufixo `S` (`s:1`) opcional que seta NZCV por `predtest`.
   ⚠️ `EOR_pppp` com `pg = Pd` e `s=1` é o alias `NOTS`; `ORR_pppp` com `rn == rm == pg` é `MOV`.
   Aliases não precisam de `Kind` próprio — mas o executor tem que produzir o resultado certo.
2. **Misc** (10) — `PTEST`, `PTRUE` (com os 32 padrões `pat:5`: `POW2`, `VL1`..`VL256`, `MUL4`,
   `MUL3`, `ALL`), `PTRUE_cnt`, `PFALSE`, `SETFFR`, `RDFFR`, `RDFFR_p`, `WRFFR`, `PFIRST`, `PNEXT`.
3. **Partition break** (7) — `BRKA`/`BRKB` (zeroing e merging), `BRKPA`/`BRKPB`, `BRKN`.
4. **Contagem por predicado** (9) — `CNTP`, `CNTP_c`, `FIRSTP`, `LASTP`, `INCDECP_r`/`_z`,
   `SINCDECP_r_32`/`_r_64`/`_z`.
5. **Element count** (6) — `CNT_r` (`CNTB`/`CNTH`/`CNTW`/`CNTD`), `INCDEC_r`, `SINCDEC_r_32/_64`,
   `INCDEC_v`, `SINCDEC_v`. Todas leem o `VL` que a B17.3 expõe e o padrão `pat:5`.
6. **`SvePredicateOps`** (nome sugerido) — a classe utilitária com `predtest` (fwd e bwd), o
   decodificador de `pat:5` → número de elementos e as primitivas de leitura/escrita de bit de
   predicado por `esz`. É o substrato compartilhado; **cada operação em UM lugar só** (mesma
   disciplina da RFC B13.2/D1).
7. Testes (ver Aceite).

## Não inclui

- **`WHILE*`/`CTERM`/`PEXT`** — B17.9 (ver Achado 1).
- **Loads/stores de predicado** (`LDR_pri`/`STR_pri`) — B17.17/B17.18.
- **Permutação de predicado** (`ZIP1_p`/`PUNPKLO`/`REV_p`) — B17.11.
- **`PSEL`** (broadcast predicate element) — B17.22.
- **Qualquer load que ESCREVE o `FFR`** (`LDFF1`/`LDNF1`) — B17.17.
- **Emissão nativa/Truffle** — padrão da trilha B.

## Armadilhas

1. **`predtest` não é "compare com zero".** N/Z/C têm significado de `First`/`None`/`!Last` sobre os
   elementos **ativos** (mascarados por `pg`), e `V` é sempre 0. Implementar como flags aritméticas
   normais é um bug silencioso que só aparece em loop VLA real.
2. **`PTRUE` com padrão maior que o `VL` produz predicado TODO ZERO, não exceção.** Ex.: `PTRUE
   p0.b, VL256` com `VL=128` ⇒ nenhum elemento. Tratar como UNDEF quebra código VLA legítimo (é
   justamente assim que o software descobre o `VL`).
3. **`P<n>` é bit-por-BYTE, não bit-por-elemento.** Para `esz>0` só o bit do byte MAIS BAIXO de cada
   elemento é significativo; os demais têm que ser escritos como 0 pelas operações que geram
   predicado, e ignorados pelas que consomem. Errar isso faz `CNTP` contar múltiplo do valor certo.
   (O `expand_pred_s` do QEMU — `[0x01] = 0x00000000ffffffffull` — é a evidência do layout.)
4. **`PTRUE_cnt`/`CNTP_c` são predicado-como-contador (SVE2.1), estado DIFERENTE.** `%pnd 0:3
   !function=plus_8` mostra que o destino é `PN8`-`PN15`, e a codificação é uma contagem, não uma
   máscara. Se a B17.3 não modelou isso, esta task tem duas saídas honestas: (a) modelar o
   predicado-como-contador aqui (escopo maior, documentar) ou (b) deixar essas 2 linhas
   **explicitamente não implementadas**, devolvendo `null` no decoder (`❌` honesto, G8) e
   registrando-as como pendência nomeada desta task. **Não** decodificá-las como `PTRUE`/`CNTP`
   comuns — é o misdecode silencioso que o G8 proíbe.
5. **`BRKA_m`/`BRKB_m` usam `@pd_pg_pn_s0` (`s=0` forçado)** e têm `esz` FIXO no padrão
   (`00`/`10`), diferente de `BRKA_z`/`BRKB_z` (`0.`/`1.`). O bit 22 aqui **não** é `esz` — é parte
   do opcode. Ler o padrão literal, não presumir o layout comum.
6. **`SETFFR`/`RDFFR`/`WRFFR` não têm campo `esz`** — são encodings totalmente fixos. O medidor os
   sonda com os bits fixos; um decoder que exija `esz` os recusa.
7. **`PFIRST` é `@pd_pn_e0`** (esz fixo 0) e `PNEXT` é `@pd_pn` (esz variável) — e as duas são
   destrutivas (`Pdn`). Conferir no manual qual registrador é lido/escrito.

## Não fazer

- Não implementar `WHILE*`/`CTERM`/`PEXT` (B17.9) nem `PSEL` (B17.22).
- Não implementar nenhum load/store (B17.17/B17.18).
- Não decodificar `PTRUE_cnt`/`CNTP_c` como se fossem predicado-máscara (Armadilha 4).
- Não espalhar `128`/`16` como tamanho de predicado — vem do `VL` (G6).

## Resultado

**Fechada em 2026-09-25.** 38 dos 40 encodings decodificam e executam; as 2 exceções são pendências nomeadas
(abaixo), recusadas em vez de misdecodificadas (G8). `docs/COBERTURA-ISA.md` **inalterada** (zero-diff medido:
`sve.decode` segue `NOT_IN_ANY_PRESET` até a B17.26); `docs/COBERTURA-JIT.md` ganhou os 5 `Kind` novos (152 → 157).

**O que foi feito**

- `decoder64/Aarch64SveDecoder` (novo, package-private, gate `Aarch64Feature.SVE`): as linhas de `sve.decode` transcritas
  em `máscara`/`valor` (bits fixos de cada linha), conferidas contra `aarch64-none-elf-as -march=armv9.4-a+sve2p1`.
  `Aarch64Decoder` roteia a classe `bits[28:26]=001` para ele; o que não bate devolve `null` → `unsupported` (G8).
- `ir64/Ir64Op`: 5 records (`SvePredicateLogical`, `SvePredicateMisc`, `SvePartitionBreak`, `SvePredicateCount`,
  `SveElementCount`; `Kind` 152-156), cada um com um `enum Op` interno (as 40 linhas colapsam em 5 `Kind`).
- `executor64/SvePredicateOps` (novo) — o substrato do épico: predicado como `long[]` com **um bit por byte do vetor**,
  `predTest` (transcrição de `iter_predtest_fwd`: N = primeiro ativo, Z = nenhum ativo verdadeiro, C = último ativo falso,
  V = 0), `decodePredCount` (`pat:5`), `saturate32`/`saturate64`/`updateVector`, `elementOf`/`setElementOf` (elemento de `Z`).
  Sempre no `VL` **efetivo** do core (`vectorLengthBytes()`), então serve `VL` 256/512 e o `SVL` em modo streaming.
- `Aarch64Feature.SVE2_2` (`FEAT_SVE2p2`, nenhum preset a declara): gate de `FIRSTP`/`LASTP`.
- Acesso: `sveAccessCheck` (`EC=0x19`) fora do streaming, `smeEnabledCheck` em streaming (`aa64_sme_or_sve`);
  `SETFFR`/`RDFFR`/`RDFFR_p`/`WRFFR` são `UNDEFINED` em streaming sem FA64 (`TRANS_FEAT_NONSTREAMING` do QEMU).

**Achados que a spec não trazia** (todos conferidos no `sve_helper.c`/`translate-sve.c` do QEMU, revisão fixada)

1. **`PTRUES` seta flags diferente de `PTEST`**: `N = (count ≠ 0)`, `Z = (count = 0)`, `C = (count = 0)`, `V = 0` — a máscara
   do teste é o próprio resultado, não `Ones` (`do_predset`). `PredTest(Ones, resultado)` daria `C=1` em `PTRUE .., VL1`.
2. **`BRKN`/`BRKNS` usam `PredTest(Ones(PL), Pdm)`** (não `Pg`) quando o último elemento ativo de `Pn` é verdadeiro; senão
   zeram `Pdm` e as flags são as de predicado vazio (`N=0 Z=1 C=1`).
3. **`PNEXT` NÃO mascara `Pdn` por `Pg`** ao achar o último elemento verdadeiro (`last_active_element(vd)` usa só a máscara
   de `esz`); só a BUSCA do próximo é restrita a `Pg`.
4. **`SEL` com `S=1` não está alocado** (`trans_SEL_pppp`: `if (a->s) return false`) — o `.decode` deixa o bit livre.
5. **`FIRSTP`/`LASTP` não são SVE base** (`aa64_sme2p2_or_sve2p2`): entram atrás de `Aarch64Feature.SVE2_2`.
6. Elemento vetorial `INCP`/`SQINCP`/`INCH`/… com `esz=0` é não alocado; `SINCDEC_r_32` com quantidade `0` ainda
   estende (`ext32s`/`ext32u`) o `Wn` — testado.
7. `RDFFR_p` (`0x25..`) e `RDFFR` (`0x2519f0..`) diferem no bit 16 — a máscara de `RDFFR_p` fixa `21:9`, não só o prefixo.

**Pendências nomeadas (nada excluído)**

- **`PTRUE_cnt` (`0x25207810` = `ptrue pn8.b`) e `CNTP_c` (`0x25208301`)** — predicado-como-contador (SVE2.1, `PN8`-`PN15`), um
  estado que NÃO é máscara de bits (Armadilha 4). Recusadas (`UnsupportedOperationException`), testadas como recusa. Entram
  quando o estado predicado-como-contador for modelado (a B17.25 e a B18.12 já o citam como dependência).
- SME **sem** SVE (nenhum preset assim hoje): o decoder exige `FEAT_SVE`; SVE em streaming num core só-SME entra junto com esse preset.
- `CPACR_EL1.FPEN` não é checado (só `ZEN`, como na B17.3).

**Testes** (`Aarch64SvePredicateTest`, 194 casos, `VL` 256 **e** 512): decode por grupo; recusa sem `FEAT_SVE`
(`ARMV8_0_A`/`ARMV8_5_A`); os casos não alocados/pendentes; `FIRSTP`/`LASTP` só com `SVE2_2`; lógica de predicado (7 operações
× com/sem `S`, rodadas aleatórias contra um oráculo escrito em separado, incl. `SEL`); tabela de `PTEST`; `PTRUE`/`PTRUES` com os
32 padrões × 4 `esz` × 2 `VL` (+ contagens calculadas à mão: `VL64` em `VL256` ⇒ predicado VAZIO, nunca exceção);
`SETFFR`/`RDFFR`/`WRFFR`; `PFIRST`/`PNEXT` (percorre cada elemento ativo uma vez, por `esz`); `BRK*` (after/before,
zeroing/merging, `BRKP*`, `BRKN*`); `CNTP` ignora bytes que não são o mais baixo do elemento; `INCP`/`DECP`; saturação

`UNDEFINED` em streaming; o mesmo bloco pelo `StandardIr64BlockLifter` + `executeBlock`. Mutação de sanidade (inverter `C` do
