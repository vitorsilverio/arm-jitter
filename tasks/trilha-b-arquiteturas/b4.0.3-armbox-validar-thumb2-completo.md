# B4.0.3 — Validar Thumb-2 COMPLETO no armbox (pós-B2.6, com binário de compilador)

**Trilha:** B · **Depende de:** B2.6 · **Repo:** armbox · **Fecha:** armbox#1

## Contexto

B4.0.2 validou Thumb-2 no armbox só com o subconjunto data-processing (o preset da
época). Com B2.6 fechando o preset (4 extensões + BL/BLX de 32 bits), falta a
validação de nível 3 da matriz (`docs/VALIDACAO-ARQUITETURAS.md` do arm-jitter):
**código Thumb-2 gerado por compilador**, que usa load/store de 32 bits, IT blocks
e tabelas TBB à vontade — coisas que nenhum teste sintético cobre com a mesma
malícia.

Nota: a parte handwritten (torture estendido) já entra na PRÓPRIA B2.6 (passo 6).
Esta task é o degrau seguinte: compilador real.

## Inclui

1. `testdata/hello-thumb2.c` + rotinas com switch denso (força TBB/TBH), structs
   com bitfields e um qsort pequeno (força IT + cmp/branches), compilado
   `arm-none-eabi-gcc -mthumb -march=armv6t2 -Os -static` (mesma libc/receita dos
   testdata atuais; `-Os` gera mais IT blocks). Conferir via `objdump -d` que o
   binário contém: `ldr.w`, `strd`, `ldmia.w`, `tbb`, `it`/`itt`, `bl` — anexar o
   trecho no PR como prova.
2. Se a toolchain não tiver multilib armv6t2, usar `-march=armv7-m` NÃO (é perfil
   M, ABI diferente de syscall? não — user-mode Linux é ABI EABI igual; mas v7-m
   não tem ARM mode e o _start da libc pode ser ARM) — fallback correto:
   `-march=armv7-a -mthumb` e rodar com `--arch=thumb2` só se o binário não usar
   nada v7-only (checar objdump por `sdiv/udiv/movw/movt/sbfx/ubfx/bfi/dmb`; se
   usar, esta task fica bloqueada por B3.7 e roda com `--arch=armv7a` — registrar
   qual caminho valeu).
3. `busybox` Thumb-2: baixar/buildar busybox estático compilado em Thumb-2
   (`CONFIG_EXTRA_CFLAGS="-mthumb"` ou binário musl thumb2 pronto) e rodar o
   MESMO subconjunto que B4.0 validou no ARM (echo, `sh -c`, uname).
4. `Thumb2CompilerBinaryTest`: os binários acima nos 3 backends
   (JIT/`--interp`/`--check`), stdout/exit idênticos.

## Aceite

- Binários de compilador Thumb-2 rodando idênticos nos 3 backends; instruções-alvo
  comprovadas no objdump; matriz de validação atualizada (linha ARMv6K+Thumb2,
  nível 3 ✅).

## Armadilhas

- O ponto frágil histórico é exatamente dados-que-parecem-prefixo após BL — pools
  de literais de compilador fazem isso de graça; se algo divergir, o bug
  provavelmente é do arm-jitter (B2.6), não do armbox: reduza para um `.s` mínimo
  e reporte com o par de halfwords exato em vez de contornar.
- `--check` compara interpretado×JIT a cada bloco — é o backend que MAIS pega bug
  de decode (larguras/fetch atômico); rode-o primeiro.
