# B7.2 — `MProfileExceptionModel`: MSP/PSP, xPSR, stacking automático, EXC_RETURN

**Trilha:** B (épico B7) · **Depende de:** B7.1 · **Repo:** arm-jitter
**Referência normativa:** ARMv7-M ARM (DDI 0403E), capítulo B1.5 (exception model).
**Oráculo de implementação:** QEMU `target/arm/tcg/m_helper.c` (`v7m_exception_taken`,
`do_v7m_exception_exit`, `v7m_push_stack`) — transcrever a ordem das operações de lá.

## Contexto

Coração do perfil M. Com B7.1 pronto, este é o primeiro código genuinamente novo:
o modelo de exceção M como implementação de `ExceptionModel`, mais o estado que só
o perfil M tem. Sem NVIC ainda (B7.3): as exceções são disparadas programaticamente
nos testes (`enterException` direto + `SVC`).

## Inclui

### 1. Estado novo (dentro de `core/MProfileExceptionModel.java`)

- `int mainStackPointer` / `int processStackPointer` — o R13 "ativo" continua em
  `ArmCore.registers[13]`; o modelo faz o swap no momento certo (entrada/retorno de
  exceção e escrita de CONTROL.SPSEL) e mantém o inativo aqui. Constantes nomeadas
  (G6) para tudo.
- `int control` — bits SPSEL(1), nPRIV(0) (FPCA fica para uma futura extensão FP).
- `int currentException` — o IPSR (0 = Thread mode). Handler mode ⇔ ≠0.
- `int primask` (bit 0) — mascaramento simples; BASEPRI/FAULTMASK só v7-M (B7.4
  decide expor; deixe campos prontos e documentados).
- `int vectorTableOffset` — VTOR; default 0. B7.3 o torna memory-mapped; aqui há um
  setter para os testes.
- Enum `MProfileException` (número arquitetural fixo): RESET(1), NMI(2),
  HARD_FAULT(3), MEM_MANAGE(4), BUS_FAULT(5), USAGE_FAULT(6), SVCALL(11),
  DEBUG_MONITOR(12), PENDSV(14), SYSTICK(15), externas = 16+n.

### 2. Entrada de exceção (`enterException` / nova sobrecarga com `MProfileException`)

Ordem exata (B1.5.6; espelhar `v7m_push_stack`):

1. Alinhar SP ativo a 8 bytes se necessário (bit 2 do SP vai no xPSR empilhado —
   bit 9 do frame, flag de realinhamento).
2. Empilhar 8 words no SP ativo, offsets 0..28: R0,R1,R2,R3,R12,LR,ReturnAddress,
   xPSR. ReturnAddress conforme B1.5.6 (SVC: endereço da instrução seguinte;
   HardFault síncrono: a própria instrução — tabela do manual).
3. Montar xPSR a partir do `CpsrRegister` atual: NZCVQ (31:27) + GE (19:16, se
   PARALLEL_SIMD) + ITSTATE (26:25,15:10) + T(24)=1 + IPSR atual (8:0).
4. `LR = EXC_RETURN`: `0xFFFFFFF1` (handler→handler, usa MSP), `0xFFFFFFF9`
   (thread→handler, MSP), `0xFFFFFFFD` (thread→handler, retorna a PSP).
5. Trocar para Handler: `currentException = número`, SP ativo = MSP.
6. Buscar vetor: `PC = memory.read32(vectorTableOffset + 4*número) & ~1` (bit 0
   deve ser 1 no valor lido — se 0, HardFault INVSTATE; implementar como UNDEFINED
   controlado nesta fase, anotar). Limpar ITSTATE do CPSR ativo (igual ao A-profile
   de B2.4).

### 3. Retorno (`interceptsBranch`/`branchIntercepted` — plugado nos pontos de B7.1)

`interceptsBranch(t)` = `currentException != 0 && (t & 0xFFFFFFF0) == 0xFFFFFFF0`.
`branchIntercepted`: validar os 3 EXC_RETURN válidos (outros → UNDEFINED),
selecionar a pilha, desempilhar os 8 words na ordem inversa, restaurar xPSR nos
lugares (NZCVQ/GE/IT → CpsrRegister; IPSR → currentException; bit 9 → desfazer
realinhamento), voltar Thread/Handler e SPSEL conforme o EXC_RETURN.

### 4. Ganchos de ISA (gateados por `ArmFeature.M_PROFILE`, feature nova desta task)

- `SVC` (o `Swi` Thumb existente): com M_PROFILE, vira `enterException(SVCALL)` em
  vez do caminho `SwiDispatcher` — implementar no ponto onde o executor de `Swi`
  decide o dispatch (buscar `SwiDispatcher` no executor de sistema), gateado pelo
  modelo instalado, não por if espalhado: `exceptionModel` ganha um hook
  `handlesSupervisorCall()`.
- `BX`/`BLX` para endereço com bit 0 = 0 (tentativa de modo ARM): UNDEFINED
  controlado (M-profile não tem ARM; a exceção UsageFault real chega com B7.3+).
- `CpsrRegister` write mask: em M, `MSR`-like writes não têm bits de modo — mas
  isso é assunto do decoder SYSm (B7.4); aqui só garantir que NADA no modelo M
  chama `switchMode`/bancos A-profile.

## Não inclui

NVIC/prioridades/preempção/tail-chaining (B7.3 — aqui uma exceção por vez, sem
aninhamento além de handler→handler manual nos testes), MRS/MSR SYSm e CPS
M-profile (B7.4), presets (B7.4), FP extension frame, lazy stacking, ARMv8-M.

## Testes mínimos (`MProfileExceptionModelTest` + harness)

1. Layout do frame: SVC de Thread/MSP → os 8 words nos offsets exatos, LR =
   0xFFFFFFF9, IPSR = 11, PC = vetor[11]&~1.
2. Ida-e-volta completa: Thread(PSP) → SVC → handler roda em MSP → `BX LR` →
   estado 100% restaurado (todos os 16 regs + xPSR + SPSEL), incluindo o caso com
   SP desalinhado de 4 (bit 9 do frame).
3. handler→handler (0xFFFFFFF1) e retorno em cadeia.
4. EXC_RETURN inválido (ex. 0xFFFFFFF3) → UNDEFINED controlado.
5. ITSTATE: exceção no meio de IT block → IT salvo no xPSR empilhado, zerado no
   handler, restaurado no retorno (espelho do teste SPSR de B2.4).
6. Equivalência G1: bloco com SVC + retorno rodado interpretado × ASM
   (`BlockEquivalenceHarness` com o modelo M instalado nos dois) — estado idêntico.
7. G3: nenhum teste A-profile muda; gbaemu/ndsemu verdes.

## Armadilhas

- A ordem empilhamento→troca de SP→escrita de LR importa e é fácil inverter — siga
  o `m_helper.c`, não a intuição.
- O frame usa o SP DE ORIGEM (PSP se Thread/SPSEL=1), mas o handler SEMPRE roda em
  MSP — dois SPs envolvidos na mesma entrada.
- `ReturnAddress` empilhado NÃO tem bit Thumb; o xPSR empilhado carrega T=1. No
  retorno, o T do xPSR restaurado deve ficar em EPSR (conceitual) — na prática o
  core segue Thumb sempre; T=0 restaurado → UNDEFINED controlado (INVSTATE).
- `registers[13]` ativo vs MSP/PSP shadow: TODO acesso de instrução comum a SP usa
  o ativo — o shadow só existe dentro do modelo; nunca deixe os dois divergirem
  fora de entrada/retorno/CONTROL-write.
