# B15.4 — Perfil M: Security Extension mínima (`SG`/`BLXNS`/`BXNS`/`TT`-família) — ARMv8-M

**Trilha:** B · **Repo:** arm-jitter (+ revalidação G5) · **Depende de:** B15.1 (✅ 2026-09-12)
**Épico:** `b15-plano-armv8m.md` · **Status:** ⬜ (spec escrita 2026-09-14, ainda não executada)

## Contexto

`b15-plano-armv8m.md` lista B15.4 como a introdução de `ArmFeature.M_PROFILE_SECURITY` + os presets
`ARMV8M_BASELINE`/`ARMV8M_MAINLINE`, cobrindo "banking de MSP/PSP por estado, `SG`/`BLXNS`/`BXNS`,
`TT`/`TTT`/`TTA`/`TTAT` (a `TT` já existe desde B9.11, confirmada correta por medição)". Ao contrário
de B15.2/B15.3 (que fecham células de `m-nocp.decode` a 0%), esta task **não muda nenhuma célula de
`docs/COBERTURA-ISA.md` por si só** — `TT` já é medida `✅` (B9.11 confirmou que o decoder de
`STREX`/`LDREX` já recusa corretamente o espaço que `TT` ocupa, G8 satisfeito por omissão, não por
decisão). O que esta task fecha são as 3 células REAIS ainda `❌` (`SG`, `BXNS`, `BLXNS`) e a
infraestrutura de estado seguro/não-seguro que B15.5 (`VLLDM`/`VSCCLRM`, que preservam contexto FP
condicionalmente ao estado de segurança) e B15.6/B16 (ARMv8.1-M/MVE) precisam para existir de verdade.

### Os encodings reais (medidos em `target/isa-decode/t32.decode`/`t16.decode` nesta rodada de spec)

```
# t32.decode, dentro do bloco "Load/Store Dual, Load/Store Exclusive, table branch" (linha ~561)
{
  SG             1110 1001 0111 1111 1110 1001 01111111
  LDRD_ri_t32    1110 1001 .111 .... .... .... ........    @ldstd_ri8 w=1 p=1
}

# t32.decode, dentro do bloco "Load/Store Exclusive..." (linha ~582)
{
  TT             1110 1000 0100 rn:4 1111 rd:4 A:1 T:1 000000
  STREX          1110 1000 0100 .... .... .... .... ....      @strex_i
}

# t16.decode, forma "branch and exchange" de 16 bits (linhas 193-194)
BXNS            0100 0111 0 .... 100            @branchr
BLXNS           0100 0111 1 .... 100            @branchr
```

- **`SG` (Secure Gateway)**: encoding FIXO de 32 bits (nenhum campo livre), vive no MESMO slot que
  `LDRD_ri_t32` (`w=1,p=1`) ocuparia com `Rn=Rt=Rt2=1111` — o QEMU trata como padrão mais específico
  primeiro (mesma disciplina de prioridade que `m-nocp.decode` já usa para `VLLDM`/`VSCCLRM` antes de
  `NOCP`, ver B15.2). Só válida quando executada de um endereço dentro de uma região **Non-Secure
  Callable (NSC)** do estado Secure — se encontrada em qualquer outro contexto, comporta-se como
  `UNDEFINED` (não como `SG` de verdade).
- **`TT`/`TTT`/`TTA`/`TTAT`**: UMA linha de decode, os 4 mnemônicos são a mesma instrução
  discriminada pelos bits `A`(`bit4`)/`T`(`bit5`) — `TT`=`A=0,T=0`, `TTT`=`A=0,T=1`, `TTA`=`A=1,T=0`,
  `TTAT`=`A=1,T=1`. Já **medida como correta desde B9.11** (o decoder de `STREX` não a captura por
  engano) — esta task só precisa decidir se implementa a SEMÂNTICA real (consultar SAU/IDAU/MPU e
  devolver a configuração de segurança do endereço em `Rn`) ou deixa `❌` honesto (decode ausente)
  até a infraestrutura de SAU existir (ver "Não inclui").
- **`BXNS`/`BLXNS`**: forma de 16 bits, MESMO layout de `BX`/`BLX` comuns (`@branchr` = `Rm:4`), mas
  em opcode PRÓPRIO (`0100 0111 0/1 .... 100`, não colide com `BX`/`BLX` = `0100 0111 0/1 .... 000`
  — o bit baixo do byte final distingue). `bit0` do endereço destino (não do encoding, do VALOR em
  `Rm`) seleciona a troca de estado: `bit0=0` → muda para Non-secure; `bit0=1` → permanece Secure
  (troca normal de instruction set T/A, que este projeto já trata via `bit0` em `BX`/`BLX` comuns).

### Achado central (pesquisado via QEMU real/documentação ARM, `WebSearch`/`WebFetch` — não há
### `translate-m-nocp.c` nem outro arquivo QEMU com cópia local destas instruções; a árvore completa
### de `target/arm/tcg/` não foi buscada arquivo a arquivo nesta rodada de spec)

- **`BLXNS`** não é só um branch com troca de segurança: ele **empilha uma "assinatura de
  integridade"** (`0xFEFA125A` ou `0xFEFA125B`, dependendo se há FPU ativa) na pilha ATUAL (Secure)
  antes de saltar para Non-secure — para que um `BXNS` de retorno (vindo do código Non-secure, usando
  `LR`) consiga detectar se a pilha Secure foi adulterada enquanto a CPU estava em Non-secure. Isso é
  parte da defesa central da Security Extension contra um código Non-secure malicioso manipular o
  retorno de uma chamada Secure→Non-secure.
- **`BXNS`/`BLXNS` trocam o banco de `SP`** — cada estado de segurança (Secure/Non-secure) tem seu
  PRÓPRIO par `MSP`/`PSP` (4 ponteiros de pilha no total, não 2). O `MProfileExceptionModel` deste
  projeto JÁ modela `MSP`/`PSP` como sombra do `SP` ativo por `SPSEL`
  (`core/src/main/java/dev/vitorsilverio/armjitter/core/MProfileExceptionModel.java`, linhas
  ~160-290) — esta task precisa **dobrar** essa banking: por `SPSEL` × por estado de segurança
  (`MSP_S`/`PSP_S`/`MSP_NS`/`PSP_NS`), mesmo padrão, dimensão nova.
- **`SG` limpa o bit 0 do endereço de retorno em `LR`** ao trocar para Secure — parte do protocolo
  que garante que o retorno subsequente (via `BXNS`) sempre aponta para instrução Thumb válida.

## Objetivo

`SG`, `BXNS`, `BLXNS` decodificam e executam sob `ArmFeature#M_PROFILE_SECURITY` (banking de
`SP`/`LR` por estado de segurança, troca Secure↔Non-secure, assinatura de integridade de `BLXNS`);
`ArmFeature.M_PROFILE_SECURITY` habilita os presets novos `ARMV8M_BASELINE`/`ARMV8M_MAINLINE`
(`extending(ARMV7M_PURE/ARMV7M, ...)`, G3: não mexe nos presets existentes). `TT`-família decodifica
sob a mesma feature (semântica completa fica condicionada à existência de um modelo mínimo de SAU —
ver "Não inclui"; se não houver tempo/infraestrutura, decodificar e devolver um valor conservador
documentado é aceitável, desde que não seja G8-falso). `docs/COBERTURA-ISA.md`: as 3 células (`SG`,
`BXNS`, `BLXNS`, colunas `v8-M`) saem de "não se aplica"/`❌` para `✅`; `TT` permanece `✅` (sem
mudança de célula, mas ganha semântica de execução se a spec decidir implementá-la aqui).

## Inclui

1. **`ArmFeature.M_PROFILE_SECURITY`** — feature nova, gate único para tudo desta task.
2. **Presets `ARMV8M_BASELINE`/`ARMV8M_MAINLINE`** — `extending(ARMV7M_PURE, ...)` e
   `extending(ARMV7M, ...)` respectivamente (baseline = sem DSP, mainline = com DSP, mesmo par que
   B15.1 já estabeleceu para v7-M puro vs v7E-M), cada um com `M_PROFILE_SECURITY` adicionada.
3. **Banking de `SP`/`LR` por estado de segurança** — dobra o padrão já existente de `MSP`/`PSP`
   por `SPSEL` em `MProfileExceptionModel` para também bancar por segurança (4 ponteiros de pilha:
   `MSP_S`/`PSP_S`/`MSP_NS`/`PSP_NS`). Estado de segurança corrente (`true`=Secure) como campo novo
   do core/modelo.
4. **`SG`** — decode (encoding fixo) + executor: troca para Secure, limpa `bit0` de `LR`. Sem
   verificação de região NSC de verdade nesta task (ver "Não inclui" — SAU ainda não existe); documentar
   a simplificação.
5. **`BXNS`/`BLXNS`** — decode (`@branchr`, opcode próprio) + executor: troca de estado por `bit0`
   do valor de `Rm`, troca de banco de `SP`, `BLXNS` empilha a assinatura de integridade
   (`0xFEFA125A`/`0xFEFA125B`) na pilha Secure ativa ANTES da troca.
6. **`TT`/`TTT`/`TTA`/`TTAT`** — decodificar (a única linha do `t32.decode`, discriminada por `A`/`T`);
   decidir a fundo, documentando no `## Resultado`, se a execução consulta um modelo mínimo (mesmo
   que incompleto) ou devolve um valor fixo conservador (ex. "toda região é Secure, sem MPU" — o
   comportamento mais simples que não inventa segurança que não existe).
7. Testes (ver Aceite).

## Não inclui

- **SAU (Security Attribution Unit) real** — o hardware que decide se um endereço é Secure/
  Non-secure/NSC. Sem SAU, `SG` não pode verificar de verdade se está numa região NSC (esta task
  aceita executar `SG` sempre que decodificada, documentando a simplificação) e `TT` não tem de onde
  ler a configuração real (ver Inclui item 6). SAU modelada como task própria futura se o usuário
  priorizar — B15.4 é sobre o MECANISMO de troca de estado, não sobre a política de que região é
  o quê.
- **`SAU_CTRL`/`SAU_RNR`/`SAU_RBAR`/`SAU_RLAR`** (registradores do SAU) — dependem da SAU acima.
- **`NSACR`** (Non-secure Access Control Register, que a B15.2 já tinha adiado explicitamente para
  esta task) — controla se código Non-secure pode acessar coprocessadores/FPU; só faz sentido com
  FPU real, que o projeto não tem para perfil M (mesma exceção que B15.2/B15.3 documentaram). Se a
  sessão de execução decidir que `NSACR` como armazenamento puro (mesmo padrão de `CPACR`, B15.2
  Armadilha 4) vale a pena aqui, documentar a decisão — não é obrigatório.
- **Interrupções que trocam de estado de segurança** (`AIRCR.BFHFNMINS`, NMI/HardFault com alvo de
  segurança configurável) — fora de escopo, seria extensão do `MProfileExceptionModel` inteiro.
- **`VLLDM_VLSTM`/`VSCCLRM`** — B15.5, que DEPENDE desta task (o banking de segurança que B15.4
  cria é pré-requisito de como esses dois decidem o que preservar).
- **Emissão nativa/Truffle** — decode + interpretado apenas, mesmo padrão do resto da trilha B.

## Armadilhas

1. **`SG` vive num espaço que colide com `LDRD_ri_t32`** (`Rn=Rt=Rt2=1111,w=1,p=1`) — igual à
   disciplina de exclusão que `Thumb2NocpDecoder` (B15.2) usa para `VLLDM_VLSTM`/`VSCCLRM`: o decoder
   de `SG` tem que ser checado ANTES de `LDRD_ri_t32` capturar o mesmo padrão por engano (G8).
2. **`TT` vive num espaço que colide com `STREX`** (`Rd`/`A`/`T` no lugar de campos de `STREX`) —
   mesma disciplina, checar `TT` antes.
3. **Sem SAU real, `SG` executada fora de uma região NSC verdadeira ainda "funciona"** nesta task
   (troca para Secure sem checagem) — isso é uma SIMPLIFICAÇÃO CONSCIENTE (ver "Não inclui"), não um
   bug, mas TEM que ser documentada com destaque no `## Resultado` para não ser confundida com
   segurança real — este emulador não pode ser usado como sandbox de segurança até a SAU existir.
4. **`BLXNS` sem FPU real neste projeto**: a assinatura de integridade varia conforme há FPU ativa
   (`0xFEFA125A` sem, `0xFEFA125B` com) — como perfil M não tem FPU real aqui (ver B15.2/B15.3),
   usar sempre a assinatura "sem FPU" é a escolha honesta (documentar).
5. **Banking de SP por segurança tem que ser ORTOGONAL ao banking por `SPSEL`** — são duas dimensões
   independentes (4 combinações: `MSP_S`, `PSP_S`, `MSP_NS`, `PSP_NS`), não um enum plano de "modo".
   Confundir as duas produz o SP errado silenciosamente (G8 aplicado a estado, não a decode).
6. **G3**: `ARMV6M`/`ARMV7M`/`ARMV7M_PURE`/`ARMV7EM` (sem `M_PROFILE_SECURITY`) não podem regredir.
   Rodar a suíte completa antes de commitar.
7. **Estado novo em `ArmCore`/`MProfileExceptionModel` que entra em save state**: seguir o cuidado já
   registrado pela spec da B21.1 sobre nunca inserir campo no MEIO de um formato serializado — sempre
   ao final, com uma versão de formato se necessário (mesmo padrão que `ArmCore.loadState` já usa
   para tolerar save states antigos sem banco VFP, ver B3.3).

- O valor exato dos 2 possíveis "integrity signature" (`0xFEFA125A`/`0xFEFA125B`) foi obtido de uma

  simples) ou se há uma leitura mais correta mesmo sem SAU — decidir na execução com evidência.
