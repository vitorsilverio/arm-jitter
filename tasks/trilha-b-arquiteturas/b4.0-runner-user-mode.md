# B4.0 — Runner Linux user-mode (estilo qemu-user)

**Trilha:** B · **Depende de:** — (funciona JÁ com ARMv5TE; cresce com B1–B3)
**Repo:** NOVO projeto irmão (sugestão: `armbox`), consumidor do arm-jitter como
gbaemu/ndsemu. Nada desta task entra no arm-jitter, exceto bugs que ela revelar.

## Contexto

Antes de emular um sistema inteiro (MMU, devices), dá para rodar **binários Linux
user-mode** traduzindo syscalls — como o qemu-user faz. Isso valida o CPU core com
código real de compilador moderno e é útil por si só. Ponto-chave: um hello-world
estático compilado com `-march=armv5te` roda com o que o arm-jitter JÁ tem hoje —
esta task pode começar imediatamente e vira o veículo de validação de B1/B2/B3.

## Objetivo

CLI `armbox <elf> [args...]` que executa um ELF ARM 32-bit estático, little-endian,
EABI, traduzindo syscalls para o host, com o JIT (`JitRuntimeFactory.armThumb`) ativo.

## Especificação

### Fase 1 — hello world estático (aceite mínimo)

1. **Loader ELF32:** parse dos program headers `PT_LOAD`, mapeando segmentos num
   `AddressSpace` flat paginado (array de páginas; endereço de 32 bits do guest).
   Entry point do ELF → PC inicial; CPSR modo USER... na prática SYSTEM (o runner não
   usa privilégio; documentar).
2. **Pilha inicial ABI Linux ARM:** montar no topo da memória: argc, argv[], envp[],
   **auxv** (AT_PAGESZ=4096, AT_NULL no mínimo; AT_HWCAP conforme features), strings.
   Referência: qualquer doc de "Linux process initial stack layout".
3. **Syscalls:** ARM EABI = `SVC #0` com número em **r7**, args em r0–r5, retorno em
   r0 (negativo = -errno). Interceptar com `SwiDispatcher` do arm-jitter (ver
   `fallbackWithNumber` no README). Implementar primeiro:
   `exit/exit_group, write, read, brk, mmap2 (anônimo), munmap, fstat (stub mínimo
   para isatty), openat/close/lseek (arquivos read-only), clock_gettime, gettimeofday,
   set_tls (ARM_NR_set_tls 0xF0005) + leitura de TLS (ARM_NR_TLS via kuser helper —
   ver armadilhas)`.
   Syscall desconhecida: log claro com número/nome e retorno `-ENOSYS`.
4. **kuser helpers:** binários ARM Linux antigos/estáticos chamam a página mágica
   `0xFFFF0F60..0xFFFF0FFF` (cmpxchg, memory barrier, get_tls). Mapear essa página com
   implementações em código ARM trivial OU interceptar os endereços. Sem isso, glibc
   estática trava — é a armadilha nº 1 do user-mode ARM.

### Fase 2 — busybox

- `mmap` de arquivo, `ioctl(TCGETS)` stub, `getpid/getuid...` stubs, `uname` (reportar
  `armv5tejl`/`armv7l` conforme features), `writev`, `readlinkat`, `execve` (recusar
  educadamente), sinais como stubs (`rt_sigaction` grava e ignora).
- Aceite: `busybox echo hello` e `busybox sh -c 'echo a; echo b'`.

## Aceite (fase 1)

1. `armbox hello` (compilado `arm-none-linux-gnueabi-gcc -static -march=armv5te`)
   imprime e sai com o código correto.
2. Mesmo binário roda com runtime interpretado E com JIT ASM, mesma saída (usar também
   `divergenceCheckingArmThumb` num run).
3. README do projeto com instruções de build da toolchain/binários de teste.

## Armadilhas

- **Sem kuser helpers, nada com glibc funciona.** Implementar cedo.
- `brk`/`mmap2` precisam de um mapa de regiões consistente — mantenha um alocador
  simples de regiões livres; `mmap2` usa offset em PÁGINAS (não bytes).
- Endereços do guest são unsigned de 32 bits num `int` Java — comparar com
  `Integer.compareUnsigned`, nunca `<`/`>`.
- Thumb: binários v5 podem ter código Thumb (interworking) — o runtime `armThumb` já
  cobre; não force ARM-only.
