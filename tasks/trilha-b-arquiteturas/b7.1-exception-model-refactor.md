# B7.1 — Extrair `ExceptionModel` do `ArmCore` (refactor zero-diff)

**Trilha:** B (épico B7) · **Depende de:** B2.6 · **Repo:** arm-jitter

## Contexto

Preparação mecânica para o perfil M (RFC-M-PROFILE, decisão fechada): isolar a
lógica de exceção do perfil A atrás de uma interface, SEM nenhuma mudança de
comportamento observável. Esta task NÃO implementa nada de Cortex-M.

## Inclui

### 1. Interface `core/ExceptionModel.java`

```java
public interface ExceptionModel {
    /// Entrada síncrona/assíncrona de exceção (corpo atual de ArmCore#handleException).
    void enterException(ArmCore core, ArmException exception);
    /// Um branch/load-para-PC com este alvo é interceptado pelo modelo?
    /// (Perfil A: sempre false. Perfil M em B7.2: true para EXC_RETURN 0xFFFFFFF0+.)
    default boolean interceptsBranch(int target) { return false; }
    /// Executa a interceptação (perfil A: nunca chamado — lançar IllegalStateException).
    default void branchIntercepted(ArmCore core, int target) { throw new IllegalStateException(); }
}
```

(Assinaturas finais podem ganhar parâmetros que o corpo atual exigir — decida
olhando `ArmCore#handleException` (`ArmCore.java:467`); o critério é NÃO duplicar
estado: o modelo recebe o core, não guarda cópia de registradores.)

### 2. `core/AProfileExceptionModel.java`

Mover PARA CÁ, sem editar lógica: o corpo de `handleException` e qualquer helper
privado usado só por ele (troca de modo, banco SPSR, vetor 0x00000000/0xFFFF0000
via `highVectors()`, limpeza de ITSTATE de B2.4). `ArmCore#handleException` vira
delegação de uma linha. `switchMode`/`bankedRegister`/`spsr` PERMANECEM no
`ArmCore` (são API pública usada por MSR/CPS/SRS — G3), apenas a orquestração de
ENTRADA de exceção migra.

### 3. Pontos de intercept (preparação, sem efeito)

Nos 3 caminhos que escrevem PC vindo de dado — executor de `BranchExchange`,
`IrExecutionSupport#loadToPc`, e o caminho de `Pop`/`LoadMultiple` com PC (que já
passa por `loadToPc`) — inserir:

```java
if (core.exceptionModel().interceptsBranch(target)) {
    core.exceptionModel().branchIntercepted(core, target);
    return;
}
```

Com o modelo A isso é um branch nunca tomado sobre um método que devolve `false`
constante — custo ~zero; ainda assim, rodar o bench de sanidade (ver Validação).
**O backend ASM também**: localizar onde `AsmRuntimeHelpers`/emitters fazem
`loadToPc`/`branchExchange` e garantir que chamam o MESMO helper que agora contém o
intercept (se o ASM já delega para `IrExecutionSupport`, nada a fazer — confirmar
com teste de equivalência).

### 4. `ArmCore`

Campo `exceptionModel` com default `AProfileExceptionModel`, setter
`setExceptionModel` (chamável só antes de executar — documentar), getter usado
pelos executores.

## Não inclui

Qualquer comportamento M-profile (B7.2+), features novas, mudança em decoders.
