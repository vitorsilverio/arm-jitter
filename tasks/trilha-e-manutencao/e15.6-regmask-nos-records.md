# E15.6 — `regUse`/`regDef` nos records; `DeadCodeEliminationPass` sem `switch`

**Trilha:** E · **Repo:** arm-jitter (+ G5: gbaemu, ndsemu) · **Depende de:** E15.5 ✅ · decisão D2 do
[épico E15](e15-quebrar-arquivos-gigantes.md)
**Status:** ✅ 2026-10-02 (spec refinada e executada na mesma sessão) — ver **Resultado** no fim

## Contexto (medido em 2026-10-02, `70b049e`)

`ir/opt/DeadCodeEliminationPass.java` (288 linhas) é usada por todo backend nativo de 32 bits
(`StandardIrOptimizer.gba()` → `JitRuntimeFactory` ASM e `TruffleJitRuntimeFactory`). Tem três
`switch`:

- `regUse(IrOp)`: 41 casos por tipo + `default -> 0` (bitmask de GPR lidos);
- `regDef(IrOp)`: gate `condition() != AL -> 0` + 38 casos por tipo + `default -> 0`;
- `operandUse(IrOperand)`: `Register` (com guarda `valueOverride`), `ShiftedRegister`, `default -> 0`.

Os casos cobrem 44 dos 189 records. O conhecimento "quais GPR esta op lê/escreve" vive longe do
record, e um record novo que toca GPR cai em silêncio no `default -> 0` — **achado desta rodada de
spec: ~39 records já caem nele lendo GPR** (`MoveTop`, `Crc32`, `NeonMoveOp.LoadStore*`,
`VfpOp.LoadHalf`/`StoreHalf`, `LoopStart`, `MrsBank`/`MsrBank`, `ReturnFromException`, ~20 MVE…).
Uso não declarado deixa a DCE apagar a escrita anterior do registrador — corrupção só no JIT. Por
decisão do usuário (2026-10-02) isso é a task irmã [E15.6b](e15.6b-dce-gpr-nao-declarados.md); esta
task é refactor puro.

## Objetivo

Cada record declara os GPR que lê e escreve; a DCE vira só o laço de vivência. Nenhuma mudança de
comportamento: para toda op, `op.regUse()` = `regUse(op)` antigo e
`op.condition() == AL ? op.regDef() : 0` = `regDef(op)` antigo.

## Inclui

1. `IrOp`: `default int regUse() { return 0; }` e `default int regDef() { return 0; }`, Javadoc
   dizendo o contrato (bitmask `r0..r15`; `regDef` = o que a op escreve **quando executa** — a
   predicação é tratada pela DCE, não pelo record; o default `0` só é correto para op que não toca
   GPR, ver E15.6b).
2. `IrOperand`: `int regUse()` abstrato, implementado nos 3 records (`Immediate` = `0`).
3. Classe package-private `ir/GprMask` com as máscaras nomeadas (G6): bits de `SP`/`LR`/`PC`, índice
   do `PC`, `ALL` (`0xFFFF`), `BANKED_R8_R14` (`0x7F00`), `UNBANKED_R0_R7` (`0xFF`).
4. Override nos 44 records, logo depois do `execute`, com o corpo e os comentários que hoje estão no
   `case` correspondente (só renomeando o padrão para o próprio componente).
5. `DeadCodeEliminationPass`: `live[i] = op.regUse() | (live[i+1] & ~mustDef(op))` com
   `mustDef = condition() == AL ? regDef() : 0`; `isDead` fica (é política da passagem, não da op);
   os três `switch` saem; constantes nomeadas para `0xFFFF`/`15`.
6. `IrOpRegisterMaskTest` (pacote `ir`): um caso por branch dos corpos movidos, com a máscara
   esperada escrita à mão (é o "teste por record" que a E15.1 deixou para cá). Meta: 0 linha e 0
   branch `MISSED` em `regUse`/`regDef` de todo record e de `IrOperand`.
7. `CHANGELOG.md` (`[Não lançado]`): `IrOp#regUse`/`regDef`, `IrOperand#regUse`.

## Não inclui

- Os ~39 records sem declaração (E15.6b) — inclusive não "aproveitar" para declarar nenhum.
- Mudar a política (`isDead`, saída do bloco toda viva, gate de predicação).
- `FlagMergePass`/`ConstantFoldPass` (não têm `switch` por tipo de op).
- A64 (não tem DCE).

## Armadilhas

- `regDef` do record **não** olha a condição; quem olha é a DCE. Pôr o gate no record mudaria o
  significado do método para "must-def" e duplicaria o `if` em 38 lugares.
- `1 << -1` = bit 31 (Java mascara o shift): o oráculo compara bit a bit, então o comportamento com
  `-1` sem guarda fica idêntico, não "corrigido".
- `GprMask` package-private: a DCE (`ir.opt`) usa constantes próprias.
- `ParallelAluOp`/`IrOpCode` não são records de `IrOp`; `IrOp.Cycle`/`Fetch` ficam no default.
