ARM JIT · Java · GBA / NDS

Arquitetura do
ARM JIT Compiler

Design modular para emulação de ARM7TDMI/ARM9, com pipeline JIT em três camadas — Fetch → IR → Codegen —, memória por interface por dispositivo e SWI resolvida via callbacks sem emular BIOS.

01 · Pipeline JIT
STAGE 1
Fetch
Lê ARM / THUMB da memória. Detecta modo pelo bit T do CPSR.
STAGE 2
Decode
ArmDecoder / ThumbDecoder. Extrai opcode, registradores, imediato, condição.
STAGE 3
IR Lift
Converte para IROp[] em IrBlock. Separa load/store, ALU, branch, coprocessor.
STAGE 4
Optimize
IrOptimizer: constant fold, dead code, merge flags.
STAGE 5
Codegen
CodeEmitter → bytecode JVM via ASM. Hospeda em CompiledBlock.
STAGE 6
BlockCache
Armazena por PC. Invalida quando a memória é escrita (SMC).

06 · Estratégias de Execução
1
Interpretador (cold)
Executa ARM/THUMB diretamente via switch em ArmInterpreter. Usado nas primeiras N execuções de cada PC. Simples de manter; base para testes de corretude. Cada instrução consome ~20 ns de overhead no host.
2
JIT por Bloco (hot)
Quando hitCounter[pc] ≥ threshold, o JitRuntime compila o bloco até o próximo branch. CompiledBlock é um Runnable gerado via ASM lib. Execução host-native dentro da JVM — elimina overhead de dispatch por instrução.
3
Invalidação SMC
Todo write* em qualquer AddressSpace chama JitRuntime.invalidate(addr). O cache descarta blocos cujo range de PC inclui o endereço escrito. Necessário para jogos que geram código em IWRAM/EWRAM em runtime.
4
SWI via Callback
SwiOp no IR emite chamada ao SwiDispatcher.dispatch(imm, state). O handler Java recebe e devolve CpuState — sem entrar na ROM de BIOS. BiosFallbackHandler cobre SWIs sem handler registrado.
